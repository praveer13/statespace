### How a check becomes enforced

W1 builds the shell, the bus, the loader, Boot and the importer in parallel, and this gate lands first. Each check names the features it needs, and a feature counts as delivered when its owner's deliverable is in the tree (`lib/applicability.ts`: a source directory holding a file). Delivered means enforced: if the feature is there and the check cannot find what the documents say it should, it fails; it never reads "not found" as "pending". A check whose feature is missing is **pending** and names the task; it is reported, counted in the last line, and is not a pass. `--strict` fails on pending and on skipped. A build without `COURSE_DOMAIN` embeds no frame: once the features are delivered, `build.domain` fails and the checks it blocks stay skipped.

### What the browser checks read on a page

Each is written from the documents, so a failure names the sentence the page did not follow. A task whose page departs from one changes the page or the document, not the gate without a logged reason.

## 4. Decisions made here [D]

Each is a course parameter, not a tool fact, and `lib/budgets.ts`, `lib/boot-budget.ts` and `e2e/boot-timing.spec.ts` are the places to change one.

- **What a budget counts.** Bytes on the wire as a Pages-like host sends them: gzip level 5 for text-like files, the file itself for fonts and images; KB is 1000 bytes. Each row of ARCHITECTURE.md section 14 is held to what its label names: the entry chunk and the Boot, Today and lesson routes are JavaScript (the CSS and the fonts beside them are reported and not counted), and the instrument host page is a page, so its HTML, script and CSS count. "Entry" is the static closure of `index.html`; a route's cost is all the JavaScript a visit to it can load beyond the entry, the code it loads lazily included, on render or later and at any depth (section 3 says how its chunks are found). This is how kernelspace's rule reads (main chunk at most 250 KB; each lazy route at most 200 KB), and the section does not say; the lesson row's exclusion of instrument engines is the one exception it names, and engines are the instrument origin's files, never the site's. Two readings err only towards counting more: a dynamic import whose target is a template counts every module it can load, which overstates a route that loads one of them (course content arrives as fetched JSON, ARCHITECTURE.md section 3.3, not as such imports); and a module loaded lazily whose chunk Rollup wrote without a facade is matched by name, so when two such chunks share the name and neither names another screen's chunk, both are counted. Where the gate cannot tell what a route loads, it fails the route as unmeasurable rather than pass it. One form is not counted: an import with a query (`?worker`, `?url`, `?raw`) brings in a worker bundle, a URL or a string rather than the module's code in a chunk, and the graph does not follow it; the course's workers run on the instrument origin (ARCHITECTURE.md section 6, "Workers on the instrument origin"), not in the site's routes, and an `import()` Vite cannot analyse (neither a literal nor a `./` template) bundles nothing to count. Section 14 also says fonts are "counted in the route budgets" and gives no figure for them; a stylesheet declares every subset of a face and a page fetches only the subsets its text needs, so counting declared fonts would charge a route for files it never loads (the 12 subsets that W1-T01 ships are 283 KB in all, and a page fetches only the ones its text needs). The route checks therefore report what each route's first visit puts on the wire, fonts included, and `COUNTED` in `lib/budgets.ts` is the one switch that makes CSS and declared fonts count. W6-T02 replaces the figures with logged measurements.
- **The Boot gate.** The budget is `runs/RUN-phone-pyodide/budget.json`, which `scripts/spikes/W0-S02/derive-budget.mjs` writes: it is provisional while its reference is the emulated 0.25-CPU tier, and a merged device report regenerates it, so the gate follows without an edit. The yardstick of W0-S02 (the same 100-million-step loop) runs on the runner in a worker. The thresholds measured unthrottled (handshake, cold, warm) are the table's times Y over the recording machine's yardstick. The page's main thread is throttled with DevTools (Chromium only) to the rate that makes this runner as slow as the reference device, `round(530 / Y)`, which is the 4x of section 5.3 on the recording machine; Firefox and WebKit run unthrottled. The engine downloads over a link shaped to 20 Mbit/s, which only has to keep it in flight. A run that misses its threshold is measured twice more and the median taken; the lag check fails when two runs in a row break the budget. The handshake is W0-S02's "frame created, host page and manifest loaded, `ready` with caps", which OD-6's addendum calls "loader ready": the loader cannot state the size before the tap, so it is timed from the later of the tap and the frame's insertion to the first moment the text at the loader's bar states a size (a page that makes the frame on the tap starts both at once; one that loads more code first is timed from the frame, as W0-S02 timed it, and the route budgets hold that code), on the page's own clock through a MutationObserver. A restart after a watchdog stop is not measured, because Boot's cell has no query that outruns its budget.
- **The topology.** Three loopback ports (site, instruments, a foreign site) are the same-site, cross-origin layout W0-S02 measured on. A build made for `COURSE_DOMAIN=D` embeds `https://instruments.D` and lists `https://D` as the instruments' parent; the gate's hosts rewrite those two strings in text responses to the local origins, as a hosts file and a certificate would. The gate's own placeholder, `statespace-gate.test`, is a reserved name and never a real domain (OD-5).
- **The static host** is not `vite preview`: it answers a miss with 404, redirects a directory without its slash, serves `/x` from `x.html`, gzips at level 5, and sends no COOP, COEP or CSP header, as GitHub Pages does.

## 5. The learner-state fixture

`tests/fixtures/learner-state.json` is synthetic (a week of Project 00 for a learner who does not exist), in the shapes the architecture specifies: `events` are `event@1` records and `mirror` holds the lab-repo files that the read-only mirror shows (two statements, two receipts, the claims CL-1.1 and CL-1.2). No tool ran to make the receipts: their tool pins and verdict lines are copied from the schema fixture `schemas/fixtures/receipt/valid/z3-unsat-cross-checked.json`, and the builder puts in the stage, the date, the check, the claim template and each statement's path and hash. The verdict they carry is true of both statements by construction [D]: in `claims/guard.smt2` the guard `amount <= a` contradicts the violation `a - amount < 0`, and in `claims/conservation.smt2` the term `(a - amount) + (b + amount)` equals `a + b` for all integers, so neither statement has a model. Each mirror file is its path and its text, as the lab repo holds it (claims as `claims/*.yaml`). It is the one fixture behind the axe runs and the Playwright screenshots (DESIGN.md section 12), so that no two sheets can disagree. `fixtures/build-learner-state.mjs` writes the file, so change the builder and not the JSON; `--check` fails when the committed file is not what the builder writes. `learner-state.test.mjs` runs that check and keeps the file valid against the schemas, its IDs in the registry and its hashes the rules'; `seed-adapter.test.mjs` runs the seeding against W1-T03's real adapter in Chromium, Firefox and WebKit, which reads back all 24 events and 6 mirror files with no problem.

GATE-a11y fixes the clock to the fixture's instant for each context, loads the site, waits for the app to create its IndexedDB database `statespace` (ARCHITECTURE.md section 7.4), writes the fixture's records into the `events` and `mirror` stores that exist (it never creates a store or opens a version), and then opens each route, so screens draw from it as they would from a learner's events. Until W1-T03's storage exists the app has no database; the harness says "learner state: NOT applied" and checks the empty screens, and `--require-seed` turns that into a failure for the wave exit. `--self-check` proves the path end to end with a small app that is low in contrast only when the fixture is in its database and the clock stands at its instant.

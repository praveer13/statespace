## Negating English {minutes=13 kcs=KC-1.quantifier-negation,KC-1.only-if-direction}

A green test suite checks the inputs its author thought of. A solver can be asked about all of them, once you say what a bug is.

:::item role=prequestion family=GEN-negate-it template=t1 kcs=KC-1.violation-as-sat,KC-1.quantifier-negation mode=pick
@choice key=B
The property: every allowed transfer leaves the sender at zero or above. Which formula do you hand the solver to hunt for a bug?

- A. `allowed ∧ bal′ ≥ 0`
  - why: A model of this is a transfer that works, which says nothing about the others.
  - mis: dp:Z1
- B. `allowed ∧ bal′ < 0`
  - why: The negation of "for every allowed transfer, bal′ ≥ 0" is "some allowed transfer has bal′ < 0", and a model of it is a bug.
- C. `¬allowed ∧ bal′ < 0`
  - why: Negating the premise as well searches transfers the guard already rejects.
  - mis: dp:G3
- D. `allowed → bal′ < 0`
  - why: Any input that is not allowed satisfies an implication, so a model of it need not be a bug.
  - mis: dp:G4
:::

:::item role=prequestion family=GEN-negate-it template=t3 kcs=KC-1.only-if-direction
@choice key=A
"A transfer is allowed only if the balance covers the amount." Which formula is it?

- A. `allowed → covers`
  - why: "P only if Q" makes Q necessary for P.
- B. `covers → allowed`
  - why: This reverses the direction; covering is necessary, not sufficient.
  - mis: dp:G1
- C. `allowed ↔ covers`
  - why: This reads "only if" as "if and only if".
  - mis: dp:G3
:::

A worked example first. "Every allowed transfer leaves the sender non-negative" becomes a search for one allowed transfer that does not.[^1]

[^1]: Drawer D-03 holds the rules for negating a "for every" and a "for some".

:::instrument ins=INS-z3 cell=1 recorded=RUN-z3-demorgan
The unguarded transfer, with a negation that is slightly off.

```python
from z3 import *
a, b, amount = Ints('a b amount')
s = Solver()
s.add(a >= 0, b >= 0, amount > 0)
s.add(And(a - amount < 0, b + amount < 0))
print(s.check())
```

@direction
Query asserts: both balances end below zero at once. `sat` means such a transfer exists.

@tap
both balances stay at zero or above

@call key=B run=RUN-z3-demorgan surprise=yes
What will Z3 return for this query?

- A. `sat`
  - why: The recipient only gains, so both balances cannot go negative at once; the negation was wrong.
  - mis: dp:Z5
- B. `unsat`
  - why: No input satisfies it, yet the property is violated: the correct negation has an either-or in it.
- C. `unknown`
  - why: Three linear integer constraints are decided outright.
  - mis: dp:Z6

@after
That answer was not safety. It answered the wrong question.
:::

## One witness, one class {minutes=14 kcs=KC-1.witness-class}

:::instrument ins=INS-z3 cell=3 recorded=RUN-z3-optimize-min
Ask for the overdraft with the smallest amount.

@call key=A run=RUN-z3-optimize-min surprise=no
What amount comes back?

- A. `1`
  - why: The minimizer chooses every variable, so it sets the sender's balance to 0 and the amount to 1.
- B. `0`
  - why: The premise `amount > 0` excludes 0.
  - mis: dp:Z5
- C. One more than the sender's balance in the first witness.
  - why: This treats the first witness as the bug; it is one member of a class.
  - mis: dp:Z3
:::

"Minimal" means minimal for the objective you asked for, and nothing else.

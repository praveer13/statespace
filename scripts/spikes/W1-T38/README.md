# W1-T38: GATE-lessons

**Status:** built by W1-T38. **Date:** 2026-10-26 (machine clock). **Runs:** none. The gate is a lint over text, so it relies on no tool execution, and spine section 9.5 registers no run for this task.

GATE-lessons is the fast-lane gate over learner content, specified rule by rule in the spine (section 11.2, section 3.0, section 0 and section 12 item 48; invariants I1 and I5; V2-05 and V2-18). It reads lessons, drawers, stage and lab records, the placement walk, `labs/README.md` (and, as warnings, `labs/TOOLS.md` and `labs/AGENTS.md`) and the lessons the content build writes, and it fails on lesson anatomy that a tier does not meet, a graded item that names no family and template, an answer or a verdict in the rail, a seventh block type, lock copy, an internal name, and a glossary term used before its lesson. `content/glossary.yaml` is its vocabulary.

## 2. Running it

```
node scripts/verify-lessons.mjs                 the fast lane
node scripts/verify-lessons.mjs --strict        warnings fail too, and so does a generator family that is not built yet
node scripts/verify-lessons.mjs --json          print the report as JSON
node scripts/verify-lessons.mjs --root DIR      check the tree under DIR; --root may repeat, and then each tree is checked on its own
node scripts/verify-lessons.mjs --self-check    plant one fault at a time in a scratch copy of the fixture tree; the gate must fail on each
                                                with every rule the plant names; then the copy corpora and the vocabulary matrix
node --test scripts/spikes/W1-T38/*.test.mjs    the tests (about 15 seconds in all on the shared build machine)
node scripts/spikes/W1-T38/calibrate.mjs        the documents' quoted copy, read through the copy rules
```

It exits 0 when green, 1 on a finding and 2 when it could not run, a `--root` that is not a directory included, and it exits only once everything it printed is written: a pipe can take a write late, and on a busy machine an exit that did not wait cut the self-check's list short and could leave a `--json` report that does not parse (decision 31). A finding reads `fail <check> <file>:<line>: <what to change>`; a warning reads `warn` and passes unless `--strict`. In `--json`, each finding also names the rule that raised it (`rule`, section 8), and a lock finding every lock phrase that matched its sentence (`rules`). With several `--root` trees, each is checked on its own, `--json` prints `{strict, reports}` with one `{root, status, summary, findings, notes}` for each tree, and the run exits with the worst status; the self-check uses this to check a batch of planted copies through one command line. With `--root DIR` the glossary, the ID registry, the spine and the generators fall back to this repository's when DIR has none, so a test tree carries content only. A page that the build cannot read (`node scripts/build-content.mjs --check` says why) is reported as `read`, because the gate cannot vouch for a page it did not read.

### 3.3 Copy

Every rule below reads sentences of the masked copy: code, fenced blocks, comments, URLs, link targets, `{{run:}}` and `{{fact:}}` references, `[X ...]`, `[V]`, `[D]`, `[U]` and `[KS]` tags, footnote labels and emphasis marks are blanked, every offset kept, so a finding carries a line. A link's text is copy: `[D-03](/drawers/D-03)` is a link to a drawer, not a `[D]` tag, so `You can't open [D-03](/drawers/D-03) yet` reads "You can't open D-03 yet", and the link's target is never a word of the copy (Boot may link D-01). Emphasis is not a word: a run of `*` that touches a word and a run of `_` at the edge of one are blanked, so `**S1.L3** opens tomorrow`, `*you can't*` and `_core lesson_` read as their words; a list item's `* ` and an underscore inside a word (`snake_case`) are left alone. Each pattern reads a space as a run of white space and lets white space stand before a comma (`spaced` in `lib/copy.mjs`), because a blanked mark leaves spaces ("After *S1.L2*, S1.L3 opens" reads "After  S1.L2 , S1.L3 opens") and a sentence may wrap at any space. A finding reports the original's words, the emphasis marks around them included. A registered ID is not a word: `SEAM-1` is not a use of seam and `RUN-z3-starter` is not a use of run.

### 3.4 The lock rule in detail (I5)

`LOCK_PHRASES` in `lib/copy.mjs` holds the rule: one vocabulary and a set of frames. Each frame is one way English makes access to course content wait, and it reads any word of the vocabulary in each of its slots. Three verification rounds each found sentences of the same classes that a phrase list missed, because a list grows by pairs and a learner can say each pair many ways; the frames cover the combinations. The first phrase that matches gives the finding its rule (`lock/<phrase>`) and its words, the sentence's own; the finding also names every phrase that matched (`rules`), so a plant can pin any of them (section 8).

**When a sentence is read.** A sentence is read when it names something a learner can open, or answers, in the same paragraph, a question that does ("Want the next lesson? Finish this one first."). A padlock (🔒, 🔐), a lock label ("Locked", "Unlocked!", "Not started · Locked") and two phrases that are a lock whatever they name ("complete to unlock.", "locked lessons", "locked content") are read in any sentence. A sentence that names nothing else but says "the next one" is read by the frames alone, which need it beside an access, an opening or a refusal: "Unlock the next one", "The next one opens tomorrow" and "You can't open the next one yet" are flagged, "Pick the next one in the list" and "The first lock is held, and the next one opens after a timeout" are not. A sentence that says the policy in the negative is not read: "it unlocks nothing", "nothing is locked", "but you don't have to", "in any order", "it stays open either way".

**The vocabulary.** Each list below is a list of `VOCABULARY` in `lib/corpus.mjs`, word for word, under the name in brackets; `readme.test.mjs` holds the README's lists and the module's to each other. The vocabulary matrix (`matrixSentences`) puts S1.L3 in each kind of frame with every word of each of its slots: a purpose clause, the access last and first (the progress and the access); a consequence (the progress and an opening); the condition first (the progress, then an opening or the access); the thing opening after the condition (an opening or the access, then the progress); a refusal, then *yet* or *until* (a refusal and the access); a closure, then *until* or *for now*; access denied, then *yet* or *until*; and a schedule (an opening and a time). `frameSentences` puts each thing in one sentence of each of those kinds of frame, with *finish S1.L2*, *open*, *opens*, *can't*, *stays closed*, *no access to* and *tomorrow*, and a refusal or access denied with a definite thing only. That is 5,247 sentences, and `copy.test.mjs` and `--self-check` require each to be flagged, but for the 90 that say the policy (what is open, available or ready "daily" or "every day" is open always). A word taken out of a list the patterns are built from leaves a sentence of the matrix, a row of the corpora or a plant unflagged, so the self-check fails on it (`words.mjs` takes out each word of each list in turn, "The corpora" below; the determiners before a thing are the exception, section 6).

- *The thing* (`things`): the next lesson, the next stage, the next lab, this drawer, the next audit case, the Defence, S2, S1.L3, LAB-2, LAB-1.3, D-03, AUD-1.2, the course, more content, the next module, this unit, every segment, level 2, the next chapter, the next section, the next exercise, the next part, the next one, the rest of the course and the lab's next stage. They stand for a lesson, stage, lab, drawer, audit case or the Defence, whatever stands before it; an ID of one (a stage, a lesson, a lab, a lab's stage, a drawer, an audit case), a stage or lesson ID in exact case only, because `s1` is a session; a course, content, module, unit, segment, level, chapter, section, exercise or part only after a word that points at a piece of the course ("the next module", "this unit", "more content", "every segment", "level 2", "the course"), so "the parser module", "unit tests" and "the isolation level" are not things; "the next one", beside a frame (above); "the rest of the course". A possessive counts only when what it owns is a thing too ("the lab's next stage"), and a noun after it makes it a modifier: "the lab folder", "the lab page", "the lab's verdict lines" and "the Defence retake" are not the lab or the Defence.
- *The access* (`access`): open, see, read, view, unlock, reveal, start, begin, access, reach, enter, take, try, attempt, get to, go to, get into, move on to, move to, go on to, continue to, proceed to, progress to, advance to, skip to, jump to, jump ahead to, skip ahead to, qualify for, be eligible for, become eligible for, get through to, have access to, gain access to and get access to.
- *The progress* (`progress`): complete, finish, pass, clear, solve, earn, master, score, submit, answer, sign off, ace, get through and get … right. Each is read in any form, and so are "you're done"; "your query passes" or "returns unsat"; passing or finishing; the Defence; "S1 is signed off", "LAB-1.2 passes", "all exit items are answered"; "this check"; "completion of S1". "If you finish early" is an aside. A purpose clause also takes a lab's tasks (mount, fix, find, write, prove, build, reach, meet, mint) and a receipt's import ("Import your receipt to open LAB-1.3"), and moving on with no object takes the progress verbs alone, so "fix the encoding in LAB-1.3 to proceed" is a step of the lab.
- *Opening* (`opening`): opens, opens up, unlocks, appears, shows up and goes live. A state is an opening too, after a state verb (`stateVerbs`): is, becomes and will be. The states (`states`): open, opened, available, visible, accessible, yours, unlocked, released, ready and waiting for you. How a page opens is not whether it opens: "opens on its summary", "opens inline", "opens with Part A", "opens at its trigger" and "opens in a new tab" are left alone (curriculum/D-drawers.md sections 1.2 and 6.7), while "opens to you" is access.
- *A time* (`time`): tomorrow, tonight, in 24 hours, in two days, a day later, the next day, next week, Friday, on Monday, this Friday, from tomorrow, starting Monday, on 2026-11-03, on November 3, 3 November, at midnight, every Monday, every day, each day, every other day, every 24 hours, twice a week, daily, weekly, one a day and one at a time. The last ten are a cadence. A release verb takes any of them ("A new lesson opens every day"); a state ("is open", "is available", "is ready") takes a time still to come or a cadence that keeps it to some days ("is available every Monday", "weekly", "one a day"), because what is open every day or daily is open always, which is the policy ("This lesson is open every day of the week").
- *A refusal* (`refusal`): can't, cannot, won't, won't be able to, may not, aren't allowed to and don't get to. Each is read with the access ("you can't open S1.L3").
- *A closure* (`closed`): won't open, doesn't open, can't be opened, isn't open, hasn't opened, stays closed, stays hidden, stays greyed out, stays off-limits, stays out of reach, stays shut and stays locked.
- *Access denied* (`denied`): no access to, you're not ready for and you're not eligible for.

**Tokens.** Before the frames run, each thing in the sentence becomes one token, which says whether it is the Defence (an event as well as a thing) and whether it is definite ("the next lesson", "S1.L3", "your lab") or not ("a new lesson", "every drawer", "more content"). A frame names the thing once, and the finding is mapped back to the sentence's words. A refusal needs a definite thing, so "you can't open a drawer that doesn't exist yet" refuses nothing. The phrases kept from the earlier rounds whose tests hold narrow readings read the sentence itself: the bare words, "locked until" (so "the sender account is locked until the audit case ends" stays clean), "reward for", the countdown and the ordinary phrases other than "you cannot continue until". A padlock and a lock label are checked before the phrases (`lock/padlock`, `lock/label`). The tokens also keep the patterns small: written out, the frames came to 741,451 characters of pattern, and a self-check that started the gate once per plant took about 36 seconds on the build machine; with tokens they come to about 100,000 characters (a test holds them under 150,000). The self-check checks a batch of planted copies through each command line (section 8) and takes about 8 seconds for its 300 plants, the corpora and the matrix.

**What the frames cost.** A lock of another kind that a lesson, stage, lab, drawer or the Defence stands right before is flagged when what holds it is not one that `HELD_IN` lists: "The transfer in this lab is locked until the hold settles" reads as "this lab is locked". A holder that `HELD_IN` lists (a lock, a vault, a door, a gate, a safe, a row, a table, an account, a transaction, a mutex, a thread, a record, a file, a session, a connection, a port, a valve, a phone, a device, a key, a wallet, a server, a worker, a job or a queue) before "in this lab" is where the lock sits, so "The account in this lab is locked until the audit case ends" is not flagged; "The account in this lab is locked until you pass" is, because it waits on the learner. Reword the flagged kind ("In this lab, the transfer is locked until the hold settles" and "The transfer stays locked until the hold settles, in this lab" are not flagged). A lock of another kind rarely needs to name the lab. The same holds for the order and purpose phrases: "Find the link in the rail to open D-03" is flagged ("find" is a task here), and "Open D-03 from the rail" says the same.

## 5. Decisions this task made

Each decides something the spine leaves open. The owner reviews them with the task.

1. **Scope.** The gate reads what the content pipeline reads (lessons, drawers, stage and lab records), the placement walk (`content/stages/S{n}/placement.yaml`, which the pipeline leaves to W1-T45 and W1-T45 accepts on "GATE-lessons on its copy"; decision 16) and `labs/README.md`, which the spine names; it reads `labs/TOOLS.md` and `labs/AGENTS.md`, which are learner-facing lab documents too (`labs/README.md` sends learners to the first for the pins and the installs, and to the second, which every lab zip carries), as warnings, because they are not clean yet (section 7 has the five findings and what to do). It does not read the screens' own strings (`apps/site/src`), the other YAML and JSON under `content/` (the KC graph, claims, specimens, audit anchors, assurance, governance) or `labs/template/`. Reading all of `content/` would fail today on `content/kc/graph.yaml`, whose tool table says "Lane A", and would hold data to rules for copy. `DOCUMENTS` in `scripts/verify-lessons.mjs` is where a task adds a learner document that is clean; `WARN_DOCUMENTS` holds one that is not yet, and a document moves to `DOCUMENTS` once it is clean, or leaves `WARN_DOCUMENTS` if the owner rules it maintainer documentation. A record that joins the lesson@1 envelope is read already.
2. **Terms are matched as words, in every sense.** The spine and DESIGN.md say Boot leaves "the words Bench and run" to later, so "run the starter" in Boot is a finding as much as the label "run". "check" (term 7, "lab · check") is not matched, because "Check with Z3" is Boot's own button.
3. **Positions.** A lesson is at its ID; a stage page, a lab page and a drawer are at the end of their stage; a drawer is at the end of the first stage in the registry's "Used in"; a deferred drawer and a document have none. The builder's path (OD-3) reads S5 to S8 before S2 to S4; the gate holds the roadmap's order, and a term first introduced in S2 to S4 appearing in S5 to S8 is not checked.
4. **"Once" in the spine's labeled cross-reference** is read as one internal name per cross-reference sentence, repeats of it inside that sentence allowed. `labs/README.md` names lane in two such sentences (the Lane A and Lane B line, and the Bench's setup lanes line). Read as once per file, the second would be a finding and the line would change. An ID of the course's machinery is an internal name here too, so a cross-reference that cites three IDs, or a term and an ID, names more than one and is a finding.
5. **Counters, loss framing, deadlines and rewards** are in the same gate as lock copy because docs/EVIDENCE.md assigns rows 6, 7 and 17 to "GATE-lessons' copy lint" and W2-T16 accepts on "no overdue counts, no lock copy". "Correct!" and "Wrong!" stay with GATE-codes. Each class is read by what it does, not by DESIGN.md's example words alone: a count of days away, an overdue mark or count, a deadline on a day, loss by another name; points, a badge, a level, a ranking and praise for a click. A system's own deadline, expiry or window (a lease, a timer, a job, a protocol, a model) is not the learner's.
6. **Which ID kinds are internal.** Knowledge component (`kc`), gate, mechanic, generator, instrument, screen, task, owner decision, brief change and misconception key. A knowledge component's ID is machinery: curriculum/D-drawers.md section 1.6 says "learner copy never says KC", and DESIGN.md section 11.4 writes a competence statement as "You can now ‹KC in words› on unseen items". Wave and invariant are left out: W1, W2 and I1 name steps and invariants in the course's own examples (the double-spend model's R1, R2, W1, W2). An ID in a front matter field, a block attribute or a record field that holds IDs alone is data (decision 17).
7. **A hook cannot be told from a prequestion's scenario,** because the page format has no block for it and the lesson screen opens on the first prequestion (DESIGN.md, SCR-lesson). The gate checks that a core lesson opens with prose or a prequestion, and leaves the hook to the review checklist.
8. **A claim or specimen block may stand after a segment's graded item.** "Establishes" shows them after the exit items, so they draw nothing inside the segment.
9. **A page that does not read is a finding,** except for the two read errors the gate reports itself (an item with no family or template, and a block type outside the six), which it would otherwise report twice. Prose written as a block (`:::prose`) is of one of the six types, so the six-type rule says nothing of it, and the build's refusal is the finding (`read/page`).
10. **Severity.** Segment counts and lengths, the parts of a lesson, words and the rest are errors. Planned totals (40 to 60 and 15 to 25 minutes) and a second cell in a core segment are warnings, because "planned at" and "one instrument run" describe a plan; `--strict` fails on them.

12. **`meaning` in the glossary file is a gloss.** Term 15's is reworded, because GATE-codes reads everything under `content/` as learner copy and reserves a bare "correct" for stamps.
13. **A lock that names its content is lock copy whatever else the sentence is about.** The weak words (unlock, locked) step aside for a sentence about a lock of another kind, and S1's own nouns (a transfer, a balance, an account, a refund, a payment) are on that list, so "Fix the transfer to unlock LAB-1.3" first passed. 20. **The lock rule is frames over one vocabulary, and a thing is one token.** Spine I5 says what nothing may do (wait), not the words for it, and each of three verification rounds found sentences of the same classes that a list of phrases missed. A frame (section 3.4) is one relation (a purpose, a consequence, a condition first, a refusal, a schedule, a requirement, a means, a restriction, a wait) with a slot for each part of the vocabulary, and the vocabulary matrix (`lib/corpus.mjs`, which `copy.test.mjs` and `--self-check` read) holds each kind of frame to every word of the vocabulary's lists and to each kind of thing. The thing is replaced by a token before the frames run, which keeps each frame short and the patterns small enough to compile once per run of the gate. The cost is that a frame may flag a sentence that no phrase of the earlier rounds named; the run over every document (section 3.3) found none, and every look-alike that the held-out batches found is a must-not-flag row.
21. **What a learner can open, beyond the six nouns and the IDs.** A course, content, module, unit, segment, level, chapter, section, exercise or part is a thing only after a word that points at a piece of the course ("the next module", "more content", "level 2"), because each is also a word of the course's subject ("the parser module", "unit tests", "isolation level"). A padlock, a lock label ("Locked", "Unlocked!", a status segment "· Locked"), "complete to unlock." and "locked lessons" or "locked content" are lock copy whatever else the sentence names, and a sentence that answers a question about content in the same paragraph ("Want the next lesson? Finish this one first.") is read as naming it. A thing that stands where a lock of another kind sits is not what opens ("the lock in LAB-6 opens after the transaction commits").
22. **A condition is lock copy; a suggested order is not.** "Start S2 once S1 is signed off", "finish S1.L1 before starting S1.L2" and "S2 opens after the Defence" make the content wait on something. "Finish S1.L2 and move on to S1.L3", "Pass the Defence, then S2" and "Start LAB-1.2 after S1.L1" suggest an order and say nothing waits, and "come back tomorrow to continue with S1.L3" is a suggestion; none is flagged, and the review checklist reads them against I5 (section 6). The lock corpus keeps them as unjudged rows, so a later change that flags them is a decision and not an accident.
23. **"One tool per session" is read per segment.** Spine section 4.1 gives GATE-lessons the segment row, "12–15 min, ending in a graded interaction; one tool per session", and the gate cannot see a sitting, so it holds the row where it can: the cells of one segment run one instrument. Two cells of one instrument stay a warning about the one instrument run (section 3.1); an item checked offline, as S1.L5's witnesses are, is not a cell.

24. **Every rule has an ID, and every rule has a plant.** The self-check counted a plant as caught when any finding of its check appeared, so a rule could be deleted while another rule of the same check still caught its plant: the repair run's first verifiers deleted 31 rules, one at a time, and 14 of the 79 lock phrases, and the self-check stayed green. Each finding now names the rule that raised it (`<check>/<name>`, `lib/rules.mjs`), a lock finding every phrase that matched its sentence, and each plant names the rules it must raise; the self-check counts a plant as caught only when all of them fired. `rules.test.mjs` requires a plant for every rule and a rule for every plant, and deletes each lock, pressure and reward phrase in turn. Two rules no plant can reach (the pipeline's own lists of types, and a rule that throws) are held by tests instead, as `NOT_PLANTED` says. The cost is 300 plants, which the self-check checks in batches, several planted copies through each command line (`--root` repeats), in about 8 seconds with the corpora and the vocabulary matrix, which it holds the copy rules to as well.
25. **Markup is not a word.** Emphasis marks, and a link's brackets and target, are blanked before the rules read a sentence, and each pattern reads its spaces as runs of white space. The house style bolds and italicizes freely (curriculum/, docs/ and labs/ hold thousands of bold runs), and lock copy, a pressure phrase or an internal name in bold or italics is the same copy; a drawer's ID in brackets, `[D-03](/drawers/D-03)`, is a link and not a `[D]` tag.
26. **A lock of another kind in a lab is excused only while it waits on the system.** `HELD_IN` excuses "the lock in LAB-6 opens after the transaction commits", where the lab is where the lock sits. When the sentence makes it wait on the learner's progress or on the Defence ("the vault in this lab opens after you pass the Defence"), the lab waits on the learner, which I5 forbids, and the sentence is flagged.
27. **What is open daily is open always.** A release verb with any cadence is a schedule ("A new lesson opens every day"). A state with "every day" or "daily" says the policy ("This lesson is open every day of the week"), and a state with a cadence that keeps it to some days ("available every Monday", "open weekly", "one a day") is a schedule.
28. **The self-check holds what the tests and this README hold.** The repair run's second verifiers weakened rules part of the way: one end of a range, a limit loosened, a scope narrowed, a word taken out of a list, one alternative of a phrase taken out. Each passed the self-check, because each rule had a plant at one point of it and the corpora did not hold the tests' sentences or the README's examples. Now each end of each range of the anatomy and the rail has a plant one step past it, and so does each part of a rule's condition (the role, the variant, the scope of drawers); `rules.test.mjs` loosens each limit by one at either end, and takes each word out of the rail's lists, and requires a plant to be missed each time. The corpora hold every sentence of `copy.test.mjs`'s tables and every example that the pressure, reward and internal rows of section 3.3 and the table of frames and "Not lock copy" of section 3.4 give; each alternative of each phrase flags a row alone; each word of each list the patterns are built from is pinned by a row, a sentence of the matrix or a plant (`words.mjs`); each form of each internal name is pinned by a row of `fixtures/copy/internal.txt` (in the repair run's third round, which added that corpus, only "core lesson" of the tier names' forms had a plant); and `readme.test.mjs` holds this README's vocabulary lists, its examples and its numbers to the modules. The cost is more rows and plants, and a few seconds.
29. **Boot asks its call before the first run.** Spine section 3.1 says Boot asks one call before the first run, and curriculum/S01-counterexample.md says the call is "asked before any instruction, answered by the run". The gate reads the first cell of the page: it carries the `@call`, or a fixed question stands before it. A free run before the cell with the call, or a fixed question after a free run, lets the learner see a result first, and is a finding; a page with no cell asks its call as a fixed question.
30. **A Build this card names a lab stage the registry has.** The spine's card is "for the next lab stage", so `lab=` names a lab stage (`LAB-1.2`), and the gate checks it against the registry wherever the card stands: a lab (`LAB-1`), a lesson (`S1.L3`) or a stage that does not exist (`LAB-1.99`) is a finding. Which stage is the next one is the review's.
31. **The gate exits once its output is written.** Node takes a write to a pipe asynchronously, and `process.exit()` drops what is still queued: with six self-checks at once on the build machine, five printed their list cut short, mid-line, and a `--json` report cut short would not parse (the self-check reads one for each batch of planted copies, and would count the batch's plants missed). The gate and `words.mjs` now exit through `exitWhenWritten`, which waits for stdout and stderr to take everything; the same six self-checks, run twice, printed every line, and `gate.test.mjs` holds it with a reader that waits before it reads.
32. **A title is plain text, underscores included.** The pipeline's check of markup reads backticks, asterisks, brackets, braces, angle brackets, backslashes and bars, not underscores, so `What _it_ showed` passed as a title; emphasis in underscores is Markdown as much as emphasis in asterisks, so the gate reports it as markup (`rail/markup`, `rail/built-markup`). An underscore inside a word (`balance_after`) is not emphasis.

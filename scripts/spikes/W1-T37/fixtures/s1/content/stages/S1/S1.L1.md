## Negating English {minutes=14 kcs=KC-1.quantifier-negation,KC-1.only-if-direction}

:::instrument ins=INS-z3 cell=1 recorded=RUN-z3-demorgan
```python
from z3 import *

a, b, amount = Ints('a b amount')
a2, b2 = a - amount, b + amount     # the balances after the transfer, which has no guard
s = Solver()
s.add(a >= 0, b >= 0, amount > 0)
s.add(And(a2 < 0, b2 < 0))          # "both balances stay at zero or above", negated the wrong way
print(s.check())
```

@call key=B run=RUN-z3-demorgan surprise=yes
This query asks for both balances to end below zero on the unguarded transfer. What will Z3 return?

- A. `sat`
  - why: The transfer is unguarded, but this query asks for both balances to go negative at once, and the recipient only gains.
  - mis: dp:Z5
- B. `unsat`
  - why: No input satisfies it, so Z3 answers unsat, yet the property is violated: the correct negation is sat.
- C. `unknown`
  - why: Three linear integer constraints are decided outright.
  - mis: dp:Z6
:::

## One witness, one class {minutes=14 kcs=KC-1.witness-class}

:::instrument ins=INS-z3 cell=2 recorded=RUN-z3-optimize-min
```python
from z3 import *

a, b, amount = Ints('a b amount')
o = Optimize()
o.add(a >= 0, b >= 0, amount > 0)
o.add(a - amount < 0)               # the overdraft
o.minimize(amount)
print(o.check())
print(o.model())
```

@call key=A run=RUN-z3-optimize-min surprise=no
Z3 is asked for the overdraft with the smallest amount. What amount comes back?

- A. `1`
  - why: The minimizer chooses every variable, so it sets the sender's balance to 0 and the amount to 1.
- B. `0`
  - why: The premise amount > 0 excludes 0.
  - mis: dp:Z5
- C. one more than the sender's balance in the first witness
  - why: That treats the first witness's balance as fixed; it is one member of the class, not the bug.
  - mis: dp:Z3
:::

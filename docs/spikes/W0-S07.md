# W0-S07 · `vcgen` on a custom `Cmd`

**Status:** decision record, awaiting owner review (0.5 h). **Date:** 2026-10-24 (machine clock). **Run:** [X RUN-vcgen-cmd], recorded in `runs/RUN-vcgen-cmd.json` with raw outputs in `runs/RUN-vcgen-cmd/`. **Implements:** the S4.L9 production twin (spine §13, W0).

## Question

Does Lean's experimental `vcgen` work on a custom, Mini-Plinth-style command type, so that S4.L9's dated production twin (SP-4.7) can be shown on a command like the learner's own? What does it prove, what obligation does it leave, and how stable does the interface look?

The measured shallow probe, a `def transfer … requires … ensures` contract over Lean integers, is {{run:RUN-lean-vcgen}}, which W0-S11 re-records with its output. This spike does not re-run it.

## Method

1. A small Lake project, `scripts/spikes/W0-S07/lean/`, defines the command type in `W0S07/Cmd.lean`. It follows the S3 spec's Mini-Plinth v0 shape plus LAB-4's additions: typed parameters (accounts and integers kept apart), a guarded command `command C(params) requires g do st` whose false guard is the explicit error `guardFailed C`, and the statements `skip`, `move n from x to y` (debit, then credit reading the updated state, so a self-posting is a no-op), `set f(x) := e` on an integer scalar field, sequencing and `if`. It is a probe, not the course reference: balances are a function `Acct → Int` where the LAB-3 template keeps an association list, and `move` is the only resource operation.
2. The weakest precondition is defined from the big-step semantics `exec`, which is what the 4.35.0 docstring asks of an inductive command type [X RUN-vcgen-cmd]. The module gives two `Std.WP.WP` instances (statements and commands) over assertions `Env → State → Prop` with the exception postcondition `Err → Prop`, one `wp` equation per constructor derived from `exec`, and one `@[spec]` lemma per constructor. The guard and `if` each get two spec styles: the upstream IMP example's, an `if` inside the precondition (`tests/elab/vcgenImp.lean`, read at commit `eb6cafb` on 2026-10-24 [V]), and one written with the lattice connectives `⊓` and `⇨`.
3. Eight probe files exercise it. Each runs as `lake env lean <file>` after `lake build`, every step in its own `docker run --rm --memory=6g --network=none` container, one step at a time.
4. For stability, the same nine steps run on three toolchains: 4.35.0, the edition 1 pin (OD-12); 4.36.0-rc1, the next release candidate; and nightly-2026-10-24, the newest nightly on the recording date (4.37.0 development). Each probe's output is compared with the 4.35.0 output.
5. `node scripts/spikes/W0-S07/record.mjs` does all of this and writes the record. It needs Docker, the `ss-lean:4.35.0` image, curl and tar with zstd, and no npm packages.

## Results

### 1. `vcgen` works on the custom command type

On 4.35.0, given the two WP instances and the per-constructor specs, `vcgen` decomposes triples over Mini-Plinth-style command values, the exception postcondition for `guardFailed` included; all 27 steps across the three toolchains exited with their expected codes [X RUN-vcgen-cmd].

The glue is small. Counting comments and blank lines, the section that defines the weakest preconditions and the two WP instances takes 34 source lines, the per-constructor `wp` equations with their two helper lemmas 34, the registered specs 16 and the lattice-style guard and `if` specs 38, against 55 for the syntax and 44 for the semantics [X RUN-vcgen-cmd].

### 2. What it proves

| Probe | Triple | How it closes |
|---|---|---|
| P1 | the roadmap's Transfer, from `0 < amount ∧ NonNeg s` to `NonNeg s`, with rejection `guardFailed "Transfer"` | one condition (below), closed by `grind`; also by `vcgen [Transfer] with finish` once `NonNeg` is unfolded |
| P2 | under a false guard: rejection `guardFailed "Transfer"` and no committed state | `vcgen … with finish` |
| P3 | the sum of the `from` and `to` balances is kept and every other balance is unchanged, self-transfer included | `vcgen … with finish` |
| P4 | FeeTransfer (sequencing, `if`, an integer scalar) keeps `NonNeg` | two conditions, one per branch, closed by `grind` |
| P5 | each wrong triple of `Residual.lean` is false | witnesses: `balance(from) = 0, amount = 1` for the weakened guard; `x = y` for PayTwo |

Every theorem in `Proved.lean` depends on the axioms `[propext, Classical.choice, Quot.sound]` [X RUN-vcgen-cmd]. `NonNeg s` is "every account except `mint` is non-negative", the sign part of the S3 invariant.

The condition P1 leaves is the learner's obligation shape, `Inv(S) ∧ Guard(S) ⊢ Inv(S′)`, stated over the command type's own functions; the rejection branch closes inside `vcgen`, so only the commit branch is printed [X RUN-vcgen-cmd]:

```
a✝¹ : 0 < s✝¹.num "amount" ∧ NonNeg s✝
a✝ : holds (BExpr.ge (Expr.balance (AExpr.var "from")) (Expr.var "amount")) s✝¹ s✝
⊢ NonNeg
    (post s✝ (AExpr.eval s✝¹ (AExpr.var "from")) (AExpr.eval s✝¹ (AExpr.var "to"))
      (Expr.eval s✝¹ s✝ (Expr.var "amount")))
```

### 3. What it leaves

| Probe | Command | Obligation left, abridged | Verdict |
|---|---|---|---|
| R1 | guard weakened to `balance(from) >= 0`; postcondition `0 ≤ balance(from)` | `⊢ 0 ≤ (post s from to amount).bal from` under `0 < amount ∧ 0 ≤ balance(from)` | false at `balance(from) = 0, amount = 1` |
| R2 | the same command against `NonNeg` | `⊢ NonNeg (post s from to amount)` | false on the same witness |
| R3 | PayTwo: two debits behind two guards read in the pre-state | `⊢ NonNeg (post (post s x z n) y z m)` | false at `x = y` |

All three are printed as unsolved goals and refuted in Lean by P5 [X RUN-vcgen-cmd]. R1 verbatim:

```
a✝¹ : 0 < s✝¹.num "amount" ∧ 0 ≤ s✝.bal (s✝¹.acct "from")
a✝ : holds (BExpr.ge (Expr.balance (AExpr.var "from")) (Expr.lit 0)) s✝¹ s✝
⊢ 0 ≤
    (post s✝ (AExpr.eval s✝¹ (AExpr.var "from")) (AExpr.eval s✝¹ (AExpr.var "to"))
          (Expr.eval s✝¹ s✝ (Expr.var "amount"))).bal
      (s✝¹.acct "from")
```

R1 is the deep-embedded counterpart of the shallow probe's `⊢ 0 ≤ (a - amt, b + amt).fst` {{run:RUN-lean-vcgen}}: the same dropped `amt ≤ a`, stated over the command type's `post` instead of a Lean pair. R3 is the aliasing hazard the S3 spec records, which sequencing brings back: both guards pass in the pre-state and the second debit overdraws.

### 4. The spec style decides how far `vcgen` goes

- With the guard written as an `if` in the precondition, the upstream example's style, `vcgen` applies the spec but does not split the `if`: the condition still holds `wp` of the whole body, which for FeeTransfer is the entire sequence, `if` and `set` [X RUN-vcgen-cmd]. Unfolding the `wp` equations by hand then lets `grind` finish.
- With the guard and `if` written as `(holds g ⇨ wp b Q E) ⊓ (fails g ⇨ …)`, `vcgen` splits on the guard, lifts it into the context and continues into the body, leaving one pure condition per path [X RUN-vcgen-cmd]. Results 2 and 3 use this style.

### 6. Stability across the three toolchains

| Probe | 4.36.0-rc1 | nightly-2026-10-24 |
|---|---|---|
| `Proved`, `Residual`, `StyleIf`, `ContractOk`, `ContractFail` | output identical to 4.35.0 | output identical to 4.35.0 |
| `ContractThrows` | elaborates, with spec `… ⦃ fun x x_1 s => NonNeg s; fun e => e = Err.guardFailed "Transfer" ⦄`; on 4.35.0 the clause does not parse (`unexpected token '=>'`) | as on 4.36.0-rc1 |
| `ContractThrowsBare` | fails: the expected type of `.guardFailed` could not be determined, and `grind` fails, reporting that it cannot synthesize `EPostSlot (Err → Prop) ?m.32 Prop` | fails with the same two errors; this `grind` prints no diagnostics without `+verbose` |
| `Interface` | `WP`'s fields are renamed `trans` and `trans_monotone`, keeping `wpTrans` and `wp_trans_monotone` as aliases; its exception parameter `EPred` is renamed `EPosts`; the monotonicity predicate prints as `Monotone`, was `monotone`; `vcgen` and `@[spec]` are declared in `Std.WP.Tactic` instead of `Std.Tactic.Do.Syntax` | as on 4.36.0-rc1 |

All from [X RUN-vcgen-cmd]. Unchanged on all three toolchains: the docstring's sentence "`vcgen` is experimental and subject to change", the `experimental.vcgen` and `experimental.intrinsic` options (both default `false`), and the warning each feature reports while its option is off, "The `vcgen` tactic is an experimental drop-in replacement for `mvcgen` that will eventually replace it" and "The `ensures` clause is part of the experimental intrinsic verification syntax" [X RUN-vcgen-cmd].

Reading: the probe compiled unchanged on both newer toolchains only because the renamed `WP` fields kept their old names as aliases and the probe's imports (`Std.Tactic.Do`, `Std.WP`) still bring in the moved syntax; meanwhile the contract syntax gained a clause between 4.35.0 and 4.36.0-rc1. The interface is moving behind compatibility shims, not settled.

## Decision

1. **The twin stays dated and experimental.** Wherever S4.L9's production twin (SP-4.7) appears, it is labeled experimental, dated "Lean 4.35.0, recorded 2026-10-24", and shown after the learner's own generator. The tool says the same of itself on every toolchain run: the docstring calls `vcgen` "experimental and subject to change", and both `vcgen` and the contract syntax warn while their acknowledging options are off [X RUN-vcgen-cmd].
2. **The custom type works, so S4.L9 may show it.** The S4 lesson task (W3-T03) may show `vcgen` on a Mini-Plinth-style `Transfer` value beside the measured shallow contract {{run:RUN-lean-vcgen}}. SP-4.7's point, that an unprovable condition and a satisfiable negation are two faces of one obligation, reads better on the command type, whose condition is the learner's obligation shape over the semantics' own `post` (results 2 and 3). The card's open sentence "on a custom command type it is {{run:RUN-vcgen-cmd}}" can become, for example: on a Mini-Plinth-style command type, `vcgen` proves the guarded Transfer once it is given a weakest-precondition instance and one specification per construct, and with the guard weakened to `balance(from) >= 0` it leaves `0 ≤ (post s from to amount).bal from` [X RUN-vcgen-cmd].
3. **The course ships the glue; the learner does not write it.** The WP instances, `wp` equations and specs are read-only reference behind a recorded run, since the tab runs no Lean. LAB-4 and the stretch stage LAB-4.9 are unchanged.
4. **If the glue is shown, use the lattice style.** Write the guard and `if` specs with `⊓` and `⇨`, not with an `if` in the precondition (result 4).
5. **State rejections with a triple on the 4.35.x pin.** Use `⦃ P ⦄ c ⦃ Q; E ⦄` for a reachable rejection, not a contract: a 4.35.0 contract's exception postcondition is `⊥` (F2), and `throws` does not parse on 4.35.0 but does on 4.36.0-rc1 (result 6). Write a contract's command as an inline literal (F3).
6. **Re-check at every toolchain bump.** A Lean bump re-runs this record with the rest of `runs/` (GATE-runs); the twin's date moves only when the re-run passes. Production-twin pins carry a 60-day TTL (GATE-facts), so this result is due for re-checking by 2026-12-23 at the latest.

## Fallback

If a later toolchain breaks the command-type demonstration, for example by dropping the `wpTrans` aliases, the twin keeps showing the 4.35.0 recorded run, still dated and experimental, until the glue is ported. If porting is not worth it, S4.L9 shows `vcgen` on the measured shallow transfer contract alone {{run:RUN-lean-vcgen}}. Neither path drops the "experimental" label or the date.

## Open risks

1. A later release may remove the `wpTrans` and `wp_trans_monotone` aliases; the glue then needs the new names `trans` and `trans_monotone` (result 6).
2. The lattice-style split rests on how `vcgen` decomposes `⊓` and `⇨` today. It is behavior observed in this run, not checked against documentation, and an experimental tactic can change it.
3. The conditions were discharged with `grind`, so every proof lists `Classical.choice` [X RUN-vcgen-cmd]. That is fine for a twin, but a card that sets it beside S2's manual proofs should say so.
4. Coverage is narrow: `move` is the only resource operation (no `deposit`, `hold`, `capture` or `release`), there are no loops, and the state is a function. The LAB-3 template's association-list `State` would need its own lemmas, untested here.
5. 4.36.0-rc1 and the nightly are previews; 4.36.0 and 4.37.0 may differ. Edition 1 stays on 4.35.x (OD-12).

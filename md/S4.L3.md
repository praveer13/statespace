## Rules for sequence, branch and guard (16 min)

**Question** (before the segment):

Transfer is `requires g; move`, where `g` is `bal(from) ≥ amount`. Which formula is `wp(Transfer, Q)` for a state predicate `Q`?

- A. `g ∧ wp(move, Q)`
- B. `g → wp(move, Q)`
- C. `(g → wp(move, Q)) ∧ (¬g → Q)`
- D. `wp(move, Q)`

Two rules cover sequence and branching. Work backwards through a sequence, last command first, and split a branch by its condition:

`wp(c₁; c₂, Q) = wp(c₁, wp(c₂, Q))`

`wp(if b then c₁ else c₂, Q) = (b → wp(c₁, Q)) ∧ (¬b → wp(c₂, Q))`

A guard `g` before a body `c` has four readings. They differ in what a failing guard means:

| Reading | When `g` fails | `wp(g; c, Q)` |
|---|---|---|
| `if g → c fi` (Dijkstra) | the program aborts | `g ∧ wp(c, Q)` |
| `assert g; c` | an error to rule out | `g ∧ wp(c, Q)` |
| `assume g; c` | the run is ignored | `g → wp(c, Q)` |
| `requires g; c` (Mini-Plinth) | `Err`, state unchanged | `(g → wp(c, Q)) ∧ (¬g → Q)` |

The first two share a formula and differ in meaning. Mini-Plinth is the last row: a rejected command still runs and leaves the state as it was, so `Q` must already hold there. One cost to know: the weakest precondition of n sequential `if`s copies `Q` up to 2ⁿ times, because each branch substitutes into its own copy. Naming each intermediate formula with `define-fun` keeps the query linear, and LAB-4.3 tests it.[^s1b2-1]

**Cell 1** (INS-derivation)

Query asserts: for each line, a state where the line fails to follow from what it rests on. Line 5 asks for a state where the assume-reading candidate and the reject-reading formula disagree. `sat` means the line is not valid.

```text
command  Transfer:  requires amount ≤ a;  a := a − amount;  b := b + amount
post     Inv = a ≥ 0 ∧ b ≥ 0

1  wp(b := b + amount, Inv)         =  a ≥ 0 ∧ b + amount ≥ 0                          rule: assignment
2  wp(a := a − amount; …, Inv)      =  a − amount ≥ 0 ∧ b + amount ≥ 0                 rule: sequence, then assignment
3  wp(requires …, Inv)              =  (amount ≤ a → line 2) ∧ (¬(amount ≤ a) → Inv)   rule: guard, reject reading
4  candidate, assume reading        =  amount ≤ a → line 2                             rule: guard, assume reading
5  line 4  ⇔  line 3                                                                   rule: equivalence
```

Is the assume-reading candidate (line 4) equivalent to the reference weakest precondition of Transfer (line 3)?

- A. They are equivalent.
- B. They differ wherever the guard fails.
- C. They differ only where the guard fails and Inv already fails.

**Question** (ends the segment):

The command is `assert amount ≤ limit; a := a − amount` with postcondition `a ≥ 0`. A failing `assert` is an error to rule out. Which formula is the weakest precondition?

- A. `amount ≤ limit → a − amount ≥ 0`
- B. `(amount ≤ limit → a − amount ≥ 0) ∧ (amount > limit → a ≥ 0)`
- C. `a − amount ≥ 0`
- D. `amount ≤ limit ∧ a − amount ≥ 0`

## Exit (4 min)

**Question** (exit question):

Which formula is the weakest precondition of `if a ≥ amount then a := a − amount else b := b + amount` for `a ≥ 0 ∧ b ≥ 0`?

- A. `(a ≥ amount → a − amount ≥ 0 ∧ b ≥ 0) ∧ (a < amount → a ≥ 0 ∧ b + amount ≥ 0)`
- B. `a ≥ amount → a − amount ≥ 0 ∧ b ≥ 0`
- C. `(a − amount ≥ 0 ∧ b ≥ 0) ∧ (a ≥ 0 ∧ b + amount ≥ 0)`
- D. `(a ≥ amount → a ≥ 0 ∧ b + amount ≥ 0) ∧ (a < amount → a − amount ≥ 0 ∧ b ≥ 0)`

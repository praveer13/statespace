# S5.L8 · What "no error" means

> Draft: first-learner pass pending.

**Format.** Short lesson with reading, about 18 minutes.

**Objective.** State what a TLC result covers, from its constants, bounds and symmetry, and choose its stamp, which is [M] with its qualifier and never [P].

**Ideas taught.**

- "No error" holds for stated constants and bounds, not every size

**Segments.**

1. Change the constants
2. Exit

## Change the constants (14 min)

**Question** (before the segment):

TLC checks a transfer model with two workers and finishes with no error. What may you claim?

- A. [M] · two workers, these constants · complete
- B. [P] for every size: the transfer never overspends
- C. [T] · n = the distinct-state count

A model check is a check of one finite model, and changing the model can change the verdict. Run the transfer model from S5.L3 with each worker spending 40 from a balance of 100.

**Cell 1** (INS-spectacle)

Spec asserts: each worker reads the balance, checks the guard against what it read, then writes. The check asks whether `NoOverspend` can fail. Set `Init` to 100, `Amount` to 40 and two workers, run to completion, then add a third worker and watch the minimap.

```tla
---- MODULE DoubleSpend ----
EXTENDS Naturals
CONSTANTS Init, Amount, Workers
VARIABLES bal, pc, seen, spent
vars == <<bal, pc, seen, spent>>

Init_ == /\ bal = Init
         /\ pc = [w \in Workers |-> "read"]
         /\ seen = [w \in Workers |-> 0]
         /\ spent = 0

Read(w) == /\ pc[w] = "read"
           /\ seen' = [seen EXCEPT ![w] = bal]
           /\ pc' = [pc EXCEPT ![w] = IF bal >= Amount THEN "write" ELSE "done"]
           /\ UNCHANGED <<bal, spent>>

Write(w) == /\ pc[w] = "write"
            /\ bal' = seen[w] - Amount
            /\ spent' = spent + Amount
            /\ pc' = [pc EXCEPT ![w] = "done"]
            /\ UNCHANGED seen

Next == \E w \in Workers : Read(w) \/ Write(w)
NoOverspend == spent <= Init
====
```

**From a system to a finite model.** Your system has no fixed number of workers and no cap on a balance, and TLC can finish only on a finite graph. So a check explores a finite-state abstraction of your system: a model with finitely many states that stands in for it. Constants fix the number of workers and the amounts. A CONSTRAINT cuts the search off at a bound. SYMMETRY counts states that differ only by swapping interchangeable workers as one. What TLC reports is about that model, and it covers your system only as far as the model does.

Each choice has a cost.

- Constants change the size fast: at `Amount` 80 the model has 11, 45, 191 and 813 distinct states at two to five workers.
- A CONSTRAINT drops states silently, so the stamp is [M] · bound · partial.
- SYMMETRY can shrink the space by about n! for n interchangeable workers, but TLC warns that symmetry during liveness checking might miss violations (run RUN-tlc-sym-liveness). Liveness cards say symmetry off.
- A complete run prints collision estimates, 8.3E-7 (optimistic) and 2.1E-9 (actual fingerprints), on a model of 2,986,377 distinct states. Complete means every reachable state, unless a collision hid one.
- TLC runs one worker unless told otherwise (run RUN-tlc-help), so claim a shortest trace only from a one-worker run.

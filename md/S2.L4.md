**Objective.** Put the steps of an induction proof in order, spot the circular step, and pick the hypothesis each case needs.

**Ideas taught.**

- Base case and step; the hypothesis is not circular

1. Base, step, and one trap

## Base, step, and one trap (15 min)

**Question** (before the segment):

`net` adds up a list of postings: `net [] = 0` and `net (x :: xs) = x + net xs`. To prove `net (xs ++ ys) = net xs + net ys` for all lists, which variable do you induct on?

- A. `xs`
- B. `ys`
- C. Both at once
- D. Neither: `simp` proves it

You met induction on a number. The same idea works on a list, and a list is closer to a ledger: a list of postings is either empty or a first posting followed by the rest. To prove a claim about every list, prove it for the empty list (the base case), then prove it for `x :: xs` assuming it for `xs` (the step). That assumption is the **induction hypothesis**, `ih`. It is not circular: `ih` is about the shorter list `xs`, and you are proving the claim for the longer `x :: xs`.

Here the claim is that the net of two joined lists is the sum of their nets. You induct on `xs`, the list that `++` takes apart. In the base case both sides reduce to `net ys`. In the step, `net (x :: xs ++ ys)` unfolds to `x + net (xs ++ ys)`, `ih` rewrites `net (xs ++ ys)`, and what is left is adding up in a different order.

**Cell 1** (INS-goal-replay)

Replay shows: the whole proof of `net_append`, one tactic at a time. The `nil` case is the base case; in the `cons` case, `ih` is the claim for the shorter list `xs`.

```lean
def net : List Int → Int
  | [] => 0
  | x :: xs => x + net xs

theorem net_append (xs ys : List Int) : net (xs ++ ys) = net xs + net ys := by
  induction xs with
  | nil => simp [net]
  | cons x xs ih => simp [net, ih, Int.add_assoc]
```

Now the trap. Suppose the step skipped `ih` and appealed to the theorem itself on the same list, `x :: xs`. That uses the claim for the very list you are proving it for. Make your call before you see what Lean does.

**Cell 2** (INS-goal-replay)

Replay shows: Lean's verdict on this variant, whose step appeals to the claim on the same list `x :: xs`.

```lean
theorem net_append_loop (xs ys : List Int) : net (xs ++ ys) = net xs + net ys := by
  cases xs with
  | nil => simp [net]
  | cons x xs => exact net_append_loop (x :: xs) ys
```

**Question** (ends the segment):

These blocks belong to a proof of `net_append`, and some do not.

1. Induct on `xs`.
2. Induct on `ys`.
3. Base case: both sides reduce to `net ys`.
4. Step: rewrite with `ih`, the claim for the shorter list `xs`, then add up in the other order.
5. Step: rewrite with `net_append (x :: xs) ys`, the claim being proved.

Which list of blocks, in this order, is a proof?

- A. 2, 3, 4
- B. 1, 4
- C. 1, 3, 4
- D. 1, 3, 5

**Question** (ends the segment):

In the proof of `net_append`, which fact does the `x :: xs` case need?

- A. `net_append (x :: xs) ys`
- B. `ih : net (xs ++ ys) = net xs + net ys`
- C. `net [] = 0`
- D. `net (ys ++ xs) = net ys + net xs`

## Exit (5 min)

**Question** (exit question):

`doubleAll` doubles every posting in a list: `doubleAll [] = []` and `doubleAll (x :: xs) = (x + x) :: doubleAll xs`. To prove `(doubleAll xs).length = xs.length` by induction on `xs`, which fact does the `x :: xs` case need?

- A. `(doubleAll (x :: xs)).length = (x :: xs).length`
- B. `(doubleAll []).length = [].length`
- C. `x + x = 2 * x`
- D. `ih : (doubleAll xs).length = xs.length`

Explain it back to yourself: say why the base case is needed and what the step assumes, without naming a tactic. Nobody grades this.

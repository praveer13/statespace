## One pinned environment, and its size (2 min)

The devcontainer pins the Lean toolchain (run RUN-lean-ledger), the TLA+ tools by SHA-256 with a Java runtime (run RUN-tlc-jars), PostgreSQL (run RUN-pg-anomalies), Z3 (run RUN-z3-starter), cvc5 and the Rust crates, with their binaries recorded in (run RUN-scaffold). Each tool is met first in the tab, and the container is for the labs.

Check the sizes before you start. The Lean toolchain unpacks to 3.0G (run RUN-lean-toolchain). The course uses no Mathlib, and a Mathlib project's packages take 7.3G (run RUN-lean-mathlib). A Codespaces prebuild is the zero-install route.

## What doctor checks (1 min)

`statespace doctor` checks the pins and the sandbox and prints a receipt-ready environment block (run RUN-doctor-devcontainer). Green means the environment matches the pins. It checks no proof, and a failed sandbox does not turn it red: that is recorded, never required.

## The sandbox (3 min)

Lean builds run in a bubblewrap sandbox on Linux only, and the receipt records it as on, off or failed, never as required. The threat is self-deception, not attack. Without bubblewrap the comparator exits with code 2. Under default Docker bubblewrap cannot start, and the comparator exits with code 1, the code of a rejection (run RUN-lean-bwrap-docker). A checker killed for memory exits like a rejection too (run RUN-bwrap-lanes). With the sandbox disabled, `lake check` prints a warning that the run is not trustworthy (run RUN-lean-axioms).

So receipts parse verdict lines and never trust an exit code alone. A failed sandbox is told from a rejection by a `bwrap:` line, and the first `bwrap:` line names the cause. `statespace doctor` prints the matching hint (run RUN-bwrap-lanes):

| What the first line says | What it means | What changes it |
|---|---|---|
| it cannot create a new namespace | the container's seccomp profile blocks namespace flags, as Docker's default profile does, or the host forbids unprivileged user namespaces | the devcontainer's opt-in sandbox profile; on a host, allow unprivileged user namespaces |
| it cannot mount proc | the container masks `/proc` paths | `systempaths=unconfined` |
| it cannot create `/run/user` on a read-only file system | the image has no `/run/user` | create the directory in the image |
| `pivot_root` is not permitted | seccomp blocks `pivot_root`, which Docker's default profile does even with extra capabilities | allow it, as the opt-in profile does |
| `unshare`, `mount` or `umount2` is not permitted | seccomp blocks that call | allow them |
| a uid map or loopback setup is denied | Ubuntu 24.04's AppArmor restriction on unprivileged user namespaces | on the host, the sysctl or an AppArmor profile for the binary |
| `mount` is denied on the root | Docker's AppArmor profile denies it | `apparmor=unconfined` in the container |
| the tool says it needs bubblewrap and could not find it | bubblewrap is not installed or not on `PATH` | install it |

macOS and Windows learners use the devcontainer. The lab zip's agent kit travels with it, and its hook blocks agent edits to `TODO(you)` bodies, challenge files, claims and receipts.

## A timer is state (2 min)

"Release the hold after 24 hours" is a durable record, a due time, plus an action that fires it. A timer kept only in the worker's memory dies with the worker.

A timeout that sends again can race a late reply, and the effect then happens twice with no crash at all (the timeouts family of lesson S8.L3). The remedy is a key that names the intent, not the attempt (lesson S8.L4).

## Firing needs fairness (2 min)

"The hold is eventually released" holds only if the timer action is weakly fair and the worker recovers (lessons S5.L7 and S8.L5). Without fairness, a behavior in which the timer never fires is allowed.

Time in a spec is an action. TLA+ models a timeout as an action that becomes enabled, not as wall-clock seconds, and a harness, not the clock, decides when it fires (D-21).

## Pollers (1 min)

A common design is a due-time column and a poller that claims rows with `FOR UPDATE SKIP LOCKED`. PostgreSQL's documentation says that skipping locked rows "provides an inconsistent view of the data". The lost effect of lesson S8.L3 comes from a poller that keeps a high-water mark (run RUN-tlc-lost-effect).

# S6.L1 · SQL is not relational algebra

> Draft: first-learner pass pending.

**Format.** Short lesson with reading, about 19 minutes.

**Objective.** Predict, before each run, the row count and stored values of cells that involve NULL and duplicate rows, and pick a row that a predicate and its negation both skip.

**Ideas taught.**

- Bags, NULL and three-valued logic
- CHECK accepts NULL; WHERE skips it

**Segments.**

1. Three truth values
2. Exit

## Three truth values (16 min)

Your transfer lived in a model where a comparison is true or false. Stage 6 compiles it into SQL, and SQL has a third answer. Commit to one prediction before the first cell.

**Question** (before the segment):

A table `t(id int, team int, bal bigint CHECK (bal >= 0))` holds rows. Which statement is true?

- A. Inserting a row whose `bal` is NULL is rejected.
- B. `SELECT count(bal)` counts the rows whose `bal` is NULL.
- C. `WHERE NOT (bal >= 10)` selects exactly the rows that `WHERE bal >= 10` skips.
- D. `SELECT team FROM t` can return the same value twice.

**How the cells work.** Every cell in this stage runs PostgreSQL in your browser tab through PGlite, which reports PostgreSQL 18.6 (run RUN-pglite-0511). A cell starts from an empty database, runs its statements in order, and prints each statement's rows, row count or error code. Nothing carries over to the next cell. The tab has one connection, so it cannot show two transactions at once; S6.L6 replays recorded histories for that. While the engine loads, a cell shows a recorded run with its ID.

**Cell 1** (INS-pglite)

Two rows, one with a NULL balance and one with 50. The UPDATE debits 10 from every row whose balance is at least 10.

The cell asserts nothing. It records what the database does: read the row count the UPDATE reports and the balances the SELECT shows.

```sql
CREATE TABLE t (id int PRIMARY KEY, team int, bal bigint CHECK (bal >= 0));
INSERT INTO t VALUES (1, 1, NULL), (2, 1, 50);
UPDATE t SET bal = bal - 10 WHERE bal >= 10;
SELECT id, bal FROM t ORDER BY id;
```

**Your call before the first run:**

`UPDATE t SET bal = bal - 10 WHERE bal >= 10` runs over row 1 (balance NULL) and row 2 (balance 50). What happens?

- A. 1 row: row 2 becomes 40 and row 1 is untouched.
- B. 0 rows: the NULL row stops the statement.
- C. 2 rows: row 1 stays NULL and row 2 becomes 40.
- D. An error: NULL cannot be compared.

Recorded run: RUN-pg-anomalies (postgres 18.6).

Text that follows the first run is left out here.

A `CHECK` accepts a row when its expression is true or unknown. A `WHERE` keeps a row only when its expression is true. So one NULL balance gets past the constraint, and then every guard you write skips it. Two more departures from the algebra you learned: a table is a bag, so a result can repeat a row, and `count(bal)` skips NULLs where `count(*)` does not.

**Cell 2** (INS-pglite)

Run it and check each result against the rule above.

Free run. Predicate, negation and IS NULL together account for every row; the NULL amount selects nothing; `team` repeats.

```sql
CREATE TABLE t (id int PRIMARY KEY, team int, bal bigint CHECK (bal >= 0));
INSERT INTO t VALUES (1, 1, NULL), (2, 1, 50), (3, 2, 5);
-- every row lands in exactly one of three groups
SELECT count(*) FILTER (WHERE bal >= 10)           AS p,
       count(*) FILTER (WHERE NOT (bal >= 10))     AS not_p,
       count(*) FILTER (WHERE (bal >= 10) IS NULL) AS unknown,
       count(*)                                    AS all_rows
FROM t;
-- NULL equals nothing, itself included
SELECT id FROM t WHERE bal = NULL;
SELECT id FROM t WHERE bal IS NULL;
-- a NULL amount in the guard
UPDATE t SET bal = bal - CAST(NULL AS bigint)
 WHERE id = 2 AND bal >= CAST(NULL AS bigint);
-- a table is a bag
SELECT team FROM t ORDER BY id;
```

Recorded run: RUN-pg-sql-semantics (postgresql 18.6).

**Question** (ends the segment):

A table `t(bal bigint, frozen boolean)` may hold any of the rows below, written `(bal, frozen)`. Which row is selected by neither `WHERE bal >= 10 OR frozen` nor `WHERE NOT (bal >= 10 OR frozen)`?

- A. `(NULL, true)`
- B. `(5, NULL)`
- C. `(50, NULL)`
- D. `(5, false)`

## Exit (3 min)

**Question** (exit question):

Which statement is true?

- A. `bal = NULL` is true when `bal` is NULL.
- B. `UNION` keeps duplicate rows.
- C. `count(*)` skips the rows whose balance is NULL.
- D. `2 NOT IN (1, NULL)` is unknown, so a `WHERE` built on it keeps nothing.

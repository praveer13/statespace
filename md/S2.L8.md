## One account, two writes (14 min)

**Question** (before the segment):

An account holds 10 and transfers 5 to itself. Both new balances are computed from the old state, then written in order: the debit, then the credit. What is the final balance?

- A. 10
- B. 5
- C. 15
- D. 20

Until now a ledger had two fields. A system with many accounts keeps its state as a function from account numbers to balances, and a transfer becomes a pair of writes. Here `Bal := Acct → Int`, and `upd f k v` is `f` with the single account `k` set to `v`.

The roadmap says finite maps. Here accounts are a function from every account number to a balance, because a finite-map library would need Mathlib, which this stage leaves out (run RUN-lean-mathlib). The theorems cover the two accounts a transfer touches and every account it leaves alone. A total over many accounts is not proved.

```lean
abbrev Acct := Nat
abbrev Bal := Acct → Int

def upd (f : Bal) (k : Acct) (v : Int) : Bal := fun j => if j = k then v else f j

-- both new balances are computed from the OLD state, then written in order
def xferBuggy (f : Bal) (src dst : Acct) (n : Int) : Bal :=
  if 0 ≤ n ∧ n ≤ f src then upd (upd f src (f src - n)) dst (f dst + n) else f
```

Ask Z3 whether this update can ever change an account that sends to itself.

**Cell 1** (INS-z3)

Query asserts: one account is both sender and recipient, the guard allows the amount, and the balance afterwards differs from the balance before. `sat` means such a self-transfer exists.

```python
from z3 import *

Bal = Array('Bal', IntSort(), IntSort())   # account number -> balance
src, dst, n = Ints('src dst n')

allowed = And(0 <= n, n <= Bal[src])       # the guard
# the buggy update: both new balances come from the OLD state
buggy = Store(Store(Bal, src, Bal[src] - n), dst, Bal[dst] + n)

s = Solver()
s.add(src == dst, allowed, buggy[src] != Bal[src])
print(s.check())
print(s.model())
```

The cure is to read the destination after the debit:

```lean
def xfer (f : Bal) (src dst : Acct) (n : Int) : Bal :=
  if 0 ≤ n ∧ n ≤ f src then
    let f1 := upd f src (f src - n)
    upd f1 dst (f1 dst + n)
  else f
```

Lean can check one instance of each with `decide`, which evaluates a closed, decidable claim. On another balance and amount, so the proofs in LAB-2.6 stay yours:

```lean
theorem mints_from_7 : xferBuggy (fun _ => 7) 0 0 3 0 = 10 := by decide
theorem fixed_from_7 : xfer (fun _ => 7) 0 0 3 0 = 7 := by decide
```

Lean accepts both (run RUN-lean-s2-cells). `decide` checks this instance, not the general theorem. The theorems in the lab are the general ones: every other account is untouched, the two accounts' sum is unchanged, and a self-transfer changes nothing.

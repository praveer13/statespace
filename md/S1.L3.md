# S1.L3 · The guard, and what unsat says

**Format.** Short lesson with reading, about 20 minutes.

**Objective.** Add the sufficient-funds guard, read unsat as a statement about exactly this encoding, check that the premises can hold, then fill in the six fields of your first claim.

**Ideas taught.**

- Every `unsat` needs a satisfiable premise witness
- A false premise makes an implication true; vacuous premises
- State a guarantee in six fields, with an "if weakened" witness that refutes the claim's own proposition

## Beside every answer (14 min)

With the sufficient-funds guard, the violation query is `unsat` (run RUN-z3-starter). Read that exactly: for every input of this encoding, the guarded transfer leaves the sender at zero or above, if the solver is sound. The course also runs the query on a second solver, cvc5, at build time, and it agrees (run RUN-cvc5-alethe). Two solvers agreeing is diversity, not a checked proof, so the stamp still says uncertified.

An `unsat` can be empty, though. So every `unsat` gets a premise query beside it: the premises and the guard, with no negated property.

**Cell 1** (INS-z3)

Query asserts: balances and an amount that satisfy the premises and the guard. With no negated property, `sat` means the premises can hold together.

```python
from z3 import *
a, b, amount = Ints('a b amount')
s = Solver()
s.add(a >= 0, b >= 0, amount > 0)   # the premises
s.add(amount <= a)                  # the sufficient-funds guard
print(s.check())                    # no negated property this time
print(s.model())
```

**Cell 2** (INS-z3)

Three queries on the config: (i) a violation of "the sender ends at zero or above", (ii) a violation of the absurd property "the sender ends 1,000,000 richer", and (iii) the premises alone.

Query asserts: for each property, an allowed transfer that violates it. Query (iii) asks whether any allowed transfer exists.

```python
from z3 import *
a, b, amount = Ints('a b amount')
MAX_TRANSFER = 0                      # the config's default
premises = [a >= 0, b >= 0, amount > 0, amount <= MAX_TRANSFER]

def violation_of(prop):
    s = Solver()
    s.add(premises)
    s.add(Not(prop))                  # search for a violation of the property
    return s.check()

print(violation_of(a - amount >= 0))                # (i)
print(violation_of(a - amount == a + 1000000))      # (ii)
s = Solver()
s.add(premises)
print(s.check())                                    # (iii)
```

Now your first claim. A claim is a six-part guarantee card: the proposition, its assumptions, the model, the method, how the code corresponds to the model, and the counterexample you get when an assumption is weakened. It also has a requirement row and a three-segment strip: what the solver established about the model, whether the code matches the model, and whether it is the guarantee you wanted. Drawer D-06 explains each field.

Two assumptions on the card are drawn dashed: balances are unbounded integers (SEAM-1), and the solver is sound (SEAM-7). A seam is an assumption planted on purpose. Some give way later in the course; some are tested and hold.

## A question first (3 min)

The evaluator you just met answers every call. This lesson asks what that hides.

**Question** (before the segment):

Your Lean evaluator is total: it returns a value on every input. Can a Mini-Plinth program still go wrong?

- A. Yes: a total evaluator must answer even where the semantics has no rule.
- B. No: a total evaluator answers each input, and nothing can go wrong.
- C. If the program loops: a loop is the one thing that can go wrong.

## One step at a time (11 min)

Big-step evaluation gives only the final outcome. Small-step evaluation gives the journey: a relation that takes one step from a configuration to the next. A configuration is a program part-way through a run. A call moves through `bind` (arguments meet parameters), `checked`, `guard` and `run`, and ends in `done`, with a state, an output and effects, or in `err`, with a name. Expressions step left to right, and `balance(acct a)` steps to the literal `bal s a`.

`done` and `err` are final. A non-final configuration with no step is stuck: the relation has no rule for it. Stuck is not an error. An error is a defined outcome with a rule, and stuck is the absence of a rule.

A total evaluator hides the difference, because it must answer anyway: asked for `balance(30)`, a big-step lookup can read 0 and look fine. A relation cannot fake it, so it says honestly where the semantics stops, and typing's job is to keep programs away from that edge.

```lean
abbrev State := List (String × Int)

def bal (s : State) (a : String) : Int := (s.lookup a).getD 0

inductive E where
  | num  : Int → E
  | acct : String → E
  | bal  : E → E
  | ge   : E → E → E
  | tt   : E
  | ff   : E

/-- One small step of an expression, left to right. -/
inductive Step (s : State) : E → E → Prop
  | bal_acct (a : String) : Step s (.bal (.acct a)) (.num (bal s a))
  | bal_cong {e e' : E} : Step s e e' → Step s (.bal e) (.bal e')
  | ge_left {e₁ e₁' e₂ : E} : Step s e₁ e₁' → Step s (.ge e₁ e₂) (.ge e₁' e₂)
  | ge_right {n : Int} {e₂ e₂' : E} : Step s e₂ e₂' → Step s (.ge (.num n) e₂) (.ge (.num n) e₂')
  | ge_num (m n : Int) : Step s (.ge (.num m) (.num n)) (if n ≤ m then .tt else .ff)

/-- `balance(30)`: no rule applies, so there is no next expression. -/
theorem balance_num_stuck (s : State) (n : Int) : ∀ e', ¬ Step s (.bal (.num n)) e' := by
  intro e' h
  cases h with
  | bal_cong h' => cases h'
```

**Cell 1** (INS-interp)

A command whose guard reads the balance of an amount, called with typing bypassed.

The trace view steps the call one rule at a time. Typing is bypassed, so nothing turns the program away before it runs.

```text
command Odd(from: account, to: account, amount: amount)
  requires balance(amount) >= amount

call Odd(a, b, 30)        -- typing bypassed
```

## Exit (4 min)

**Question** (exit question):

A well-typed call runs `release h` with `h` = 9, in a state that has no hold 9. How does the configuration end under the reference relation?

- A. It steps to `done`: releasing hold 9 is a no-op.
- B. It ends in an error: `err (unknownHold 9)`.
- C. It is stuck: there is no hold 9 to release (no rule).

# S7.L7 · The leaky shared document, and declassifying on purpose

> Draft: first-learner pass pending.

**Format.** Short lesson with reading, about 23 minutes.

**Objective.** Find a leak in a shared view with the paired check, write a release record that says what, who, where and when, and refute the blanket claim that no tenant ever observes any change in another tenant.

**Ideas taught.**

- What, who, where and when; why the blanket claim is false
- Counts, sizes and integrity checks as channels

**Segments.**

1. Before you start
2. Finding the leak, then releasing on purpose
3. Exit

## Finding the leak, then releasing on purpose (16 min)

The shared page now also returns `internal_notes`. Check it by pairing: related worlds agree on Acme's data and on the released title and body of shared documents.

**Cell 1** (INS-pairs)

The viewer replays the pair that Z3 finds for the self-composition query.

Query asserts: two worlds related under ~Acme with this release, and a different response to `Open(dana, contract)` in each. `sat` means such a pair exists.

```text
view Open(viewer, id) =
  if no document has this id        then error not_found
  else if not canread(viewer, id)   then error not_found
  else the page of id, with title, body, owner_team and internal_notes

release  title and body of documents shared with Acme

pair
  call   Open(dana, contract)
  left   W0
  right  W0 with a different contract.internal_notes
```

**Cell 2** (INS-pairs)

A record for sharing, in the shape `claims/declassify.yaml` will hold. The viewer relates one pair twice: under the blanket relation, and under ~Acme with this record.

Pair asserts: Birch shares contract with dana, then edits its body, and dana opens contract in both worlds.

```yaml
- what:  "title and body of document d"        # a projection of the state, not an output field
  to:    "the users and teams d is shared with"
  who:   "editors and admins of d's owning team (the Share command's guard)"
  where: "Share releases; Open and ListShared show"
  when:  "from Share until Revoke; what was delivered stays delivered"
  why:   "requirement R-share"
```

Recorded run: RUN-pairs-reference (not recorded yet).

Text that follows the first run is left out here.

Three of Sabelfeld and Sands' principles apply to a record: with an empty record you get plain noninterference; "adding further declassifications to a secure program cannot render it insecure"; and "the presence of a declassification operation cannot mask other covert information leaks". The last is why you release state projections, not output fields. If a view returned `body ++ internal_notes` as `body`, releasing the stored body still catches the notes, while exempting the output field would hide them.

**Cell 3** (INS-pairs)

Pair asserts: two worlds that differ only in whether Birch's private layoffs-memo exists, and one search by frank.

```text
view Search(viewer, term) =
  hits    the documents the viewer can read whose title matches term
  total   the number of documents whose title matches term     ; counted before the filter
  answer  {hits, total}

pair
  call   Search(frank, "layoffs")
```

## Exit (4 min)

**Question** (exit question):

Release record: the number of documents shared with the viewer. `Dashboard(frank)` returns `{shared_with_me, workspace_total}`, and `workspace_total` counts every document in every tenant. Which pair does frank tell apart in a way the record does not explain?

- A. Two worlds that differ in whether Birch shares a document with frank.
- B. Two worlds that differ only in whether Birch has one more private document.

## Two questions first (3 min)

An agent's change note on your transfer handler reads:

You will test that by playing the scheduler yourself, and then by asking TLC to try every schedule. Two questions first. Guess if you are not sure, because the lesson answers both.

## Be the scheduler (15 min)

Each worker runs two steps. `Read` copies the balance into `seen` and decides from that copy whether it may write. `Write` sets the balance to the copy minus the amount. The agent's note is true as far as it goes: the guard does run before every write. What it tests is the copy, and the copy can be stale by the time of the write, because the other worker acts in between.

Call the steps R1 and R2 for the two reads, and W1 and W2 for the two writes. The Theater below loads this spec's whole state graph. The bar lists the actions enabled in the current state, and you choose which worker moves next. Your aim is a behavior that ends with more paid out than the account held.

**Cell 1** (INS-theater)

Scene: this spec's state graph. Pick an enabled action to take a step. The trace table follows `bal`, `spent` and what each worker saw. Aim for `spent` above 100.

```tla
---- MODULE DoubleSpend ----
EXTENDS Naturals
CONSTANTS Init, Amount, Workers
VARIABLES bal, pc, seen, spent
vars == <<bal, pc, seen, spent>>

Init_ == /\ bal = Init
         /\ pc = [w \in Workers |-> "read"]
         /\ seen = [w \in Workers |-> 0]
         /\ spent = 0

Read(w) == /\ pc[w] = "read"
           /\ seen' = [seen EXCEPT ![w] = bal]
           /\ pc' = [pc EXCEPT ![w] = IF bal >= Amount THEN "write" ELSE "done"]
           /\ UNCHANGED <<bal, spent>>

Write(w) == /\ pc[w] = "write"
            /\ bal' = seen[w] - Amount
            /\ spent' = spent + Amount
            /\ pc' = [pc EXCEPT ![w] = "done"]
            /\ UNCHANGED seen

Next == \E w \in Workers : Read(w) \/ Write(w)
Spec == Init_ /\ [][Next]_vars
NoOverspend == spent <= Init
====
\* Init = 100, Amount = 80, Workers = {w1, w2}
```

## Ask TLC (15 min)

A schedule you found by hand is one behavior. TLC explores all of them, breadth first, and reports the first one that breaks the invariant. You already ran the Theater's module on the Bench with the deadlock check off in the last lesson, because with default flags TLC stops first at the finished state (run RUN-tlc-doublespend). Pull up that receipt, read its counts and its trace, and set the trace beside yours.

The repair is to merge the guard and the write into one action, `Spend(w)`, so that no other worker can act between the check and the write. That is the atomic spec from the first lesson, and it is what the next cell runs.

**Cell 2** (INS-bench-tlc)

Model asserts: `NoOverspend` holds in every reachable state of the atomic spec. This run adds `-deadlock` and uses one worker (run RUN-tlc-help).

```tla
---- MODULE DoubleSpendAtomic ----
EXTENDS Naturals
CONSTANTS Init, Amount, Workers
VARIABLES bal, pc, spent
vars == <<bal, pc, spent>>

Init_ == /\ bal = Init
         /\ pc = [w \in Workers |-> "go"]
         /\ spent = 0

Spend(w) == /\ pc[w] = "go"
            /\ IF bal >= Amount
                 THEN bal' = bal - Amount /\ spent' = spent + Amount
                 ELSE UNCHANGED <<bal, spent>>
            /\ pc' = [pc EXCEPT ![w] = "done"]

Next == \E w \in Workers : Spend(w)
Spec == Init_ /\ [][Next]_vars
NoOverspend == spent <= Init
====
\* CONSTANTS Init = 100, Amount = 80, Workers = {w1, w2}
\* INIT Init_, NEXT Next, INVARIANT NoOverspend
```

## Change the grain (12 min)

Granularity is a modeling choice, and it decides which interleavings exist. This spec, M3, splits the check out of the read: `Read` copies the balance, `Check` tests the guard against the copy, and `Write` writes. Each worker now takes up to three steps, and there is one more place for the other worker to interrupt. Predict before you run: does the shortest violation get shorter, stay the same, or grow?

**Cell 3** (INS-spectacle)

Model asserts: `NoOverspend` holds in every reachable state of the split spec. Spectacle searches breadth first and stops at the first violation.

```tla
---- MODULE RTW3 ----
EXTENDS Naturals
CONSTANTS Init, Amount, Workers
VARIABLES bal, pc, seen, spent
vars == <<bal, pc, seen, spent>>

Init_ == /\ bal = Init
         /\ pc = [w \in Workers |-> "read"]
         /\ seen = [w \in Workers |-> 0]
         /\ spent = 0

Read(w) == /\ pc[w] = "read"
           /\ seen' = [seen EXCEPT ![w] = bal]
           /\ pc' = [pc EXCEPT ![w] = "check"]
           /\ UNCHANGED <<bal, spent>>

Check(w) == /\ pc[w] = "check"
            /\ pc' = [pc EXCEPT ![w] = IF seen[w] >= Amount THEN "write" ELSE "done"]
            /\ UNCHANGED <<bal, spent, seen>>

Write(w) == /\ pc[w] = "write"
            /\ bal' = seen[w] - Amount
            /\ spent' = spent + Amount
            /\ pc' = [pc EXCEPT ![w] = "done"]
            /\ UNCHANGED seen

Next == \E w \in Workers : Read(w) \/ Check(w) \/ Write(w)
Spec == Init_ /\ [][Next]_vars
NoOverspend == spent <= Init
====
\* CONSTANTS Init = 100, Amount = 80, Workers = {w1, w2}
\* INIT Init_, NEXT Next, INVARIANT NoOverspend, deadlock check off
```

## Values and evidence (14 min)

**Question** (before the segment):

In `(h : 0 ≤ n ∧ n ≤ s.a)`, what is `h`?

- A. A Boolean value that happens to be true
- B. A term whose type is the proposition
- C. A check that the program runs on `h`
- D. A comment written for the reader

Lean is a programming language and a proof language at once. A function such as `transfer` runs: you give it numbers and it returns a ledger. A proof does not run. It is a term whose type is the statement, and Lean checks that the type fits.

That is the idea of propositions as types. A statement such as `0 ≤ n ∧ n ≤ s.a` is a type, and a proof of it is a value of that type: evidence. So a hypothesis `h : 0 ≤ n ∧ n ≤ s.a` is neither a Boolean the program tests nor a comment. It is evidence you were handed, a pair of facts: `h.1` is the first and `h.2` the second.

Start with the part that runs. Make your call, then see what `#eval` prints.

**Cell 1** (INS-goal-replay)

Replay shows: what `#eval` prints. It runs `transfer` on a ledger holding 10 and 0, moving 3.

```lean
structure Ledger where
  a : Int
  b : Int
deriving Repr, DecidableEq

def transfer (s : Ledger) (n : Int) : Ledger :=
  if 0 ≤ n ∧ n ≤ s.a then { a := s.a - n, b := s.b + n } else s

#eval transfer { a := 10, b := 0 } 3
```

**A word ahead: dependent types.** The type of `h` mentions `s` and `n`, which come before it. A type that depends on values is a dependent type; in S3 you use one to make amounts that carry a proof that they are positive. Here the idea is only named, and nothing in this lesson grades it.

**Question** (ends the segment):

What does Lean do with this declaration?

```lean
theorem keep_a (s : Ledger) (n : Int) (h : 0 ≤ n ∧ n ≤ s.a) : 0 ≤ s.a :=

```

- A. It does not elaborate
- B. It is a computation
- C. It proves its statement

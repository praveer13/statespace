## What a suite reaches (18 min)

Your compiler runs. The next question is what a test of it can tell you. A differential suite feeds the same generated commands to a reference and to the compiled plan on a real database, then compares outcome classes: committed, refused for a named reason, or an error code.

**Question** (before the segment):

A suite ran n generated transfers through the reference interpreter and the compiled plan on a database, and found no divergence. Which stamp fits?

- A. `PROVED [P] · n runs · no divergence`
- B. `MODEL-CHECKED [M] · bound n · complete`
- C. `ENFORCED [E] · in PostgreSQL, at commit`
- D. `TESTED [T] · n · generator statistics`

The cell below is a small harness in SQL. Its reference is a rule standing in for the course's interpreter: it rejects a self-transfer, refuses an overdraft and commits everything else. The plan under test is the one-statement CASE compile from S6.L2. The generator draws accounts 1 to 3 with `from` and `to` different, and amounts 1 to 200.

**Cell 1** (INS-pglite)

Each `suite(n, self_pct)` call runs n commands, with `self_pct` percent of them self-transfers, and prints its statistics and its first divergence, if any. Edit the numbers and run again.

```sql
CREATE TABLE mut (id int PRIMARY KEY, bal bigint NOT NULL CHECK (bal >= 0));

CREATE FUNCTION plan_case(f int, t int, amt bigint) RETURNS text AS $$
DECLARE n int;
BEGIN
  UPDATE mut
     SET bal = CASE WHEN id = f THEN bal - amt ELSE bal + amt END
   WHERE id IN (f, t) AND (SELECT bal FROM mut WHERE id = f) >= amt;
  GET DIAGNOSTICS n = ROW_COUNT;
  RETURN CASE WHEN n = 0 THEN 'refused' ELSE 'committed' END;
END $$ LANGUAGE plpgsql;

CREATE FUNCTION suite(n int, self_pct int)
RETURNS TABLE (commands int, self_transfers int, largest_balance bigint,
               first_divergence int, reference text, plan text) AS $$
DECLARE
  i int; f int; t int; amt bigint; bal_f bigint;
  want text; got text; selfs int := 0; big bigint := 500;
BEGIN
  DELETE FROM mut;
  INSERT INTO mut VALUES (1, 500), (2, 500), (3, 500);
  PERFORM setseed(0.42);
  FOR i IN 1..n LOOP
    f := 1 + floor(random() * 3)::int;
    IF random() * 100 < self_pct THEN
      t := f; selfs := selfs + 1;
    ELSE
      t := 1 + (f + floor(random() * 2)::int) % 3;
    END IF;
    amt := 1 + floor(random() * 200)::bigint;
    SELECT bal INTO bal_f FROM mut WHERE id = f;
    want := CASE WHEN f = t OR bal_f < amt THEN 'refused' ELSE 'committed' END;
    got := plan_case(f, t, amt);
    SELECT greatest(big, max(bal)) INTO big FROM mut;
    IF got <> want THEN
      RETURN QUERY SELECT i, selfs, big, i, want, got;
      RETURN;
    END IF;
  END LOOP;
  RETURN QUERY SELECT n, selfs, big, NULL::int, NULL::text, NULL::text;
END $$ LANGUAGE plpgsql;

SELECT * FROM suite(300, 0);
SELECT * FROM suite(300, 5);
```

A passing run earns `TESTED [T]` with its qualifier: how many commands ran, and the generator's statistics, meaning each outcome class's share, the self-transfer share and the largest balance reached. The last one returns in S6.L4. Engines belong in the stamp too. PGlite reports PostgreSQL 18.6 (run RUN-pglite-0511), so agreement on PGlite and on a Bench server is one semantics checked twice. The claim below keeps that assumption visible as a seam, drawn dashed: one database's agreement stands for the compiler. A later stage tests it.

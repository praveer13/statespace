## Five layers under one stamp (14 min)

**Question** (before the segment):

CL-1.1 reads PROVED [P] · Z3 5.3.1 unsat · uncertified · rlimit N. What does "uncertified" admit?

- A. That no person reviewed it.
- B. That it rests on the solver being sound, and no independent certificate was checked.
- C. That the encoding was not checked.
- D. That the result is bounded.

Every stamp in this stage rests on five layers, and each fails in its own way.

| Layer | Must get right | Evidence here | Effect on the stamp |
|---|---|---|---|
| Requirement | `Inv` means the rule | true and false scenarios | requirement-fit is never [P] |
| Semantics | the reference semantics | the Lean reference and its goldens | none |
| VC generator | exactly the fragment's steps | replay and equivalence tests | "encoding unverified" stays open |
| Solver and entry path | `unsat` means no model | a second solver; certificates, deferred | "uncertified" |
| Instrument | the tab's Z3 matches the native one | the course's differential tests | the badge |

The solver layer can fail. Z3 issue #11179 reports a wrong answer on a satisfiable input. Run it.

**Cell 1** (INS-z3)

Input 1 of the issue, sent through Z3's SMT-LIB command interpreter after `(push 1)`, as the report does it. The tab runs one Z3 release, and the recorded run holds four.

Query asserts: a real `y` of at least 1 whose power `(1/2)^y` is below 1/2. `sat` is the truth, because `y = 2` works. The cell prints what the tab's release says. The recorded run holds what older releases said.

```python
from z3 import *

issue = """(set-logic ALL)
(declare-const y Real)
(push 1)
(assert (>= y 1))
(assert (< (^ (/ 1 2) y) (/ 1 2)))
(check-sat)"""

# Through the SMT-LIB command interpreter, as the issue reports it.
ctx = Context()
print('command interpreter:', Z3_eval_smtlib2_string(ctx.ref(), issue).strip())

# Pin y = 2: the same assertions are decided, and the model shows the input is satisfiable.
pinned = Solver()
pinned.from_string('(declare-const y Real)(assert (= y 2))(assert (>= y 1))(assert (< (^ (/ 1 2) y) (/ 1 2)))')
print('with y pinned to 2:', pinned.check())
```

**Specimen SP-4.5** is mounted in your cabinet here.

A second solver is the cheapest independent check. On the Bench, cvc5 1.4.2 reads the same SMT-LIB. It can also emit a certificate, an Alethe proof of its `unsat`, but a certificate can be partial: its proof for S1's guard query has 3 `hole` steps, each marked "untranslated rewrite". Checking certificates is deferred (D-32), so two agreeing solvers raise your confidence and the stamp keeps "uncertified".

**Specimen SP-4.6** is mounted in your cabinet here.

Lean's experimental `vcgen` (Lean 4.35.0, recorded 2026-10-24) reads an obligation from the other side. On a shallow contract for `transfer` over plain integers it proves the guarded version, and with the guard weakened it leaves one goal unproved: the sender's new balance is not known to be non-negative (run RUN-lean-vcgen). On a Mini-Plinth-style command type it does the same once it is given a weakest-precondition instance and one specification per construct (run RUN-vcgen-cmd). Your checker finds a violating state for the weakened obligation: an unprovable condition and a satisfiable negation are two faces of one obligation. The proofs close with `grind`, so each lists `Classical.choice`, which S2's manual proofs did not (run RUN-vcgen-cmd) (run RUN-lean-ledger).

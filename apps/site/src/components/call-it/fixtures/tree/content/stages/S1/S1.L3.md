## Check the premises {minutes=13 kcs=KC-1.implication-vacuity,KC-1.non-vacuity-check}

:::instrument ins=INS-z3 cell=1 recorded=RUN-z3-vacuous-unsat
The premises of the first claim, with the violation left out.

```python
from z3 import *
a, b, amount = Ints('a b amount')
s = Solver()
s.add(a >= 0, b >= 0, amount > 0, amount <= a)
print(s.check())
print(s.model())
```

@direction
Query asserts: the premises hold together. `sat` means a transfer satisfies them all.

@call key=A surprise=no run=RUN-z3-vacuous-unsat
This query holds the claim's premises and nothing else. What will Z3 return?

- A. `sat`
  - why: A transfer of 1 from an account holding 1 satisfies every premise {{run:RUN-z3-vacuous-unsat}}.
- B. `unsat`
  - why: This confuses the premise query with the violation query, as if the violation's `unsat` made the premises empty.
  - mis: dp:Z1
- C. `unknown`
  - why: A small linear query is decided outright.
  - mis: dp:Z6

@after
A premise query that is `sat` shows the claim is about something.
:::

:::instrument ins=INS-z3 cell=2 recorded=RUN-z3-vacuous-unsat
A config default that allows no transfer at all: the largest amount is 0, beside `amount > 0`. Three queries; the first is the one called.

```python
from z3 import *
MAX_TRANSFER = 0
a, b, amount = Ints('a b amount')
premises = [a >= 0, b >= 0, amount > 0, amount <= MAX_TRANSFER]

absurd = Solver()
absurd.add(premises + [Not(a - amount == a + 1000000)])
print('(ii)', absurd.check())

sender = Solver()
sender.add(premises + [a - amount < 0])
print('(i)', sender.check())

alone = Solver()
alone.add(premises)
print('(iii)', alone.check())
```

@direction
Query (ii) asserts: an allowed transfer after which the sender does not end 1,000,000 richer. `sat` means the absurd property is refuted.

@call key=B surprise=yes run=RUN-z3-vacuous-unsat
With the largest amount set to 0, query (ii) asks for an allowed transfer that breaks the absurd property "the sender ends 1,000,000 richer". What will Z3 return?

- A. `sat`
  - why: This expects the absurd property to be refuted; with no allowed transfer, every property of allowed transfers holds vacuously.
  - mis: dp:G4
- B. `unsat`
  - why: No transfer is allowed, so the absurd property is "proved" {{run:RUN-z3-vacuous-unsat}}. The premise query is the tell.
- C. `unknown`
  - why: A small linear query is decided outright.
  - mis: dp:Z6

@after
When the premises cannot hold together, every property is proved. The premise query is the tell.
:::

## What the result covers {minutes=13 kcs=KC-1.claim-anatomy}

:::instrument ins=INS-z3 cell=3 recorded=RUN-z3-conservation-noguard
Conservation of the plain transfer, with no guard at all.

```python
from z3 import *
a, b, amount = Ints('a b amount')
s = Solver()
s.add(Not((a - amount) + (b + amount) == a + b))
print(s.check())
```

@direction
Query asserts: the total changes. `unsat` means conservation is proved.

@call key=A surprise=yes run=RUN-z3-conservation-noguard
Does the unguarded transfer conserve the total of the two balances?

- A. Proved: no transfer changes the total
  - why: Z3 proves conservation over `Int` with no guard {{run:RUN-z3-conservation-noguard}}; conservation is not non-negativity.
- B. Refuted: a transfer changes the total
  - why: The claim "money is safe" was never unpacked into one property, and conservation needs no guard.
  - mis: dp:G6
- C. No verdict: Z3 returns `unknown`
  - why: A small linear query is decided outright.
  - mis: dp:Z6

@after
Conservation holds without a guard. Non-negativity does not.
:::

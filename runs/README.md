# runs: the runs registry

**Status:** built by W0-S11. **Date:** 2026-10-24 (machine clock).

Every tool number, verdict, flag and version the course states comes from a recorded run, a file `runs/<RUN-id>.json` (invariant I4; spine section 9.5). Copy cites a run as `{{run:RUN-id}}`, documents as `[X RUN-id]`. GATE-runs checks that every reference resolves and that the registry is intact; GATE-numbers checks that tool-shaped tokens carry a reference. This page says what a record holds, how to write one, how to cite it, and what the two gates check.

## 1. What is here

| Path | What |
|---|---|
| `RUN-<id>.json` | one run record, which validates against `run@1` (`schemas/run.schema.json`) |
| `RUN-<id>/` | the run's own outputs: logs, traces, reports. GATE-runs fails when one of them no longer has the SHA-256 and size its record gives |
| `index.json` | the index: one entry per record, with the record file's SHA-256. Generated by `node scripts/runs/build-index.mjs` |
| `README.md` | this page |

Tasks add their own `RUN-*.json` files and `RUN-*/` folders. The structure, the schemas and the index are W0-S11's.

## 2. A record: `run@1`

A record is identified by its path and carries no schema tag. Field names are snake_case, the form every W0 record uses; spine section 9.5 and ARCHITECTURE.md section 9.1 write the same fields in camelCase:

| `run@1` | Spine and ARCHITECTURE.md | Holds |
|---|---|---|
| `id` | `id` | the RUN ID; it must equal the file name |
| `title`, `task` | | what the run establishes, and the task that recorded it |
| `engine`, `version`, `version_string` | `engine`, `version` | the engine and its version, verbatim as it printed it |
| `binary`, `binary_sha256` | `binarySha256` | what ran (a binary, jar, wheel or native library) and its SHA-256 |
| `image` | `image` | the container image as `name@digest`, or the browser build |
| `argv` | `argv` | the exact command line; for a run of several commands, one list per command |
| `inputs[]` | `input`, `inputSha256` | each file the run read, by repository path, URL or name, with its SHA-256 |
| `budget` | `budget` | `rlimit`, `workers`, `timeout_s`, container memory and other limits |
| `started_at`, `duration_s` | `recordedAt` | when the run executed (a date when only the date is known), and how long it took |
| `recorded_at` | | when the record was written |
| `exit_code`, `verdict_lines` | `outputs.lines` | the exit code, recorded and never read alone, and the verdict lines, verbatim |
| `outputs[]`, `values` | `outputs`, `outputs.values` | the output files with SHA-256 and size, and named values parsed from them |
| `environment` | | the host and container: OS, CPU count, memory, architecture |
| `configs[]`, `primary_config` | `configs[]` | one entry per configuration of a run with several; the top level repeats the primary one |
| `origin`, `unrecorded[]`, `records` | | `imported` for a run registered after the fact from logs in `research/`; the reason for each null field; the spine's Records cell |
| `ttl_days` | `ttlDays` | days until a run that describes a moving upstream is stale |
| `notes[]` | | substitutions, emulations, caveats |

The root is open: an engine adds its own fields (`checks`, `probes`, `values`) beside the typed core. `schemas/run.schema.json` describes every field.

## 3. Writing a record

- **Copy, never type.** Verdict lines are copied from the tool's output; values are parsed from those lines; versions are recorded as the tool printed them (`1.4.2-modified`, not a corrected `1.4.2` [X RUN-cvc5-alethe]).
- **Hash what ran and what it read.** `binary_sha256` for the binary, jar, wheel or native library; `inputs[].sha256` for every spec, script and configuration; `outputs[].sha256` and `bytes` for every committed output.
- **Name the container by digest** (`eclipse-temurin:21-jre@sha256:...`), cap it with `--memory=6g`, and remove it when it exits.
- **No private paths.** A host path in `argv` or a log becomes a placeholder: `<sandbox>/work` for a scratch copy of the inputs, `<sandbox>/tla2tools-1.8.0.jar` for the jar the record hashes.
- **Null means not recorded.** A field the execution did not record is null. An imported record names each null core field in `unrecorded` with the reason; GATE-runs fails on a null it does not explain.
- **A run with no argv is re-run before copy cites it** (spine section 9.5). The re-run record keeps the original execution as configurations named `original` and `original-*`.

## 4. Citing a run

| Form | Where | Meaning |
|---|---|---|
| `{{run:RUN-id}}` | copy, and documents for a run still to record | a run that must be recorded before the sentence ships |
| `{{run:RUN-id#values.name}}` | copy | a value printed from the record (ARCHITECTURE.md section 18, item 14); any dotted path into the record resolves |
| `[X RUN-id]`, or several IDs in one tag separated by commas | documents | an executed run on disk |
| `[X RUN-id#values.name]` | documents | a value tag: the sentence states the value at that path of an executed run's record; GATE-facts fails when the sentence does not state it as a whole token |

The format placeholders `{{run:RUN-id}}`, `{{run:ID}}` and `[X RUN-id]` describe the forms and are not references.

## 6. The gates

**GATE-runs** (`node scripts/verify-runs.mjs`). The fast lane fails on a record that does not parse, does not validate against `run@1`, or whose id is not its file name; on an output file that is missing or changed; on a configuration output that names no file, a `primary_config` that names no configuration, or two configurations with one id; on an imported record with an unexplained null; on an `[X RUN-id]` that does not resolve; on a malformed `{{run:}}` or a value path the record lacks; and on an unresolved `{{run:}}` in learner copy (`content/stages/`, `labs/`) not labeled draft. It warns about forward references in documents and drafts, inputs that changed since their run, and a stale index; `--release` (the nightly and release lanes) fails on those too. `--self-check` plants each fault in a scratch copy and requires the gate to fail on it.

**GATE-numbers** (`node scripts/verify-numbers.mjs`). It reads README.md, docs/, curriculum/, tracker/, labs/ and new artboards as documents, and content/stages/ and labs/LAB-*/ as learner copy; docs/history/ and design/canvas/ are exempt. A tool-shaped token is a version, a number with a measuring unit, a TLC count or depth, a SQLSTATE code, a TLC or `lake` flag, a tool's verdict or message, an exit code, an `rlimit` or a model value. It passes under a run reference, `[D]`, `[V]`, a source citation, or an executed-evidence key; a tag covers its sentence and the untagged sentences before it in its paragraph, a table's caption covers its rows, and a heading's tag covers its section. In a document a token also passes when the same token is tagged elsewhere in that document, the spine's "where it is introduced"; in learner copy every unit carries its own tag. A sentence on the deny-list (BRIEF section 2.2) fails whatever it carries. The rules are in `scripts/runs/numbers-rules.mjs` and the deny-list in `scripts/runs/numbers-deny-list.json`.

**Known debt.** When the gate was introduced, documents written before it held untagged tokens. They are listed in `scripts/runs/numbers-baseline.json`, each by document, token and a hash of its sentence: the fast lane reports them and passes, `--strict` (the release lane) fails on them, and an edited sentence no longer matches its entry. The list may only shrink; each entry is cleared by tagging its sentence in the document that holds it.

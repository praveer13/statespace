## A capture, twice {minutes=2 kcs=KC-1.two-state-property,KC-1.witness-class}

:::item role=prequestion family=GEN-negate-it template=t2 kcs=KC-1.two-state-property,KC-1.witness-class mode=pick band=1
@choice key=B
A capture is applied twice to the same hold. Which property catches that bug?

- A. Total money is conserved.
  - why: A double capture moves money. It does not create any {{run:RUN-z3-double-capture}}.
  - mis: dp:O2
- B. The merchant gains at most the hold's amount from it.
  - why: Two captures pay the merchant twice the hold, which breaks this property.
- C. The held balance never goes below zero.
  - why: It catches the bug only when this hold is the only one in the pool. With other holds in `held`, it passes {{run:RUN-z3-double-capture}}.
  - mis: dp:A3
:::

## Steps are relations {minutes=14 kcs=KC-1.two-state-property,KC-1.witness-class}

A state is `(avail, held, merchant, status)`. A step is a relation between a state S and the next state S′, written with primed variables. A capture is `held′ = held − h`, `merchant′ = merchant + h` and `status′ = CAPTURED`. Two captures chain S → S′ → S″. Drawer D-04 holds the notation.

:::instrument ins=INS-z3 cell=1 recorded=RUN-z3-conservation-noguard
```python
from z3 import *
a, b, amount = Ints('a b amount')
a2, b2 = a - amount, b + amount     # the state after the step
prove(a2 + b2 == a + b)             # the total is conserved
```

@direction
Query asserts: with no guard at all, whatever leaves the sender arrives at the recipient. `prove` prints `proved` when no counterexample exists.

@tap
the total is conserved

@call key=A run=RUN-z3-conservation-noguard surprise=yes
What will `prove` print?

- A. `proved`
  - why: Conservation needs no guard. The sender loses what the recipient gains {{run:RUN-z3-conservation-noguard}}.
- B. `counterexample`
  - why: Conservation is not non-negativity. "Money is safe" was never unpacked into one property.
  - mis: dp:G6
- C. `unknown`
  - why: Linear integer arithmetic is decided.
  - mis: dp:Z6

@after
Conservation holds with no guard {{run:RUN-z3-conservation-noguard}}. The model has two distinct accounts, so it cannot say what happens when they are the same one.
:::

:::instrument ins=INS-z3 cell=2 recorded=RUN-z3-double-capture
The buggy capture, applied twice to one hold, checked against five queries.

```python
from z3 import *
Status, (HELD, CAPTURED) = EnumSort('Status', ['HELD', 'CAPTURED'])
h = Int('h')                                           # the hold's amount

class State:
    def __init__(self, tag):
        self.avail, self.held, self.merchant = Ints(f'avail{tag} held{tag} merchant{tag}')
        self.status = Const(f'status{tag}', Status)

S, S1, S2 = State(''), State('_p'), State('_pp')       # S, S', S''

def capture(x, y, guard=True):
    return And(guard, y.held == x.held - h, y.merchant == x.merchant + h,
               y.avail == x.avail, y.status == CAPTURED)

buggy   = lambda x, y: capture(x, y)                   # no guard
patched = lambda x, y: capture(x, y, x.held >= h)      # the pooled balance
fixed   = lambda x, y: capture(x, y, x.status == HELD) # the hold's own status

start = [S.avail >= 0, S.held >= 0, S.merchant >= 0, h > 0, S.held >= h, S.status == HELD]
twice = lambda step: [step(S, S1), step(S1, S2)]
total = lambda x: x.avail + x.held + x.merchant
gain = S2.merchant - S.merchant > h                    # the merchant gains more than the hold

def check(*formulas):
    s = Solver()
    s.add(*formulas)
    return s.check()

print(check(start + twice(buggy) + [total(S2) != total(S)]))   # (i) conservation fails
print(check(start + twice(buggy) + [gain]))                    # (ii) paid more than once
print(check(start + twice(patched) + [gain]))                  # (iii) the patch
print(check(start + twice(fixed) + [gain]))                    # (iv) the fixed capture
print(check(start + [fixed(S, S1)]))                           # (v) one capture works
```

@direction
Query asserts: for (i), two captures of one hold that change the total of `avail + held + merchant`. `sat` means such a pair exists.

@tap
the total is conserved

@call key=B run=RUN-z3-double-capture surprise=yes
What will Z3 return for (i)?

- A. `sat`
  - why: The double capture lowers `held` as it raises `merchant`, so money moves, and the total is unchanged.
  - mis: dp:O2
- B. `unsat`
  - why: Each capture moves the hold from `held` to `merchant`, so the total never changes {{run:RUN-z3-double-capture}}.
- C. `unknown`
  - why: These constraints are decided.
  - mis: dp:Z6

@after
Conservation holds even though the double capture is a bug {{run:RUN-z3-double-capture}}. It was the wrong property. (ii) asks for a merchant who gains more than the hold, and is `sat`: the merchant gains twice the hold. (iii) The patch "capture requires `held >= h`" reads the pooled balance. It stops the bug when this is the only hold, and fails when other holds share the pool, so it fixed the instance, not the class. (iv) Requiring `status = HELD` is `unsat`, and (v) one capture still works, so the fix is not empty {{run:RUN-z3-double-capture}}.
:::

## Exit {minutes=5}

:::item role=exit family=GEN-negate-it template=t2 kcs=KC-1.two-state-property mode=pick band=2
@choice key=A
A step takes state S to state S′. The property: "a refund never creates money", that is `total′ ≤ total`. Which formula do you hand the solver?

- A. `step(S, S′) ∧ total′ > total`
  - why: The negation of "total′ ≤ total" is "total′ > total", asked about a real step.
- B. `step(S, S′) ∧ total′ ≤ total`
  - why: A model of this is a step that works, which says nothing about the others.
  - mis: dp:Z1
- C. `step(S, S′) ∧ total′ < total`
  - why: This searches for money destroyed, not created.
  - mis: dp:Z5
- D. `step(S, S′) → total′ > total`
  - why: Any pair that is not a step satisfies an implication, so a model of it need not be a bug.
  - mis: dp:G4
:::

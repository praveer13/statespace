## A gate asks Z3 {minutes=2 kcs=KC-1.three-answers,KC-1.unknown-fails-closed}

:::item role=prequestion family=GEN-call-it template=t1 kcs=KC-1.three-answers,KC-1.unknown-fails-closed
@choice key=C
A deploy gate asks Z3 whether a new rule can overdraw any account. The answer is `unknown`. What is established?

- A. No account can be overdrawn.
  - why: `unknown` is no verdict.
  - mis: dp:Z2
- B. Some account can be overdrawn.
  - why: Only `sat` with a replayed model shows a violation.
  - mis: dp:Z1
- C. Nothing about the rule, so the gate blocks it until the question is decided.
  - why: A gate that lets `unknown` through has no evidence at all.
- D. The rule holds for the inputs Z3 tried.
  - why: Z3 reports no partial coverage. "Inputs tried" is a testing idea.
  - mis: dp:X1

## One query, one answer {minutes=13 kcs=KC-1.three-answers,KC-1.unknown-fails-closed}

An answer is about one query, one encoding and one solver run. `sat` comes with a model you can replay. `unsat` means no input satisfies this query as encoded, if the solver is sound. `unknown` means Z3 did not decide, and the reason line says why.

:::instrument ins=INS-z3 cell=1 recorded=RUN-z3-unknown-pow
```python
from z3 import *
x, y = Ints('x y')
s = Solver()
s.add(x**y == 8, y > 1)
print(s.check())
print(s.reason_unknown())
```

@direction
Query asserts: two whole numbers whose power is eight, with an exponent above one.

@tap
a solution exists

@call key=C run=RUN-z3-unknown-pow surprise=yes
What will Z3 return?

- A. `sat`
  - why: `x = 2` and `y = 3` solve it, but an answer reports what Z3 decided, not the truth.
  - mis: dp:Z6
- B. `unsat`
  - why: `x = 2` and `y = 3` solve it, so this misreads the constraint.
  - mis: dp:Z5
- C. `unknown`
  - why: The reason line names the gap.

@after
Z3 gave up, and the reason line says where: {{run:RUN-z3-unknown-pow#values.reason_unknown}} {{run:RUN-z3-unknown-pow}}. Yet `x = 2`, `y = 3` is a solution. `unknown` belongs to one query, not to a kind of arithmetic: a neighbouring query that fixes the base and the result, `2**x == y` with `x >= 0` and `y == 5`, gets a verdict {{run:RUN-z3-unknown-pow}}.
:::

::specimen id=SP-1.7 mount=true

:::instrument ins=INS-z3 cell=2 recorded=RUN-z3-budget-pyodide
This query has no solution. It runs under a budget, `rlimit`, which counts solver work rather than seconds.

```python
from z3 import *
x, y, z = Ints('x y z')
s = Solver()
s.set('rlimit', 5000000)
s.add(x > 2, y > 2, z > 2, x*x*x + y*y*y == z*z*z)
print(s.check())
print(s.reason_unknown())
```

@direction
Query asserts: three whole numbers above two whose cubes satisfy `x³ + y³ = z³`.

@tap
a solution exists

@call key=B run=RUN-z3-budget-pyodide surprise=yes
Z3 works until its budget ends. What does it say?

- A. proved: `unsat`
  - why: No solution exists, but Z3 has not shown that within the budget. Truth and verdict differ.
  - mis: dp:Z6
- B. no verdict: `unknown`
  - why: The reason, canceled, says the budget ran out {{run:RUN-z3-budget-pyodide}}.

@after
The reason is {{run:RUN-z3-budget-pyodide#values.rlimit_reason}} {{run:RUN-z3-budget-pyodide}}. A larger budget could turn this `unknown` into a verdict, and a verdict at a stated `rlimit` can be run again.

Budgets come from `rlimit`, not from `timeout`. A `timeout` of two seconds never returned under Pyodide in a Node harness {{run:RUN-z3-budget-pyodide}}, nor in three desktop browsers {{run:RUN-phone-pyodide}}, so an outside limit has to stop the worker.
:::

::specimen id=SP-1.8 mount=true

Where `unknown` guards enforcement, treat it as no. Amazon S3's Block Public Access analysis does: "To maintain soundness, we choose to fail closed: if the analysis result is unknown due to a time-out, we say the policy is not Trust Safe" (ESEC/FSE 2020, page 8).

:::item role=segment family=GEN-call-it template=t4 kcs=KC-1.three-answers
@choice key=D
Which statement about one solver answer is true?

- A. A `sat` on a violation query means the property holds.
  - why: `sat` comes with a model, and the model is a counterexample.
  - mis: dp:Z1
- B. An `unknown` with the reason "canceled" means no counterexample exists.
  - why: It means the budget ran out before Z3 decided.
  - mis: dp:Z2
- C. An `unsat` over `Int` also covers 64-bit integer code.
  - why: `Int` never overflows and 64-bit integers do, so the encoding differs.
  - mis: dp:Z4
- D. An `unsat` covers every input of exactly its encoding, if the solver is sound.
  - why: It is a statement about one query, one encoding and one solver run.
:::

## Exit {minutes=4}

:::item role=exit family=GEN-which-stamp template=t1 kcs=KC-1.unknown-fails-closed,KC-1.three-answers
@choice key=B
A deploy gate checks a new rule, and the raw solver line is `unknown` with the reason "canceled" at the gate's budget {{run:RUN-z3-budget-pyodide}}. Which stamp does the gate record, and what does it do?

- A. PROVED [P], no counterexample found: the gate allows the deploy.
  - why: `unknown` is no verdict, so nothing is proved.
  - mis: dp:Z2
- B. UNKNOWN [?], canceled at the stated budget: the gate blocks the deploy.
  - why: With no evidence either way, a gate that guards enforcement fails closed.
- C. REFUTED [R], a counterexample exists: the gate blocks the deploy.
  - why: A counterexample needs `sat` with a model that replays.
  - mis: dp:Z1
- D. TESTED [T], no bug in the inputs tried: the gate allows the deploy.
  - why: A solver answer is not a test report, and `unknown` covers no inputs at all.
  - mis: dp:X1
:::

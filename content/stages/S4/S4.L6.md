## Before you run anything {minutes=3 kcs=KC-4.cti-or-bug}

Z3 has just handed you a state. It satisfies your invariant, a command can run from it, and the next state breaks the invariant. Your instinct is to fix the command. Of the three things that state can mean, only one calls for that.

This lesson is about telling them apart with a search from `Init`, and about what you may claim when the search and the strengthening both fall short.

:::item role=prequestion family=GEN-cti-or-bug template=t2 kcs=KC-4.cti-or-bug
@choice key=B
The inductive step for `bal ≥ 0` on the holds model comes back with a pre-state where `bal = 0` and `held = 1`. A `Capture` of 1 from there leaves `bal = −1`. What do you do next?

- A. Fix `Capture`, because it lets a balance go negative.
  - why: A bug needs a run from `Init` that reaches that pre-state, and nobody has looked for one. A failing step from a state you cannot reach is no evidence against the command.
  - mis: dp:O3
- B. Ask whether `held > bal` is reachable from `Init`, and if it is not, strengthen the invariant.
  - why: A counterexample to induction is a bug only when its pre-state is reachable. Reachable means fix the command. Unreachable means the invariant forgot a fact.
- C. Report that the property is false, because the solver found a violation.
  - why: The query starts from any state with `bal ≥ 0`, not from `Init`. Its model is a step that could break the invariant, not a run that does.
  - mis: dp:Z1
- D. Ignore it, because the pre-state is only hypothetical.
  - why: Dismissing it skips the one check that can turn it into a real bug: whether any run reaches that state.
  - mis: dp:O3
:::

- A. PROVED [P] for every run.
  - why: Six steps say nothing about step seven. Only an inductive step with no counterexample covers every run.
  - mis: dp:X1

## Two models, one failing step {minutes=13 kcs=KC-4.cti-or-bug}

The holds model from S4.L4 has one account and three commands. `Hold(n)` sets `n` aside, `Capture(n)` spends held funds, and `Release(n)` frees them. The invariant is `bal ≥ 0`, and its inductive step query returns a pre-state in which `held` exceeds `bal`. One `Capture` from there pushes `bal` below zero.

That state is a counterexample to induction, a CTI: it satisfies the invariant, a step is enabled, and the invariant is broken one step later. A CTI says nothing about whether any run reaches the state. The step query starts from any state that satisfies the invariant, reachable or not.

So a satisfiable step query leaves one more question: can a run from `Init` reach the pre-state? Ask Z3 for a run of k steps from `Init` that ends with the invariant broken, for k = 0, 1, 2 and on up to a bound N that you choose and print. The first k that has a model is a trace. Replayed in the interpreter, it becomes REFUTED [R] with its length. If no k does, all you know is that there is no violation within N steps.

| Step query | Search from `Init`, up to N | Verdict | What you do |
|---|---|---|---|
| no model | not needed | inductive | check `Init ⇒ Inv` and `Inv ⇒ Safe`, then mint CL-4.4 |
| a model | a trace at step k | reachable | fix the command; the stamp is REFUTED [R] with k steps |
| a model | nothing within N | CTI so far | strengthen the invariant; if that stalls, mint CL-4.5 |

The last row says "so far" on purpose. Nothing within N is silent about runs longer than N, so the search cannot prove a pre-state unreachable. A CTI verdict becomes firm only when your strengthened invariant passes every check, which is the next segment.

Here are two models. The good model's `Hold(n)` requires `n ≤ bal − held`. Its twin's `Hold(n)` requires only `n ≤ bal`, and forgets holds already placed. Both give the same shape of CTI. Call the twin before you run anything.

:::instrument ins=INS-z3 cell=1 recorded=RUN-z3-cti-pair
The inductive step and a bounded search, on the twin and then on the good model.

```python
from z3 import *

def explore(name, hold_guard, bound=6):
    # One step of the holds model, from (bal, held) to (bal2, held2).
    def step(s, t, n):
        (bal, held), (bal2, held2) = s, t
        return And(n > 0, Or(
            And(hold_guard(bal, held, n), held2 == held + n, bal2 == bal),   # Hold(n)
            And(n <= held, held2 == held - n, bal2 == bal - n),              # Capture(n)
            And(n <= held, held2 == held - n, bal2 == bal)))                 # Release(n)

    # The inductive step for bal >= 0: a state with bal >= 0, one step, then bal < 0.
    bal, held, bal2, held2, n = Ints('bal held bal2 held2 n')
    q = Solver()
    q.add(bal >= 0, step((bal, held), (bal2, held2), n), bal2 < 0)
    print(name, '- inductive step:', q.check())
    m = q.model()
    print('  held > bal in the pre-state:', m[held].as_long() > m[bal].as_long())

    # Bounded search from Init: a run of k steps that ends with bal < 0.
    for k in range(bound + 1):
        s = [(Int(f'bal{i}'), Int(f'held{i}')) for i in range(k + 1)]
        search = Solver()
        search.add(s[0][0] >= 0, s[0][1] == 0)                  # Init
        for i in range(k):
            search.add(step(s[i], s[i + 1], Int(f'n{i}')))
        search.add(s[k][0] < 0)                                  # the invariant fails at step k
        if search.check() == sat:
            m = search.model()
            ops = []
            for i in range(k):
                h0, h1 = m[s[i][1]].as_long(), m[s[i + 1][1]].as_long()
                b0, b1 = m[s[i][0]].as_long(), m[s[i + 1][0]].as_long()
                ops.append('Hold' if h1 > h0 else 'Capture' if b1 < b0 else 'Release')
            print(f'  reachable in {k} steps:', ', '.join(ops))
            return
    print(f'  none within {bound} steps')

explore('twin', lambda bal, held, n: n <= bal)
explore('good', lambda bal, held, n: n <= bal - held)
```

@direction
Query asserts: first, a state with `bal ≥ 0`, one step of the model, and `bal < 0` afterwards. Then, for each k up to the bound, a run of k steps from `Init` that ends with `bal < 0`. `sat` on the step query means a CTI exists. `sat` on a search query means a real run breaks the invariant.

## Strengthen the invariant {minutes=13 kcs=KC-4.cti-or-bug}

A CTI is a gift: it shows which fact your invariant forgot. Here is the full procedure on the good model's CTI. You will repeat it on your own.

1. Read the pre-state. The cell checks only that `held` is above `bal`; a state such as `bal = 0`, `held = 1` has that shape.
2. Name a fact that this state breaks and that every reachable state keeps. Holds never exceed the balance: `held ≤ bal`.
3. Add it as a conjunct. The new invariant is `0 ≤ held ≤ bal`, the `I2` of S4.L4, which already implies `bal ≥ 0`.
4. Re-run three checks: `Init ⇒ Inv`, `Inv ∧ Next ⇒ Inv′`, and `Inv ⇒ Safe`, where `Safe` is the property you set out to establish, here `bal ≥ 0`.
5. Add a premise witness: a state where the invariant holds and some step is enabled. Without it, an `unsat` could be vacuous.

If a check still fails, you have a new CTI: go back to step 1.

Two cautions. Add only facts that hold in every reachable state, and read which check broke when one fails, because a wrong conjunct fails `Init ⇒ Inv` or the step. And do not edit the command to make a CTI go away: a CTI is no evidence that the command is wrong.

:::instrument ins=INS-z3 cell=2 recorded=RUN-z3-inductive
The three checks for `0 ≤ held ≤ bal` on the good model, plus a premise witness.

```python editable
from z3 import *

bal, held, n, bal2, held2 = Ints('bal held n bal2 held2')
step = And(n > 0, Or(
    And(n <= bal - held, held2 == held + n, bal2 == bal),     # Hold(n)
    And(n <= held, held2 == held - n, bal2 == bal - n),       # Capture(n)
    And(n <= held, held2 == held - n, bal2 == bal)))          # Release(n)

init = And(bal >= 0, held == 0)
inv  = lambda b, h: And(0 <= h, h <= b)       # I2, the strengthened invariant
safe = lambda b, h: b >= 0                    # the property you set out to establish

def verdict(label, *claims):
    s = Solver()
    s.add(*claims)
    print(f'{label}: {s.check()}')

verdict('Inv, step, not Inv after ', inv(bal, held), step, Not(inv(bal2, held2)))
verdict('Init and not Inv         ', init, Not(inv(bal, held)))
verdict('Inv and not Safe         ', inv(bal, held), Not(safe(bal, held)))
verdict('premise: Inv and a step  ', inv(bal, held), step)
```

@direction
Query asserts, line by line: a step from an invariant state to a state that breaks it; a start state that breaks the invariant; an invariant state that is not `Safe`; and, as the premise witness, an invariant state with a step enabled. `unsat` on the first three and `sat` on the fourth is what CL-4.4 needs.

- A. `paid ≥ 0`
  - why: The CTI has `paid = 1`, which satisfies it, so the same `Refund` still breaks `merch ≥ 0`.
  - mis: dp:O2
- B. `paid ≤ merch`
  - why: `Refund` needs `n ≤ paid`, and `paid ≤ merch` gives `merch − n ≥ 0`. `Pay` and `Refund` move both by the same amount, so the fact is kept.
- C. `paid = 0`
  - why: It excludes the CTI, but `Pay(n)` makes `paid = n`. A fact that a step breaks is too strong to be inductive.
  - mis: dp:O2
- D. `cust ≥ 0`
  - why: It is true in every reachable state, and even inductive by itself, but it says nothing about `paid` and `merch`. The CTI survives.
  - mis: dp:G9

## When strengthening stalls {minutes=13 kcs=KC-4.cti-or-bug}

Sometimes the missing facts do not come: the model has more moving parts, or each new CTI shows something different. You still have to write down what you know.

CL-4.4 needs an inductive step with no model. When you do not have one, CL-4.5 is the claim: the invariant holds on every run of up to N steps. Its stamp is MODEL-CHECKED [M] with the bound and "partial", and it carries an open defeater, inductiveness [?], with the CTI listed. It is never PROVED [P], because nothing was shown about step N + 1. A bounded verdict that does not print its bound is not a claim at all.

A claim can also be worded to look stronger than it is. CL-4.5 with the CTI line deleted does that, because the CTI is the reason the claim is not [P].

The cell holds a model with two holds on one account, each with its own `Hold`, `Capture` and `Release`. The property is `bal ≥ 0`, and `inv` is yours to strengthen. Run it as written first. The state Z3 prints for a failing step names a fact that `inv` forgot, and three facts are missing, not one.[^1]

[^1]: Drawer D-18 covers the same situation for Apalache: its inductive check earns [M], never [P] on its own.

:::instrument ins=INS-z3 cell=3 recorded=RUN-z3-cti-pair
Two holds on one account. Edit `inv`, run again, and read which check changes.

```python editable
from z3 import *

def inv(bal, h1, h2):
    return And(bal >= 0)             # the invariant; add conjuncts here to strengthen it

def step(s, t, n):
    (bal, h1, h2), (bal2, h1b, h2b) = s, t
    free = bal - h1 - h2
    return And(n > 0, Or(
        And(n <= free, h1b == h1 + n, h2b == h2, bal2 == bal),           # Hold on slot 1
        And(n <= free, h2b == h2 + n, h1b == h1, bal2 == bal),           # Hold on slot 2
        And(n <= h1, h1b == h1 - n, h2b == h2, bal2 == bal - n),         # Capture slot 1
        And(n <= h2, h2b == h2 - n, h1b == h1, bal2 == bal - n),         # Capture slot 2
        And(n <= h1, h1b == h1 - n, h2b == h2, bal2 == bal),             # Release slot 1
        And(n <= h2, h2b == h2 - n, h1b == h1, bal2 == bal)))            # Release slot 2

def fresh(i):
    return Int(f'bal{i}'), Int(f'h1_{i}'), Int(f'h2_{i}')

# The three checks: Init => Inv, Inv and a step => Inv after, and Inv => Safe.
s0, s1, n = fresh(0), fresh(1), Int('n')
init = And(s0[0] >= 0, s0[1] == 0, s0[2] == 0)
checks = [
    ('Init and not Inv', [init, Not(inv(*s0))]),
    ('Inv, step, not Inv after', [inv(*s0), step(s0, s1, n), Not(inv(*s1))]),
    ('Inv and not Safe', [inv(*s0), Not(s0[0] >= 0)])]
for label, claims in checks:
    q = Solver()
    q.add(*claims)
    r = q.check()
    print(f'{label:26}', r)
    if r == sat:                     # read the state in the model: which fact does it break?
        m = q.model()
        print('   state:', {str(v): m.eval(v, model_completion=True).as_long() for v in s0})

# Bounded search from Init: a run of k steps that ends with bal < 0.
bound = 6
for k in range(bound + 1):
    s = [fresh(i) for i in range(k + 1)]
    q = Solver()
    q.add(s[0][0] >= 0, s[0][1] == 0, s[0][2] == 0)
    for i in range(k):
        q.add(step(s[i], s[i + 1], Int(f'n{i}')))
    q.add(s[k][0] < 0)
    if q.check() == sat:
        print('reachable in', k, 'steps')
        break
else:
    print('none within', bound, 'steps')
```

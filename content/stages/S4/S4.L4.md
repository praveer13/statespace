## The obligation, by weakest precondition {minutes=15 kcs=KC-4.vc-shape}

Stage 1 gave you queries shaped like bugs. The roadmap states the general shape. For a command with a guard and a step, and an invariant `Inv`, ask Z3 for a state that satisfies

`Inv(S) ∧ Guard(S) ∧ Step(S, S′) ∧ ¬Inv(S′)`

A model is a state from which the command leaves the invariant, and `unsat` means there is none. The last three lessons built the pieces by hand. This one assembles them two ways, and then asks the harder question: what does a `sat` answer prove?[^1]

[^1]: Drawer D-04 covers state as a function and a step as a relation between two states, the vocabulary of `Step(S, S′)`.

  - why: The query starts from any state that satisfies `Inv`, reachable or not.
- C. A reachable state violates `Inv`: a real bug.
  - why: This reads a counterexample to the step as a reachable bug. Reachability is a separate question.

  - mis: dp:Z2
:::

:::item role=prequestion family=GEN-cti-or-bug template=t1 kcs=KC-4.invariant-vs-inductive
@choice key=D
For a predicate `I` that holds in every initial state, which combination is impossible?

- A. Invariant and inductive.
  - why: Possible: the strengthened predicate later in this lesson is both.
  - mis: dp:G9
- B. Invariant, not inductive.
  - why: Possible: a later predicate is true of every reachable state and still broken by a step from an unreachable one.
  - mis: dp:G9
- C. Neither.
  - why: Possible: a predicate can fail after a single step from a reachable state.
  - mis: dp:G9
- D. Inductive, not invariant.
  - why: `Init ⇒ I` and `I ∧ Next ⇒ I′` give `I` in every reachable state, by induction on the length of the run.
:::

Start from the requirement that `Inv` survives Transfer: `Inv → wp(Transfer, Inv)`. Under the reject reading from the last lesson, `wp(Transfer, Inv)` is `(g → wp(move, Inv)) ∧ (¬g → Inv)`. With `Inv` assumed, the second conjunct says `Inv → Inv` and falls away, leaving `Inv ∧ g → wp(move, Inv)`. Negate it and you have the roadmap's query, with `Step` folded into the substitution.

Two habits go with every `unsat`. First, ask for a premise witness: a state that satisfies `Inv ∧ Guard ∧ Step` alone. If that is `unsat`, the premises contradict each other and the first `unsat` proves nothing, the vacuity trap from Stage 1. Second, remember what `Inv` ranges over: every state that satisfies it, reachable or not. Typing facts such as `amount > 0` go into every query.

:::instrument ins=INS-z3 cell=1 recorded=RUN-check-fragment
```python
from z3 import *

a, b, c, amount = Ints('a b c amount')           # state before, and the parameter
a_p, b_p, c_p = Ints('a_p b_p c_p')              # state after

Inv     = lambda a, b, c: And(a >= 0, b >= 0, c >= 0)
typing  = amount > 0                             # amounts are positive
guard   = amount <= a                            # requires bal(from) >= amount
wp_move = Inv(a - amount, b + amount, c)         # substitute the move into Inv
wp_transfer = And(Implies(guard, wp_move), Implies(Not(guard), Inv(a, b, c)))   # reject reading

def check(*facts):
    s = Solver(); s.add(*facts); return s.check()

print('1 reduction     :', check(typing, Inv(a, b, c), Not(wp_transfer == Implies(guard, wp_move))))
print('2 obligation    :', check(typing, Inv(a, b, c), Not(wp_transfer)))
print('3 premise       :', check(typing, Inv(a, b, c), guard))
print('4 reject branch :', check(typing, Inv(a, b, c), Not(guard),
                                  a_p == a, b_p == b, c_p == c, Not(Inv(a_p, b_p, c_p))))
```

@direction
Query asserts, line by line: 1, that the reduction fails, so the full formula and the guarded one differ under `Inv`; 2, a state where `Inv` holds and the weakest precondition does not; 3, a state that satisfies `Inv` and the guard, the premise witness; 4, a state where `Inv` holds, the guard fails, the state is left unchanged and `Inv` fails afterwards. `sat` means such a state exists.

Must the checker also query the reject branch, `Inv ∧ ¬Guard ∧ S′ = S ∧ ¬Inv′` (line 4)?

- A. Yes, it can be `sat`.

  - mis: dp:G4
- B. No, it is `unsat` whenever `Inv` is assumed.
  - why: The reject branch changes nothing, so `¬Inv′` contradicts the `Inv` that the query assumes.
- C. Only for a self-transfer.
  - why: A self-transfer is about aliasing inside a successful step. The reject branch changes nothing, whichever accounts are involved.

@choice key=A
A Transfer between `a` and `b` leaves a third account `c` alone. Write `Inv(a, b, c)` for `a ≥ 0 ∧ b ≥ 0 ∧ c ≥ 0`, `Guard` for `0 < amount ∧ amount ≤ a`, and `Step` for `a′ = a − amount ∧ b′ = b + amount ∧ c′ = c`. Which query asks for a violating step?

- A. `Inv(a, b, c) ∧ Guard ∧ Step ∧ ¬Inv(a′, b′, c′)`
  - why: It starts from an `Inv` state, takes the guarded step and asks for an `Inv` violation afterwards.
- B. `Inv(a, b, c) ∧ Guard ∧ Step ∧ Inv(a′, b′, c′)`
  - why: This asks for a step that works, so a model says nothing about bugs.
  - mis: dp:Z1
- C. `Inv(a, b, c) ∧ ¬Guard ∧ Step ∧ ¬Inv(a′, b′, c′)`
  - why: This searches the transfers that the guard rejects, which never run.

- D. `Inv(a, b, c) ∧ Guard ∧ a′ = a − amount ∧ b′ = b + amount ∧ ¬Inv(a′, b′, c′)`

## The obligation, forward {minutes=14 kcs=KC-4.symbolic-execution}

Forward symbolic execution runs the command on symbols. After `a := a − amount` the symbolic value of `a` is `a − amount`, so the body becomes equations over primed variables: `a′ = a − amount` and `b′ = b + amount`. A variable the command does not touch needs its own equation, `c′ = c`. That equation is a frame, and the next lesson shows what happens without it.

For a deterministic command, `Step` fixes `S′` as a function of `S`. So `∃S′. Step(S, S′) ∧ ¬Inv(S′)` is satisfiable in exactly the states where `¬wp(c, Inv)(S)` holds. The two routes ask one question in two spellings, as long as both encode the same update.

:::instrument ins=INS-z3 cell=2 recorded=RUN-check-fragment
```python
from z3 import *

a, b, c, amount = Ints('a b c amount')
a_p, b_p, c_p = Ints('a_p b_p c_p')

Inv     = lambda a, b, c: And(a >= 0, b >= 0, c >= 0)
typing  = amount > 0
guard   = amount <= a
wp_move = Inv(a - amount, b + amount, c)                        # route 1: substitution
step    = And(a_p == a - amount, b_p == b + amount, c_p == c)   # route 2: forward, frame included

def check(*facts):
    s = Solver(); s.add(*facts); return s.check()

print('routes differ   :', check(typing, guard, step, Not(Inv(a_p, b_p, c_p) == wp_move)))
print('obligation      :', check(typing, Inv(a, b, c), guard, step, Not(Inv(a_p, b_p, c_p))))
print('premise witness :', check(typing, Inv(a, b, c), guard, step))
```

@direction
Query asserts, in order: a state where the step holds and `Inv′` disagrees with the weakest precondition; the forward obligation; and its premise witness. `sat` means such a state exists.

@call key=A run=RUN-check-fragment surprise=no
Can the two routes' queries for one deterministic command get different verdicts?

- A. Never, as long as both encode the same update.
  - why: `Step` fixes `S′` as a function of `S`, so the forward query is satisfiable exactly where the weakest precondition fails.
- B. When the guard fails.
  - why: Both routes carry the guard as a premise, so a failing guard removes the state from both.
  - mis: dp:G4
- C. On a self-transfer.
  - why: A difference there needs the simultaneous update, the bug from lesson 2, in one route. With the same update in both, the verdicts match.
  - mis: dp:L7

@after
The routes never differ, the obligation comes back empty, and the premise witness does not. For one command the choice of route is a matter of taste. It stops being one as commands grow: substitution needs no frame, and forward execution makes you state every one. {{run:RUN-check-fragment}}
:::

:::item role=segment family=GEN-call-it template=t4 kcs=KC-4.symbolic-execution
@choice key=B
Which statement about the two routes is true?

- A. Forward execution can leave out `c′ = c` for an untouched account, because substitution does.
  - why: Substitution has no `c′` to leave free. Forward execution creates `c′`, so it must say what `c′` is.
  - mis: dp:O4
- B. Forward execution must state `c′ = c` for every untouched account, and substitution leaves untouched variables alone.
  - why: Substitution rewrites only what the command assigns. Forward execution introduces a primed copy of every variable, and each copy needs an equation.
- C. The two routes can disagree on a self-transfer.
  - why: Only if they encode different updates. With the same update, both routes ask the same question.
  - mis: dp:L7
- D. The forward route must query the reject branch, and the backward route need not.
  - why: Both routes drop it for the same reason: the reject branch leaves the state unchanged.
  - mis: dp:G4
:::

## Four predicates on one model {minutes=15 kcs=KC-4.invariant-vs-inductive}

Two words are easy to blur. An invariant is true in every reachable state. An inductive invariant is preserved by every step from any state that satisfies it: `Init ⇒ I` and `I ∧ Next ⇒ I′`. By induction on the length of a run, such an `I` holds in every reachable state. So for a predicate that holds at `Init`, inductive implies invariant. The converse fails: a predicate can be true of every reachable state and still be broken by a step from an unreachable one. That step is a counterexample to induction, a CTI: a `sat` answer that is not yet a bug.

The model is one owner with a balance and a hold. `held` is the owner's open escrow, and `bal` is the balance plus that escrow, as in the postings of Stage 3. Initially `bal ≥ 0` and `held = 0`. Three commands, each with an amount `n > 0`:

| Command | Requires | Sets |
|---|---|---|
| `Hold(n)` | `n ≤ bal − held` | `held := held + n` |
| `Capture(n)` | `n ≤ held` | `held := held − n` and `bal := bal − n` |
| `Release(n)` | `n ≤ held` | `held := held − n` |

Four predicates to sort: `I1` is `bal ≥ 0`. `I2` is `bal ≥ 0 ∧ 0 ≤ held ∧ held ≤ bal`. `I3` is `held = 0`. `I4` is `bal < 0 ∧ held = 0`.

:::instrument ins=INS-z3 cell=3 recorded=RUN-z3-cti-pair
```python
from z3 import *

def step(b, h, n, b2, h2):
    hold    = And(n <= b - h, h2 == h + n, b2 == b)
    capture = And(n <= h,     h2 == h - n, b2 == b - n)
    release = And(n <= h,     h2 == h - n, b2 == b)
    return And(n > 0, Or(hold, capture, release))

init = lambda b, h: And(b >= 0, h == 0)
preds = {
    'I1': lambda b, h: b >= 0,
    'I2': lambda b, h: And(b >= 0, h >= 0, h <= b),
    'I3': lambda b, h: h == 0,
    'I4': lambda b, h: And(b < 0, h == 0),
}

def check(*facts):
    s = Solver(); s.add(*facts); return s.check()

def search(I, k):                       # any violation within k steps of Init?
    b = [Int(f'b{i}') for i in range(k + 1)]
    h = [Int(f'h{i}') for i in range(k + 1)]
    n = [Int(f'n{i}') for i in range(k)]
    run = [init(b[0], h[0])]
    for i in range(k):
        stay = And(b[i+1] == b[i], h[i+1] == h[i])
        run.append(Or(step(b[i], h[i], n[i], b[i+1], h[i+1]), stay))
    return check(*run, Or([Not(I(b[i], h[i])) for i in range(k + 1)]))

bal, held, n, bal2, held2 = Ints('bal held n bal2 held2')
for name, I in preds.items():
    print(name,
          '| fails at Init:', check(init(bal, held), Not(I(bal, held))),
          '| inductive step fails:', check(I(bal, held), step(bal, held, n, bal2, held2), Not(I(bal2, held2))),
          '| violated within 6 steps:', search(I, 6))
```

@direction
Query asserts, for each predicate: a state that satisfies `Init` and fails the predicate; a state that satisfies the predicate and steps to one that fails it; and a run of at most six steps from `Init` that ends outside it. `sat` means such a state or run exists.

@call key=A run=RUN-z3-cti-pair surprise=yes
Is the inductive step for `I1` `sat` or `unsat`?

- A. `sat`
  - why: A state with `held` above `bal` still satisfies `I1`, and a Capture from it drives `bal` below zero.
- B. `unsat`
  - why: This assumes every true invariant is inductive. The step starts from any state that satisfies `I1`, not only the reachable ones.
  - mis: dp:G9
- C. `unknown`
  - why: A few linear integer constraints are decided outright.
  - mis: dp:Z2

@after
The model Z3 returns is a CTI: it satisfies `I1`, and a Capture takes it out. It is no bug yet, because no run from `Init` reaches a state with `held` above `bal`: every Hold checks `n ≤ bal − held` first. The search from `Init` finds no violation of `I1` within its bound. {{run:RUN-z3-cti-pair}}
:::

The runs fill in the 2×2 {{run:RUN-z3-cti-pair}} {{run:RUN-z3-inductive}}:

| | inductive | not inductive |
|---|---|---|
| invariant | `I2` | `I1` |
| not invariant | `I4` | `I3` |

`I2` adds the missing relationship, holds never exceed the balance, and every step preserves it. `I1` is true of every reachable state and not preserved from unreachable ones. `I3` fails after a single Hold. `I4` is inductive for a cheap reason: no command is enabled from a state with `bal < 0`, so nothing leaves it. It is not invariant, because it fails at `Init`.

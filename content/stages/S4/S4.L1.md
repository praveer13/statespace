## A triple is a query {minutes=14 kcs=KC-4.hoare-triple}

Until now you asked Z3 about one transfer at a time. A Hoare triple asks about a whole command: from every state that meets a condition, what holds afterwards? Here the command is a loop that can run out of fuel. `settle(fuel, pending)` captures one pending hold per turn and returns `outOfFuel` if the fuel runs out first.

:::item role=prequestion family=GEN-call-it template=t1 kcs=KC-4.hoare-triple
@choice key=B
With fuel 2 and 3 pending captures, which triples hold for `{Inv} settle {Inv}`?

- A. Both the partial and the total triple.
  - why: Total correctness needs every run to finish, and with two turns and three captures every run ends `outOfFuel`.
  - mis: dp:O5
- B. The partial triple holds and the total triple fails.
  - why: Partial correctness reads "if the run finishes, Inv holds". No run finishes, so the claim holds vacuously. Total correctness also demands that the run finishes.
- C. The total triple holds and the partial triple fails.
  - why: Impossible: a total triple says everything a partial triple says, and more.
  - mis: dp:O5
- D. Neither the partial nor the total triple.
  - why: A partial triple fails only through a finished run that breaks Inv, and there is none.
  - mis: dp:G4
:::

A Hoare triple `{P} c {Q}` says: start in any state where P holds and run c; if c finishes, Q holds. Transfer's successful step gives this triple:[^1]

`{a ≥ 0 ∧ b ≥ 0 ∧ amount > 0 ∧ amount ≤ a}  a := a − amount; b := b + amount  {a ≥ 0}`

To check a triple, ask Z3 for a state that meets P, takes the step and breaks Q. If there is none, the triple holds for this encoding. From the next lesson you draw triples like this on the Derivation Board.

[^1]: Drawer D-10 maps the notation of Programming Language Foundations onto this one.

:::instrument ins=INS-z3 cell=1 recorded=RUN-z3-starter
```python
from z3 import *

a, b, amount = Ints('a b amount')     # before the step
a1, b1 = Ints('a1 b1')                # after it

P    = And(a >= 0, b >= 0, amount > 0, amount <= a)   # precondition
step = And(a1 == a - amount, b1 == b + amount)        # a := a - amount; b := b + amount
Q    = a1 >= 0                                        # postcondition

s = Solver()
s.add(P, step, Not(Q))
print(s.check())
```

@direction
Query asserts: a state that meets the precondition, takes the transfer and leaves the sender below zero. `sat` means the triple fails. `unsat` means no such state exists.

@tap
the sender stays at zero or above

@call key=B run=RUN-z3-starter surprise=no
What does Z3 return?

- A. `sat`
  - why: `sat` needs a state where the guard holds and the sender still ends below zero, and the guard rules that out.
  - mis: dp:Z1
- B. `unsat`
  - why: No state meets the precondition, takes the step and breaks the postcondition, so the triple holds for this encoding.
- C. `unknown`
  - why: A few linear integer constraints are decided outright.
  - mis: dp:Z2

@after
Take `amount <= a` out of the precondition and the same query finds an overdraft: {{run:RUN-z3-starter#values.model}}.
:::

A triple leaves one thing open: what if c never finishes? Two answers give two claims. Partial correctness: if the run finishes, Q holds. Total correctness: the run finishes, and Q holds. A run that stops at `outOfFuel` is unfinished. Partial correctness says nothing about it, so it can hold with no run finishing at all. Total correctness counts it as a failure.

Fuel is an unrolling bound: Z3 sees the loop as that many copies of its body.

:::instrument ins=INS-z3 cell=2 recorded=RUN-z3-cti-pair call=false
```python
from z3 import *

def settle(fuel, pending, bal):
    """Unrolled once per unit of fuel: each turn captures one pending hold."""
    for _ in range(fuel):
        working = pending > 0
        bal = If(working, bal - 1, bal)
        pending = If(working, pending - 1, pending)
    return pending == 0, bal            # did the run finish? and the ending balance

bal = Int('bal')
pending = IntVal(3)
pre = bal >= pending                    # Inv before: every pending hold is covered
for fuel in (2, 3):
    finished, bal_end = settle(fuel, pending, bal)
    post = bal_end >= 0                 # Inv after
    partial = Solver(); partial.add(pre, finished, Not(post))
    total = Solver();   total.add(pre, Not(And(finished, post)))
    print('fuel', fuel, '| finished run breaks Inv:', partial.check(), '| total triple fails:', total.check())
```

@direction
Query asserts, first: a run that finishes and ends below zero. Second: a run that does not finish, or finishes below zero. `sat` means such a run exists.

@after
With too little fuel no run finishes, so the first question has nothing to find and the second finds the unfinished run. With enough fuel both questions come back empty. A later lesson, S4.L6, uses the same bound to search for bugs.
:::

@choice key=C
`settle` captures one pending hold per turn, and Inv says every pending hold is covered. Which statement is true?

- A. With fuel 3 and 3 pending, only the partial triple holds.
  - why: Three turns capture three holds, so every run finishes and both triples hold.
  - mis: dp:O5
- B. With fuel 2 and 3 pending, neither the partial nor the total triple holds.
  - why: No run finishes, so no finished run can break Inv, and the partial triple holds vacuously.
  - mis: dp:G4
- C. With fuel 2 and 3 pending and a body that can break Inv, the partial triple holds.
  - why: A broken Inv would show only in a finished run, and none finishes. The total triple fails, because every run is unfinished.
- D. With fuel 3 and 3 pending and a body that can break Inv, only the total triple fails.
  - why: A finished run that ends outside Inv fails the partial triple too, and the total triple fails with it.
  - mis: dp:O5
:::

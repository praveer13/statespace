## How a false theorem looks proved {minutes=13 kcs=KC-4.trust-stack,KC-4.frame-condition}

:::item role=prequestion family=GEN-spot-the-gap template=t2 kcs=KC-4.trust-stack
@choice key=C
A checker reports PROVED [P] for a command you know overdraws. Z3 and cvc5 both say `unsat`. Where is the bug most likely?

- A. In Z3.
  - why: A bug in one solver is rarely shared by a separately built solver.
  - mis: dp:O5
- B. In both solvers.
  - why: Possible, but far less likely than one wrong input that both read.
  - mis: dp:O5
- C. In the VC generator, because both solvers read the same wrong text.
  - why: Agreement rules out a lone solver bug. It does not rule out a wrong query.
- D. Nowhere, because two solvers agreeing settles it.
  - why: Each answered the question it was asked. Agreement is not validation of the question.
  - mis: dp:G8
:::

A query is a conjunction, `Inv ∧ Guard ∧ Step ∧ ¬Inv′`, and conjunction tells you which way a translation can fail. Drop a conjunct, a frame equation or the guard, and the query gains models: `unsat` can turn into `sat`. That is a false alarm, never a false proof. Add a wrong conjunct, or encode a step that does less than the command does, and the query loses real violating steps: `sat` can turn into `unsat`. That is a false proof, and at the limit the premises contradict each other and every obligation looks proved.[^1]

Cedar's authors name the two halves. With the invariant itself encoded exactly, a translation is sound when its step relation contains every real step, and complete when it contains nothing else. Replay tests completeness, because an alarm whose witness does not replay is a step that is not real. Premise witnesses and known-false fixtures test soundness.

[^1]: Drawer D-02 holds the truth table for implication and vacuity.

| Evidence | Points at |
|---|---|
| a second solver disagrees, or a model fails the solver's own input | the solver |
| both solvers agree on a wrong verdict | the text both read: your generator |
| a model that does not replay | an incomplete step relation, which holds a step that is not real |
| a known-false fixture reported PROVED [P] | an unsound step relation, which misses a real step |

:::instrument ins=INS-z3 cell=1 recorded=RUN-z3-vacuity-trap
Two translations of `Withdraw`, then the source as written. For each, the violation query and its premise witness.

```python editable
from z3 import *

def report(name, premises, violation):
    q = Solver()
    q.add(*premises, violation)
    p = Solver()
    p.add(*premises)
    print(f'{name}: violation query {q.check()}, premise witness {p.check()}')

a, a2, amount = Ints('a a2 amount')
inv = lambda x: x >= 0

# 1. Withdraw with no guard, and an over-broad frame planted: "a is unchanged" beside "a is debited".
report('over-broad frame  ', [inv(a), amount > 0, a2 == a - amount, a2 == a], Not(inv(a2)))

# 2. The source's guard is amount <= a + 1; the translation emits amount < a + 1.
report('guard strengthened', [inv(a), amount > 0, amount < a + 1, a2 == a - amount], Not(inv(a2)))

# 3. The source as written: a known-false fixture, whose reference verdict is a violation.
report('source as written ', [inv(a), amount > 0, amount <= a + 1, a2 == a - amount], Not(inv(a2)))
```

@direction
Query asserts: the premises of `Withdraw` and a state that breaks `a ≥ 0` afterwards. The premise witness drops that last conjunct and asks whether the premises can hold at all.

@call key=A surprise=yes run=RUN-z3-vacuity-trap
A naive checker stamps every `unsat` PROVED [P] and runs no premise witness. What does it report for the first translation?

- A. PROVED [P]
  - why: The frame says `a` is unchanged beside a step that debits it, so no state satisfies the premises. Every violation query is `unsat`, and a false theorem looks proved.
- B. REFUTED [R]
  - why: That expects the overdraft, but contradictory premises admit no state at all.
  - mis: dp:O5
- C. UNKNOWN [?]
  - why: This is linear arithmetic, which Z3 decides outright.
  - mis: dp:Z2

@after
The first translation's premise witness is `unsat`: its proof is vacuous {{run:RUN-z3-vacuity-trap}}. The second is the sequel. Its premise witness has a model, so the witness cannot catch it. Only the third line shows the disagreement: the source overdraws and the translation says it does not. A known-false fixture catches that.
:::

@choice key=A
`Deposit(amount)` has the guard `amount ≤ limit`. An agent's checker reports PROVED [P] for "no balance goes negative", with Z3 and cvc5 in agreement and a premise witness that replays. Its emitted query leaves out the guard. What do you write in the audit?

- A. None: the claim is sound.
  - why: A dropped premise only widens the query, so its `unsat` covers every amount the guard allowed.
- B. A vacuous premise.
  - why: The premise witness replays, so the premises can hold together.
  - mis: dp:O5
- C. Model drift: the query no longer matches the command.
  - why: It does not match, but the mismatch makes the obligation stronger, not weaker.
  - mis: dp:O4
- D. Common-mode evidence: both solvers read the same query.
  - why: Common-mode evidence matters when the shared text could be wrong in the claim's favor, as in the prequestion. A query that asks for more than the obligation cannot be.
  - mis: dp:X2
:::

## Exit {minutes=3 kcs=KC-4.frame-condition}

:::item role=exit family=GEN-find-the-witness template=t1 kcs=KC-4.trust-stack,KC-4.frame-condition
@choice key=A
The source guard is `amount ≤ bal + 1` and the translation emits `amount < bal + 1`. The invariant is `bal ≥ 0`. Which state does the emitted query exclude, the source admit, and the step turn into a violation?

- A. `bal = 2, amount = 3`
  - why: The source admits 3 ≤ 3, the translation excludes 3 < 3, and the step leaves −1.
- B. `bal = 2, amount = 2`
  - why: Both guards admit it, and the step leaves 0, which is no violation.
  - mis: dp:O1
- C. `bal = 2, amount = 4`
  - why: Even the source rejects it, because 4 ≤ 3 is false.
  - mis: dp:O1
- D. `bal = 2, amount = 1`
  - why: Both guards admit it, and the step leaves 1.
  - mis: dp:O1
:::

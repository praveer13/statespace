## Substitution {minutes=14 kcs=KC-4.wp-assignment}

Stage 1 asked Z3 about one state at a time. A command preserves an invariant when every state that meets some condition before it ends inside the invariant after it. This stage finds that condition, and this lesson finds it by hand. You derive it on the Derivation Board, a worksheet where every line you write is one Z3 query: Z3 says whether the line follows from the one before.

The condition you want is the weakest precondition. For a command `c` and a postcondition `Q`, `wp(c, Q)` holds in exactly the states from which `c` ends in a state that satisfies `Q`. It is the weakest because every other sufficient precondition implies it.

:::item role=prequestion family=GEN-wp-it template=t1 kcs=KC-4.wp-assignment band=1
@choice key=A
What must hold before `fee := fee + 2` so that `fee ≤ 10` holds after it?

- A. `fee + 2 ≤ 10`
  - why: Substitute the assigned expression for `fee` in the postcondition.
- B. `fee ≤ 10`
  - why: This copies the postcondition and ignores the assignment.
  - mis: dp:O4
- C. `fee ≤ 12`
  - why: This substitutes in the wrong direction, as if undoing the assignment.
  - mis: dp:O4
- D. `fee + 2 = 10`
  - why: This is sufficient for one value only, so it is not the weakest.
  - mis: dp:O2
:::

:::item role=prequestion family=GEN-wp-it template=t1 kcs=KC-4.capture-avoiding-substitution band=3
@choice key=B
The invariant is `∀k. bal(k) ≥ 0`. `Debit(k, amt)` replaces `bal(k)` by `bal(k) − amt`. Someone substitutes and gets `∀k. bal(k) − amt ≥ 0`. Is that the weakest precondition?

- A. Yes.
  - why: The parameter `k` was captured by the quantifier's `k`, so this formula says something else.
  - mis: dp:O4
- B. No, it is stronger than needed: it demands that every account cover `amt`.
  - why: The capture-free weakest precondition is `bal(k) − amt ≥ 0 ∧ ∀j ≠ k. bal(j) ≥ 0`.
- C. No, it is weaker than needed.
  - why: The captured formula implies the right one, so it is stronger, not weaker.
  - mis: dp:O4
- D. No, it should mention only account `k`.
  - why: The other accounts must still be non-negative afterwards, so they stay in the weakest precondition.
  - mis: dp:O2
:::

For an assignment the rule is substitution: `wp(x := e, Q) = Q[e/x]`, read "Q with e written in place of x". Q describes the state after the assignment, and after it `x` holds what `e` evaluated to before. Here is a worked example, one line at a time:

| Line | Formula | Rule |
|---|---|---|
| 1 | `wp(a := a − amount, a ≥ 0 ∧ b ≥ 0)` | the goal |
| 2 | `(a ≥ 0 ∧ b ≥ 0)[a ↦ a − amount]` | assignment: write the right-hand side in place of `a` |
| 3 | `a − amount ≥ 0 ∧ b ≥ 0` | substitute: `b` is not assigned, so it stays |

Each line is a query. For an assignment or a simplification, Z3 is asked for a state where the line and the one before it disagree, and `unsat` makes the line valid. For a consequence line, `P ⇒ P′`, Z3 is asked for a state where the implication fails. If you claim a precondition is the weakest, the Board also expects the reverse implication to fail.

:::instrument ins=INS-derivation cell=1 recorded=RUN-z3-wp-transfer
```text
command  fee := fee + 2
post     fee ≤ 10
claim    fee ≤ 7

1  wp(fee := fee + 2, fee ≤ 10)  =  (fee ≤ 10)[fee ↦ fee + 2]    rule: assignment
2                                 =  fee + 2 ≤ 10                 rule: substitute
3  claim ⇒ line 2:  fee ≤ 7  ⇒  fee + 2 ≤ 10                      rule: consequence
4  line 2 ⇒ claim:  fee + 2 ≤ 10  ⇒  fee ≤ 7                      rule: consequence, reverse
```

@direction
Query asserts: for each line, a state where the line fails to follow from what it rests on. `sat` means the line is not valid, and the Board shows the state.

@call key=B run=RUN-z3-wp-transfer surprise=moderate
The proposed precondition `fee ≤ 7`, for the postcondition `fee ≤ 10` across `fee := fee + 2`. Is it the weakest, sufficient but stronger, or insufficient?

- A. The weakest precondition.
  - why: `fee = 8` also works, and `fee ≤ 7` excludes it, so a weaker precondition exists.
  - mis: dp:O2
- B. Sufficient but stronger.
  - why: `fee ≤ 7` implies `fee + 2 ≤ 10`, but `fee ≤ 8` is allowed too, so the implication does not hold in reverse.
- C. Insufficient.
  - why: Every state with `fee ≤ 7` ends with `fee ≤ 9`, so the postcondition holds.
  - mis: dp:O4

@after
Line 3 is valid and line 4 is not: `fee = 8` is a state the weakest precondition accepts and the claim rejects. A precondition can be sufficient and still not be the weakest. To call one the weakest you need both directions. {{run:RUN-z3-wp-transfer}}
:::

:::item role=segment family=GEN-wp-it template=t1 kcs=KC-4.wp-assignment band=1
@choice key=B
Which formula is `wp(bal := bal − amt, bal ≥ 2 · amt)`?

- A. `bal ≥ 2 · amt`
  - why: This copies the postcondition and ignores the assignment.
  - mis: dp:O4
- B. `bal − amt ≥ 2 · amt`
  - why: Only `bal` is assigned, so only `bal` is replaced and `amt` stays.
- C. `bal + amt ≥ 2 · amt`
  - why: This substitutes in the wrong direction, as if undoing the assignment.
  - mis: dp:O4
- D. `bal − amt = 2 · amt`
  - why: An equation fits one set of states only, so it is not the weakest.
  - mis: dp:O2
:::

## Functions are updated, not variables {minutes=14 kcs=KC-4.wp-assignment}

In Mini-Plinth the balances are one function, `bal`, from accounts to integers. A ResourceOp does not assign a variable. It replaces the function with an updated copy. Write `bal[f ↦ v]` for the function that agrees with `bal` everywhere except at `f`, where it returns `v`. A debit is `bal := bal[f ↦ bal(f) − amt]`, and `move amt from f to t` is two updates in a row:

`bal := bal[f ↦ bal(f) − amt]` and then `bal := bal[t ↦ bal(t) + amt]`

The second update reads the function the first one produced, so the weakest precondition of a move substitutes one update and then the other. A postcondition that mentions `bal(g)` becomes `bal[f ↦ v](g)`, which is `v` when `g = f` and `bal(g)` otherwise.

The tempting shortcut is the simultaneous update, `bal[f ↦ bal(f) − amt][t ↦ bal(t) + amt]`, which reads both new values from the old `bal`. When `f ≠ t` it agrees with the sequential one. When `f = t` it does not: the second entry overwrites the first, so the account gains `amt` and nothing is debited. That is the self-transfer bug from the Lean stage, now inside a weakest precondition.

:::instrument ins=INS-derivation cell=2 recorded=RUN-z3-wp-transfer
```text
command  A, sequential:    bal := bal[f ↦ bal(f) − amt];  bal := bal[t ↦ bal(t) + amt]
command  B, simultaneous:  bal := bal[f ↦ bal(f) − amt][t ↦ bal(t) + amt]
post     bal(x) + bal(y) + bal(z) = S
given    f and t are among x, y, z;  amt > 0

1  wp(A, post)  =  post with the first update substituted, then the second    rule: assignment, twice
2  wp(B, post)  =  post with the combined update substituted                   rule: assignment
3  line 1  ⇔  line 2                                                           rule: equivalence
```

@direction
Query asserts: a state where the two weakest preconditions disagree. `sat` means they are not equivalent, and the Board shows the state.

@call key=B run=RUN-z3-wp-transfer surprise=yes
Are the two weakest preconditions equivalent?

- A. Equivalent.
  - why: With distinct accounts the two updates agree, but an account can be both `f` and `t`, and then they do not.
  - mis: dp:L7
- B. Not equivalent, and only where `f = t`.
  - why: When `f ≠ t` both updates give the same function. When `f = t` the simultaneous update credits the account and never debits it.
- C. Not equivalent, and also where `f ≠ t`.
  - why: With distinct accounts the two updates agree, so the difference sits at `f = t` alone.
  - mis: dp:S1

@after
The Board finds a state where the two disagree, and with `f ≠ t` added it finds none: every disagreement has `f = t` {{run:RUN-z3-wp-transfer}}. A self-transfer is the whole difference: under the simultaneous update it changes the balance {{run:RUN-z3-selftransfer}}. The same aliasing makes a refund theorem hold under the sequential update and fail under the simultaneous one when the customer and the merchant are one account {{run:RUN-z3-refund-a21}}.
:::

:::item role=segment family=GEN-wp-it template=t1 kcs=KC-4.wp-assignment band=2
@choice key=C
For `move amt from f to t`, where `f` and `t` may be the same account, which formula is the weakest precondition of `bal(t) ≥ 0`?

- A. `bal(t) + amt ≥ 0`
  - why: This reads the credit from the old function, so it is the simultaneous update. It is wrong when `t = f`.
  - mis: dp:L7
- B. `bal(t) ≥ 0`
  - why: This ignores the move, which changes `bal(t)` whenever `t` is credited.
  - mis: dp:O4
- C. `(t = f → bal(f) ≥ 0) ∧ (t ≠ f → bal(t) + amt ≥ 0)`
  - why: The debit and the credit cancel when `t = f`, and the credit alone applies otherwise.
- D. `bal(t) + amt ≥ 0 ∧ bal(f) − amt ≥ 0`
  - why: This asks for both new balances to be non-negative, which is more than the postcondition says.
  - mis: dp:O2
:::

## Capture {minutes=14 kcs=KC-4.capture-avoiding-substitution}

Substitution has one trap. Suppose the formula you substitute into binds a name that also appears free in the expression you write in. The quantifier catches it. `Debit(k, amt)` takes the account `k` as a parameter, and the invariant `∀k. bal(k) ≥ 0` binds a `k` of its own. Substitute the update `bal[k ↦ bal(k) − amt]` for `bal` without care, and the `k` inside the update falls under the quantifier:

`∀k. bal(k) − amt ≥ 0`

That formula says every account must cover `amt`, which the command does not need. Rename the bound variable first, `∀j. bal(j) ≥ 0`, and then substitute:

`∀j. bal[k ↦ bal(k) − amt](j) ≥ 0`, which unfolds to `bal(k) − amt ≥ 0 ∧ ∀j ≠ k. bal(j) ≥ 0`

:::instrument ins=INS-derivation cell=3 recorded=RUN-z3-capture
```text
command  Debit(k, amt):  bal := bal[k ↦ bal(k) − amt]
post     ∀k. bal(k) ≥ 0
given    amt > 0

1  naive          ∀k. bal(k) − amt ≥ 0                                   rule: substitute, no renaming
2  capture-free   bal(k) − amt ≥ 0  ∧  ∀j. j ≠ k → bal(j) ≥ 0           rule: rename the bound k to j, then substitute
3  line 1  ⇔  line 2                                                       rule: equivalence
4  line 1  ⇒  line 2                                                       rule: consequence
5  line 2  ⇒  line 1                                                       rule: consequence, reverse
```

@direction
Query asserts: a state where line 1 and line 2 disagree, then a state where an implication between them fails. `sat` means the line is not valid, and the Board shows the state.

@call key=B run=RUN-z3-capture surprise=moderate
Is `∀k. bal(k) − amt ≥ 0` equivalent to the capture-free weakest precondition, stronger, or weaker?

- A. Equivalent.
  - why: This ignores the capture. The quantifier absorbed the parameter `k`, so the formula now constrains every account.
  - mis: dp:O4
- B. Stronger.
  - why: Every state that satisfies it satisfies the capture-free formula, but not the other way round: it asks every account to cover `amt`.
- C. Weaker.
  - why: This reverses the implication. The captured formula implies the right one, so it is stronger.
  - mis: dp:O4

@after
Line 4 is valid and line 5 is not. A state that separates them has account `k` covering `amt` and another account holding less than `amt` but not less than zero: the command handles it fine, and the naive formula rejects it. Built into an obligation, the naive formula would report a violation that debiting `k` never causes. {{run:RUN-z3-capture}}
:::

Capture can also err the other way. Take the invariant "only account `x` may be negative", `∀k. k ≠ x → bal(k) ≥ 0`, under the assignment `x := k`. Naive substitution gives `∀k. k ≠ k → bal(k) ≥ 0`, which is true of every state. A weakest precondition that is always true is a false proof: an obligation built from it would pass.

::specimen id=SP-4.2

:::item role=segment family=GEN-wp-it template=t1 kcs=KC-4.capture-avoiding-substitution band=3
@choice key=B
The command is `x := k` and the invariant is `∀k. k ≠ x → bal(k) ≥ 0`: only account `x` may be negative. Which formula is the weakest precondition?

- A. `∀k. k ≠ k → bal(k) ≥ 0`
  - why: The parameter `k` was captured by the quantifier. The formula is true of every state, so it proves nothing.
  - mis: dp:O4
- B. `∀j. j ≠ k → bal(j) ≥ 0`
  - why: Rename the bound `k` to `j` first, then write `k` in place of `x`: every account other than `k` must be non-negative.
- C. `∀k. k ≠ x → bal(k) ≥ 0`
  - why: This leaves the postcondition unchanged, but after the assignment `x` holds the value of `k`.
  - mis: dp:O4
- D. `∀j. j = k → bal(j) ≥ 0`
  - why: This swaps the inequality for an equation and asks only about account `k`.
  - mis: dp:O2
:::

## Exit {minutes=5}

:::item role=exit family=GEN-wp-it template=t1 kcs=KC-4.wp-assignment band=2
@choice key=C
Which formula is `wp(x := x + y, x ≥ 2 · y)`?

- A. `x ≥ 2 · y`
  - why: This copies the postcondition and ignores the assignment.
  - mis: dp:O4
- B. `x − y ≥ 2 · y`
  - why: This substitutes in the wrong direction, as if undoing the assignment.
  - mis: dp:O4
- C. `x + y ≥ 2 · y`
  - why: Write `x + y` in place of `x` and leave `y` alone.
- D. `x + y = 2 · y`
  - why: An equation fits one set of states only, so it is not the weakest.
  - mis: dp:O2
:::

:::item role=exit family=GEN-call-it template=t1 kcs=KC-4.wp-assignment
@choice key=C
The command is `bal := bal − 5` and the postcondition is `bal ≥ 10`. The proposed precondition is `bal ≥ 12`. Is it the weakest, sufficient but stronger, or insufficient?

- A. The weakest precondition.
  - why: The weakest precondition is `bal ≥ 15`, and `bal ≥ 12` admits states below it.
  - mis: dp:O2
- B. Sufficient but stronger.
  - why: A stronger precondition must imply `bal ≥ 15`, and `bal ≥ 12` does not: `bal = 12` ends at 7.
  - mis: dp:O4
- C. Insufficient.
  - why: `bal = 12` meets the precondition and ends at 7, below 10.
:::

## Values and evidence {minutes=14 kcs=KC-2.props-as-types}

:::item role=prequestion family=GEN-proof-structure template=t3 kcs=KC-2.props-as-types
@choice key=B
In `(h : 0 ≤ n ∧ n ≤ s.a)`, what is `h`?

- A. A Boolean that happens to be true
  - why: A proposition is not a `Bool`: nothing evaluates it to true or false.
  - mis: dp:L1
- B. Evidence: a term whose type is the proposition
  - why: Propositions are types, and a proof of one is a term of that type.
- C. A check the program runs
  - why: Nothing runs. Lean's type checker checks every use of `h`.
  - mis: dp:L1
- D. A comment for the reader
  - why: Delete `h` and every proof that uses it breaks.
  - mis: dp:L1
:::

Lean is a programming language and a proof language at once. A function such as `transfer` runs: you give it numbers and it returns a ledger. A proof does not run. It is a term whose type is the statement, and Lean checks that the type fits.

That is the idea of propositions as types. A statement such as `0 ≤ n ∧ n ≤ s.a` is a type, and a proof of it is a value of that type: evidence. So a hypothesis `h : 0 ≤ n ∧ n ≤ s.a` is neither a Boolean the program tests nor a comment. It is evidence you were handed, a pair of facts: `h.1` is the first and `h.2` the second.

Start with the part that runs. Make your call, then see what `#eval` prints.

:::instrument ins=INS-goal-replay cell=1 recorded=RUN-lean-s2-cells
```lean
structure Ledger where
  a : Int
  b : Int
deriving Repr, DecidableEq

def transfer (s : Ledger) (n : Int) : Ledger :=
  if 0 ≤ n ∧ n ≤ s.a then { a := s.a - n, b := s.b + n } else s

#eval transfer { a := 10, b := 0 } 3
```

@direction
Replay shows: what `#eval` prints. It runs `transfer` on a ledger holding 10 and 0, moving 3.

@call key=A surprise=no run=RUN-lean-s2-cells
What will `#eval transfer { a := 10, b := 0 } 3` print?

- A. `{ a := 7, b := 3 }`
  - why: The guard holds, since 0 ≤ 3 ≤ 10, so 3 moves from `a` to `b`.
- B. `{ a := 10, b := 0 }`
  - why: That is the rejected branch, but the guard holds here.
  - mis: dp:L4
- C. `{ a := 13, b := -3 }`
  - why: The money would move the wrong way.
  - mis: dp:L4
- D. An error, because Lean definitions do not run
  - why: `transfer` is an ordinary function, and `#eval` runs it.
  - mis: dp:L1

@after
`#eval` runs the function {{run:RUN-lean-s2-cells}}. A theorem never runs: Lean only checks it.
:::

Now the evidence. This term proves that the guard's second half holds on its own.

:::instrument ins=INS-goal-replay cell=2 recorded=RUN-lean-s2-cells call=false
A proof is a term too: `h.2` is the second part of the pair `h`.

```lean
theorem guard_gives_cover (s : Ledger) (n : Int) (h : 0 ≤ n ∧ n ≤ s.a) : n ≤ s.a := h.2
```

@direction
Replay shows: Lean accepting the term, because its type is the statement.

@after
Written with `def` instead of `theorem`, the same text is accepted with a linter warning that asks for `theorem` {{run:RUN-lean-s2-cells}}. `theorem` marks a proof, which nothing computes with; `def` marks data.

Had you written `h.1` instead, Lean would refuse the term: `h.1` proves `0 ≤ n`, and the theorem states `n ≤ s.a`. That refusal is what "does not elaborate" means. Lean could not make the term's type match the statement.
:::

**A word ahead: dependent types.** The type of `h` mentions `s` and `n`, which come before it. A type that depends on values is a dependent type; in S3 you use one to make amounts that carry a proof that they are positive. Here the idea is only named, and nothing in this lesson grades it.

For practice that nobody grades, write `transfer` and one proof term yourself on the Bench. The live editor at https://live.lean-lang.org also works, but your code leaves your machine.

:::item role=segment family=GEN-call-it template=t1 kcs=KC-2.props-as-types
@choice key=C
What does Lean do with this declaration?

```lean
theorem keep_a (s : Ledger) (n : Int) (h : 0 ≤ n ∧ n ≤ s.a) : 0 ≤ s.a :=
  Int.le_trans h.1 h.2
```

- A. It does not elaborate
  - why: `h.1` is `0 ≤ n` and `h.2` is `n ≤ s.a`, so the two fit together.
  - mis: dp:L4
- B. It is a computation
  - why: A `theorem` is checked, never run, so there is no value to print.
  - mis: dp:L1
- C. It proves its statement
  - why: `Int.le_trans` chains `0 ≤ n` and `n ≤ s.a` into `0 ≤ s.a`, the stated type.
:::

## Exit {minutes=5 kcs=KC-2.props-as-types}

:::item role=exit family=GEN-proof-structure template=t3 kcs=KC-2.props-as-types
@choice key=C
With `h : 0 ≤ n ∧ n ≤ s.a` in scope, which term proves `0 ≤ n`?

- A. `h.2`
  - why: That is `n ≤ s.a`, a different fact.
  - mis: dp:L4
- B. `h`
  - why: `h` is the pair of both facts, not a proof of one of them.
  - mis: dp:L1
- C. `h.1`
  - why: The first part of the pair is exactly `0 ≤ n`.
- D. `⟨h.2, h.1⟩`
  - why: That swaps the pair and proves `n ≤ s.a ∧ 0 ≤ n`.
  - mis: dp:L4
:::

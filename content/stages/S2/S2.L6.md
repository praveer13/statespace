## Which fact serves which branch {minutes=14 kcs=KC-2.rejection-unchanged,KC-2.automation-scope}

- D. Both add `sorryAx` to their axiom lists.

  - mis: dp:L8

A transfer proof splits in two. In the allowed branch the guard holds, the balances change, and the proof does arithmetic. In the rejected branch the guard fails and the transfer hands back the state it was given. That second branch has a fixed shape: every rejection theorem has one hypothesis, that the guard fails, and one conclusion, that nothing changed.

```lean
theorem transferPos_rejected (s : Ledger) (n : Int) (h : ¬ (0 < n ∧ n ≤ s.a)) :
    transferPos s n = s
```

`transferPos` is the transfer from earlier in this stage with a stricter guard: it also rejects a zero amount. It runs parallel to the transfer in LAB-2, so the proof below uses the moves you will need there without being a proof you will write. Read it as a manual proof, and watch which line uses which fact.

:::instrument ins=INS-goal-replay cell=1 recorded=RUN-lean-s2-cells
```lean
structure Ledger where
  a : Int
  b : Int
deriving Repr, DecidableEq

def transferPos (s : Ledger) (n : Int) : Ledger :=
  if 0 < n ∧ n ≤ s.a then { a := s.a - n, b := s.b + n } else s

theorem transferPos_nonneg (s : Ledger) (n : Int) (ha : 0 ≤ s.a) (hb : 0 ≤ s.b) :
    0 ≤ (transferPos s n).a ∧ 0 ≤ (transferPos s n).b := by
  unfold transferPos
  split
  · next hg => exact ⟨Int.sub_nonneg_of_le hg.2, Int.add_nonneg hb (Int.le_of_lt hg.1)⟩
  · exact ⟨ha, hb⟩

#print axioms transferPos_nonneg
```

@direction
Replay shows: the proof one tactic at a time with the goal after each, then the axioms the finished proof depends on. No tactic in it is automation.

@tap
both balances are non-negative after an allowed transfer

@call key=B surprise=yes run=RUN-lean-s2-cells
In the allowed branch, which fact makes `0 ≤ s.a - n` true?

- A. `ha : 0 ≤ s.a`
  - why: Not needed here: `n ≤ s.a` alone gives `0 ≤ s.a - n`. `ha` serves the rejected branch.
  - mis: dp:L4
- B. The guard's `n ≤ s.a`
  - why: Taking away at most `s.a` leaves at least 0.
- C. `hb`, about the recipient's balance
  - why: That is a fact about the recipient.
  - mis: dp:L4
- D. The guard's `0 < n`
  - why: It serves the recipient's half, not the sender's.
  - mis: dp:L4

@after
Each half of the allowed branch has its own fact: `n ≤ s.a` for the sender, `hb` and `0 < n` for the recipient. The rejected branch uses no guard fact at all. The state is unchanged, so `ha` and `hb` already are the goal. That is what unchanged on rejection looks like inside a proof.
:::

Automation can hide all of this. `omega` closes goals of linear integer arithmetic. `grind` is a general solver whose proofs can use more axioms than a manual proof does {{run:RUN-lean-axioms}}. `decide` evaluates a closed goal. Each can finish the step you are meant to learn, and each can change the axiom list a stamp carries. So LAB-2.3 and LAB-2.4 run in manual mode: the check wants a proof with none of them in the theorem it teaches. The rest of the course stays open.

## Exit {minutes=4 kcs=KC-2.rejection-unchanged,KC-2.automation-scope}

:::item role=exit family=GEN-proof-structure template=t3 kcs=KC-2.rejection-unchanged
@choice key=D
To prove `transferPos s n = s`, which fact turns the `if` into its `else` branch?

- A. `ha : 0 ≤ s.a`
  - why: Nothing about the sender's balance decides the guard.
  - mis: dp:L4
- B. The guard itself, `(0 < n ∧ n ≤ s.a)`
  - why: That is the allowed branch's fact. Here the guard fails.
  - mis: dp:L4
- C. `hb : 0 ≤ s.b`
  - why: The recipient's balance is not part of the guard.
  - mis: dp:L4
- D. `h : ¬ (0 < n ∧ n ≤ s.a)`
  - why: It rules out the allowed branch, so the `else` branch is the only one left.
:::

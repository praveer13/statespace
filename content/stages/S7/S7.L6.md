## What counts as learning something {minutes=3 kcs=KC-7.observer-equivalence}

To say "frank learns nothing", you have to say two things: what frank sees, and which worlds he must not be able to tell apart. The last lesson used both informally. This lesson makes them exact, turns them into one query for Z3, and shows what the answer leaves assumed.

:::item role=prequestion family=GEN-leaks-to-observer template=t1 kcs=KC-7.observer-equivalence
@choice key=B
To check that frank learns nothing about Birch's private documents, which pairs of worlds should the check compare?

- A. Every pair of worlds.
  - why: frank's own documents legitimately differ. This is the blanket claim that the next lesson takes apart.
  - mis: dp:A15
- B. Pairs that agree on everything Acme may know and differ only in Birch's private data.
  - why: The relation states what frank may already know.
- C. Identical worlds only.
  - why: Then every view passes and the check says nothing.
  - mis: dp:A12
:::

## The observer and the relation {minutes=13 kcs=KC-7.observer-equivalence}

The **observer** of a view, run on behalf of user u, is the value returned to u, error code included. That is the whole definition. Response size, timing, caches and logs lie outside it, so a claim built on this observer says nothing about them.

Two worlds are **related**, written `S ~Acme S′`, when they agree on all of Acme's data and on what Birch released to Acme principals: the shares to Acme users and teams, and the released projections of the documents shared with them. They may differ anywhere in Birch's private data.

Noninterference for a view V then reads: for every Acme user u and every argument, `S ~Acme S′` implies `obs_u(V(S)) = obs_u(V(S′))`. Related worlds, equal observations. A leak is a related pair with different observations.

## Self-composition {minutes=14 kcs=KC-7.observer-equivalence,KC-7.hyperproperty}

To ask a solver for a leaking pair, put two copies of the state in one query. It is S4's shape, `Inv ∧ Guard ∧ Step ∧ ¬Inv′`, with two copies of the state in place of a before-and-after pair. For `Open`, the product obligation is:

```text
Rel(S_L, S_R)                                  ; agree on Acme's data and on Birch's releases to Acme
∧ out_L = Open(frank, k)(S_L)
∧ out_R = Open(frank, k)(S_R)
∧ obs_frank(out_L) ≠ obs_frank(out_R)          ; the negated conclusion
```

Read the answer as you read S1's. A result of `sat` is a leaking pair: decode both states and replay them in the viewer. A result of `unsat` is noninterference for this view, this observer, this relation and this encoding, and you read it only beside a premise witness. `Rel(S_L, S_R) ∧ secret_L ≠ secret_R` must itself be `sat`, because a relation that also forced Birch's data equal would pass every view.

:::instrument ins=INS-z3 cell=2 recorded=RUN-z3-selfcomp
The product query for `Open(frank, layoffs-memo)`, for version 0 and for version 1, which has one answer for both refusals. The last line is the premise witness.

```python
from z3 import *

# One request: Open(frank, "layoffs-memo"). Per world, the view reads three facts:
#   exists: is there such a document?  mayread: may frank read it?  body: its text.
# A response is a pair (code, body): code 0 = not_found, 1 = forbidden, 2 = page.

def open_v0(exists, mayread, body):
    code = If(Not(exists), 0, If(Not(mayread), 1, 2))
    return code, If(code == 2, body, 0)

def open_v1(exists, mayread, body):          # one answer for both refusals
    code = If(And(exists, mayread), 2, 0)
    return code, If(code == 2, body, 0)

def related():
    eL, eR = Bools('exists_L exists_R')
    mL, mR = Bools('mayread_L mayread_R')
    bL, bR = Ints('body_L body_R')
    # Rel: the worlds agree on what Acme may know.
    rel = And(mL == mR, Implies(mL, And(eL == eR, bL == bR)))
    return (eL, mL, bL), (eR, mR, bR), rel

def leak(view):
    L, R, rel = related()
    (cL, xL), (cR, xR) = view(*L), view(*R)
    s = Solver()
    s.add(rel, Or(cL != cR, xL != xR))       # the negated conclusion: the responses differ
    return s.check()

def premise_witness():
    L, R, rel = related()
    s = Solver()
    s.add(rel, L[0] != R[0])                 # Rel holds and the secret differs
    return s.check()

print('v0', leak(open_v0))
print('v1', leak(open_v1))
print('premise witness', premise_witness())
```

@direction
Query asserts: two related copies of the state in which frank's response differs. `sat` means a leaking pair exists. The last query asks only whether the relation lets the secret vary.

@tap
frank's response does not depend on Birch's private data

@call key=A run=RUN-z3-selfcomp surprise=moderate

- B. `sat`

@after

Read together, that is noninterference for this view, observer and relation, as encoded. It is a [P] result for the encoding and no more, and it is uncertified.
:::

## Through your own checker, and what stays assumed {minutes=12 kcs=KC-7.observer-equivalence}

In LAB-7.5 you teach `miniplinth check` this construction. It renames every state symbol twice, emits `Rel` from your `claims/observer.yaml`, emits the view twice, negates the equality of the two observations, and decodes a model into two states. The stamp is [P] for the encoding, by self-composition and uncertified, with the observer carried as [A]. That is claim CL-7.3, and the assumption in it is a seam.

:::instrument ins=INS-z3 cell=3 recorded=RUN-z3-selfcomp
The reference checker's SMT-LIB for version 1. Every symbol of the state appears twice, once per world.

```smt2
; Self-composition of Open v1 for frank and layoffs-memo.
; _L is the left world and _R the right world.
(declare-const exists_L Bool)
(declare-const exists_R Bool)
(declare-const mayread_L Bool)
(declare-const mayread_R Bool)
(declare-const body_L Int)
(declare-const body_R Int)

; Rel: the worlds agree on what Acme may know.
(assert (= mayread_L mayread_R))
(assert (=> mayread_L (and (= exists_L exists_R) (= body_L body_R))))

; The view, once per world: a page only when the document exists and frank may read it.
(define-fun resp_code ((e Bool) (m Bool)) Int (ite (and e m) 2 0))
(define-fun resp_body ((e Bool) (m Bool) (b Int)) Int (ite (and e m) b 0))

; The negated conclusion: frank's two responses differ.
(assert (or (distinct (resp_code exists_L mayread_L) (resp_code exists_R mayread_R))
            (distinct (resp_body exists_L mayread_L body_L) (resp_body exists_R mayread_R body_R))))
(check-sat)
```

@direction
Query asserts: the two worlds are related and frank's two responses differ. `sat` would be a leaking pair.

@tap
frank's response does not depend on Birch's private data

@call key=B run=RUN-z3-selfcomp surprise=no
Your [P] covers frank's responses. Does it cover how long they take?

- A. Yes
  - why: What the observer leaves out is not covered.
  - mis: dp:P1
- B. No
  - why: Time lies outside the observer, so the claim carries it as an assumption.

@after
The query compares two responses and nothing else {{run:RUN-z3-selfcomp}}. Time, size and cache state do not appear in it. The observer is the response body, error code included, and that is an assumption the claim must say out loud. It is SEAM-10, and you meet it again in S9.L9.
:::

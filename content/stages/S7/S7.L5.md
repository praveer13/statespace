## Where the last lesson ended {minutes=3 kcs=KC-7.enforcement-vs-ni,KC-7.hyperproperty}

Every read was checked, and it still leaked. S7.L4 ended with a policy that filtered every row and still told frank something, and that was not a bug in the policy. Here you find out why, and you learn the move that finds this kind of leak: compare two runs instead of reading one.

The examples use the reference world W0. It has two tenants, Acme and Birch. frank (a viewer on Growth) and dana (an editor on Payments) are in Acme. gia and hal are on Birch's Legal team. Legal owns contract, which Birch shared with dana, and layoffs-memo, which it shared with nobody.

:::item role=prequestion family=GEN-leaks-to-observer template=t3 kcs=KC-7.enforcement-vs-ni
@choice key=B
An API never returns a document's content unless `canread(viewer, doc)` holds. Can a viewer learn anything about documents they may not read?

- A. No: every read is checked.
  - why: The check governs what is read, not what the response depends on.
  - mis: dp:A4
- B. Yes: what comes back, or which error, can depend on data they may not read.
  - why: An error code or a count is part of the response.
- C. Only through timing.
  - why: The response itself already leaks; timing is a further channel.
  - mis: dp:P1
:::

:::item role=prequestion family=GEN-call-it template=t4 kcs=KC-7.hyperproperty
@choice key=B
Can you refute "frank's responses never depend on Birch's private data" by exhibiting one run?

- A. Yes: a run whose response contains Birch's data.
  - why: Dependence is not containment. An implicit flow shows no secret in any one response.
  - mis: dp:A4
- B. No: you need two runs that differ only in Birch's data and whose responses differ.
  - why: The property compares runs.
- C. Only with an infinite run, as for liveness.
  - why: Liveness needs infinite behaviors. This needs a pair of finite ones.
  - mis: dp:C5
:::

## Two runs, one difference {minutes=14 kcs=KC-7.enforcement-vs-ni}

`Open(viewer, id)` returns one document. Version 0 has three outcomes: the page; `forbidden`, when the document exists and the viewer may not read it; and `not_found`, when no such document exists. Every page it returns passes `canread`, so a monitor that checks each response against the read rule never fires.

Now send one request to two worlds that differ in one thing: whether Birch's layoffs-memo exists. The observer is whoever receives the response, here frank, who sees the whole response, error code included.

:::instrument ins=INS-pairs cell=1 recorded=RUN-pairs-reference
The monitor checks each run on its own. The viewer then sets frank's two responses side by side.

```text
view Open(viewer, id) =
  if no document has this id        then error not_found
  else if not canread(viewer, id)   then error forbidden
  else the page of id

monitor  every page returned passes canread

pair
  call   Open(frank, layoffs-memo)
  left   W0
  right  W0 without layoffs-memo
```

@direction
Pair asserts: two worlds that differ only in Birch's private document layoffs-memo, and one request from frank. A leak is a pair in which frank's responses differ.

@call key=B run=RUN-pairs-reference surprise=yes
Will frank's two responses be identical?

- A. Identical: frank can read neither document.
  - why: He reads neither, but the refusals differ.
  - mis: dp:A4
- B. Different: `forbidden` in one world, `not_found` in the other.
  - why: The error code depends on whether Birch's document exists.
- C. Identical, because errors are not part of a response.
  - why: An error code is a returned value. Dropping it from the observer hides the leak.
  - mis: dp:P1

@after
The monitor passed on both runs, and the responses still differ: `forbidden` where layoffs-memo exists and `not_found` where it does not {{run:RUN-pairs-reference}}. frank learned a fact about Birch's private data without reading anything.
:::

A check on each response asks whether this response hands over something it should not. This leak is in no single response. It is in the difference between two. The fix is one answer for both cases: return `not_found` whenever the document is missing or unreadable.

A witness for this kind of leak is a pair of worlds that are related (they differ only in data the observer may not see) and that the observer tells apart. Both conditions matter, and the next item tests both.

:::item role=segment family=GEN-leaks-to-observer template=t3 kcs=KC-7.enforcement-vs-ni
@choice key=B
`Share(by, doc, user)` answers `no_such_user` when no user of that name exists in any tenant, and `shared` otherwise. dana, an editor on Payments in Acme, shares q3-plan with "hal". Which pair of worlds lets dana learn something about Birch's private data?

- A. None: dana only shares her own team's document.
  - why: The answer depends on whether a user exists, whichever document is shared.
  - mis: dp:A4
- B. Two worlds that differ only in whether Birch has a user named hal.
  - why: Only Birch's private data differs, and dana gets `shared` in one world and `no_such_user` in the other.
- C. Two worlds that differ in whether q3-plan exists.
  - why: q3-plan is Acme's own data, which dana may already know, so these worlds are not related.
  - mis: dp:A2
:::

## Why one run is never enough {minutes=12 kcs=KC-7.hyperproperty}

From S5 you know two kinds of property over runs. A safety property says something bad never happens, and a finite prefix of one run can break it. A liveness property says something good eventually happens, and only an infinite run can break it. Both are sets of runs, and each run is in the set or not, judged on its own.

"Every page returned passes `canread`" is a safety property. The two runs of the last segment each satisfy it, which is why the monitor passed.

"frank's responses do not depend on Birch's private data" is a different kind of statement. It says that any two runs that differ only in Birch's data give frank the same responses. That is a set of sets of runs, a hyperproperty.[^1] No single run can break it, because a run cannot show what would have happened otherwise. Two finite runs can, which makes noninterference a 2-safety hyperproperty.

[^1]: Clarkson and Schneider (2010) named hyperproperties. Terauchi and Aiken (2005) treat information flow as a 2-safety problem.

:::instrument ins=INS-pairs cell=2 recorded=RUN-pairs-reference
The same two runs, checked two ways.

```text
run 1  W0                        Open(frank, layoffs-memo)
run 2  W0 without layoffs-memo   Open(frank, layoffs-memo)

check A, on each run alone      every page returned passes canread
check B, on the two together    frank's responses are equal
```

@direction
Pair asserts: check A looks at one run at a time, and check B looks at both.

@call key=A run=RUN-pairs-reference surprise=no
What kind of property is check A, "every page returned passes `canread`"?

- A. Safety
  - why: A finite prefix of one run can violate it.
- B. Liveness
  - why: Nothing has to happen eventually.
  - mis: dp:C5
- C. A hyperproperty
  - why: That is the property it gets mistaken for.
  - mis: dp:A4

@after
Check A passes on each run alone, and check B fails on the pair {{run:RUN-pairs-reference}}. A check on one run cannot find a leak that exists only between two runs.
:::

:::item role=segment family=GEN-call-it template=t4 kcs=KC-7.hyperproperty
@choice key=B
Which of these properties can one finite run refute?

- A. "Every `Open` request is eventually answered."
  - why: A finite prefix can still be extended with an answer, so only an infinite run refutes it.
  - mis: dp:C5
- B. "No page reaches frank unless `canread` holds."
  - why: The first page that fails the check refutes it, and a finite prefix shows that page.
- C. "frank's responses never depend on Birch's private data."
  - why: Dependence is a comparison between runs, so refuting it takes two.
  - mis: dp:A4
:::

## Two claims, two stamps {minutes=12 kcs=KC-7.enforcement-vs-ni}

S7.L4's slug insert is the same story with a command in place of a view. Slugs are unique across all tenants, so `CreateDoc` fails when any document, readable or not, already has the slug. In that lesson the insert failed when Birch held the slug and succeeded when it did not {{run:RUN-pg-rls-covert}}. Row-level security filtered every read along the way.

:::instrument ins=INS-pairs cell=3 recorded=RUN-pairs-reference
The slug pair, modeled in Mini-Plinth and run in the viewer.

```text
command CreateDoc(by, team, slug) =
  if any document in any tenant has this slug   then error slug_taken
  else add the document to team                 and answer created

pair
  call   CreateDoc(frank, Growth, "layoffs-memo")
  left   W0
  right  W0 without layoffs-memo
```

@direction
Pair asserts: two worlds that differ only in whether Birch holds the slug layoffs-memo, and one command from frank.

@call key=B run=RUN-pairs-reference surprise=yes
Suppose row-level security is on, `FORCE` is set, and the per-user differential finds no disagreement with the access matrix. Does noninterference hold for frank?

- A. Yes: enforcement is complete.
  - why: Enforcement is complete for reads, while the insert outcome still depends on Birch's row.
  - mis: dp:A4
- B. No: the slug pair refutes it.
  - why: Two runs that differ only in Birch's private row are told apart by frank.

@after
frank's command is refused in the world where Birch holds the slug and succeeds in the other {{run:RUN-pairs-reference}}. The pair is the witness, and it is one row.
:::

The same system earns two results for two different statements. "RLS enforces the read rule" is an [E] result, backed by a [T] differential: a mechanism in place, checked user by user. "frank's outcomes do not depend on Birch's private rows" is an [R] result, and its witness is the pair, one row long. Both results hold of the system at once, which is why a per-user differential can never stand in for noninterference.

:::item role=segment family=GEN-leaks-to-observer template=t1 kcs=KC-7.enforcement-vs-ni
@choice key=B
`Open(frank, roadmap)` returns the page and a field `last_edited_by`, read from the newest edit anywhere in the system. Every document it returns passes `canread`. Which pair of worlds shows that the view leaks?

- A. None: the only document returned is Growth's own.
  - why: The page depends on an edit log that includes Birch's private documents.
  - mis: dp:A4
- B. Two worlds in which the newest edit falls on layoffs-memo, made by gia in one and by hal in the other.
  - why: Only Birch's private data differs, and frank's `last_edited_by` differs.
- C. Two worlds that differ in who last edited roadmap.
  - why: roadmap is Acme's own data, so the worlds are not related and a different page is expected.
  - mis: dp:A2
:::

## Exit {minutes=4 kcs=KC-7.enforcement-vs-ni,KC-7.hyperproperty}

:::item role=exit family=GEN-leaks-to-observer template=t3 kcs=KC-7.enforcement-vs-ni
@choice key=C
`Open` version 1 answers `not_found` when the id is missing or frank may not read it, and the page otherwise. Within the printed scope, two tenants and up to four documents, which pair of worlds that differ only in Birch's private data lets frank tell them apart?

- A. Worlds that differ in whether layoffs-memo exists.
  - why: frank gets `not_found` in both, so the responses are equal.
  - mis: dp:A5
- B. Worlds that differ in layoffs-memo's body.
  - why: The view never returns it, so the responses are equal.
  - mis: dp:A5
- C. None within the scope.
  - why: Every response is the same for each difference in Birch's data that fits the scope.
:::

:::item role=exit family=GEN-call-it template=t4 kcs=KC-7.hyperproperty
@choice key=B
A teammate says: "Our monitor checks every response against the read rule and has never fired, so no tenant can learn anything about another." What is wrong with that argument?

- A. A monitor that has never fired is only a test, not a proof.
  - why: Even a proof about the monitor would leave the claim open, because the claim is about pairs of runs.
  - mis: dp:T5
- B. The monitor checks one run at a time, and the claim compares two.
  - why: A leak can exist only between runs, so a silent monitor says nothing about it.
- C. The monitor would have to run forever.
  - why: Noninterference needs a pair of finite runs, not an infinite one.
  - mis: dp:C5
:::

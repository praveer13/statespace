## Containment, and conjunctive queries {minutes=3}

Q1 is contained in Q2 when, on every database, every row Q1 returns Q2 returns too. Equivalence is containment both ways.

For select-project-join queries with equalities, under set semantics, Q1 is contained in Q2 exactly when some homomorphism maps Q2's body into Q1's and Q2's output variables onto Q1's. That is the result of Chandra and Merlin (STOC 1977), which lesson S9.L8 cites. Example: `Q1(x) :- shared(x, d), team(d, t)` and `Q2(x) :- shared(x, d)`. Mapping Q2's one atom onto Q1's first atom shows Q1 is contained in Q2: whoever has a share of a team's document has a share.

## Where SQL breaks it {minutes=2}

SQL returns bags, not sets, and a comparison with NULL is unknown, which WHERE treats like false, silently dropping the row {{run:RUN-pg-anomalies}}. A set-semantics proof can therefore fail for SQL. Refute it with an instance run in the tab on PGlite {{run:RUN-pglite}}.

## What each method earns {minutes=2}

A containment proof for the fragment under its stated semantics earns PROVED [P] of that encoding, uncertified. A distinguishing instance earns REFUTED [R], with the rows. "Results match" on one database earns only TESTED [T], with one instance {{run:RUN-pg-one-db}}.

Lesson S9.L8 compares a prover for a fragment, bounded checkers and refuters. None of them is taught here.

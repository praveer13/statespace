## Versions and snapshots {minutes=2}

An UPDATE writes a new version of a row, and a transaction reads the versions its snapshot makes visible. At READ COMMITTED each statement takes a fresh snapshot. At REPEATABLE READ and SERIALIZABLE the whole transaction reads one snapshot. The tablespace course's lesson T4 teaches the visibility rules themselves; this page is the self-contained card you need before it.

## What PostgreSQL did on the course's histories {minutes=3}

Each row is one pattern at three levels. A serialization failure is SQLSTATE 40001, and a deadlock failure is SQLSTATE 40P01 {{run:RUN-pg-anomalies}} {{run:RUN-pg-claims}}.

| Pattern | READ COMMITTED | REPEATABLE READ | SERIALIZABLE |
|---|---|---|---|
| Application read-modify-write: two debits of 80 from 100, each writing a balance computed from its own read | both commit, and more is spent than the account held | the second writer is refused with a serialization failure | the second writer is refused with a serialization failure |
| Conditional UPDATE with the balance in its WHERE clause | the second statement re-checks its WHERE clause, updates no row and loses nothing | the second writer waits, then is refused | the second writer waits, then is refused |
| Predicate read, then insert, over holds | both commit, and more is held than the balance covers | both commit, and more is held than the balance covers | the second transaction is refused |
| Write skew: each checks a team total, then debits a different account | both commit, and the team total goes negative | both commit, and the team total goes negative | one is refused, and the total stays above zero |

Two transfers that lock the same rows in opposite order end with one transaction refused for a deadlock {{run:RUN-pg-claims}}. The catalog of recorded histories that the items draw on is {{run:RUN-pg-catalog}}.

## SERIALIZABLE, retries and the pattern {minutes=3}

SERIALIZABLE refuses one transaction of a dangerous pattern {{run:RUN-pg-anomalies}}. The application retries the whole command, never the failed statement alone (lesson S6.L7), and that retries terminate is an assumption, stamped ASSUMED [A]. The guarantee covers committed SERIALIZABLE transactions only, so one writer at a weaker level voids it {{run:RUN-pg-mixed-levels}}.

The same transfer, compiled two ways, behaves differently at one level, so specimens name their compilation pattern and never the level alone. An anomaly is an interleaving the level permits, not a timing accident: `statespace isorun` reproduces each one by detecting lock waits, never by sleeping.

What T4 adds is version visibility, vacuum and contention, which this course does not re-teach. A completed T4 counts as evidence for the anomaly basics.

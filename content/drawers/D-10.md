## Why a drawer {minutes=1}

The roadmap's Stage 4 reading is Programming Language Foundations (PLF), whose Hoare chapters are written in Rocq. The course installs no Rocq, and the reading is optional. This page translates the notation into the course's own. Check each form against the edition you read, since notation moves between editions.

## The notation, side by side {minutes=3}

- `{{ P }} c {{ Q }}` is a triple: from any state satisfying P, if c terminates, it ends in a state satisfying Q. The course writes `{P} c {Q}` (lesson S4.L1).
- `X := a`, inside a command, is an assignment. The course writes `x := e`.
- `Q [X |-> a]` is Q with a in place of X: a substitution, not a state. The course writes `Q[e/x]`, so the weakest precondition of `x := e` for Q is `Q[e/x]` (lesson S4.L2).
- `P ->> Q` says every state satisfying P satisfies Q. The course writes P ⇒ Q, a consequence step on the Derivation Board.
- `(X !-> v ; st)` is the state st with X updated to v. The course writes `upd(st, x, v)` (D-04).
- `hoare_asgn`, `hoare_seq`, `hoare_if` and `hoare_consequence_pre` are rule names. They match the Derivation Board's step kinds: assignment, sequence, conditional and consequence.

The two substitution notations list the variable and the expression in opposite orders: read `[X |-> a]` as "X replaced by a" and `Q[e/x]` as "e in place of x".

## Partial and total {minutes=1}

PLF's triples are partial: a command that never terminates satisfies every triple. Total correctness adds termination, which lesson S4.L1 checks on a fueled loop.

## How to read a PLF proof {minutes=1}

A decorated program lists assertions between commands. Each line's obligation is what the Derivation Board checks as one Z3 validity query (lesson S4.L2). Read the decorations and skip the Rocq tactic scripts.

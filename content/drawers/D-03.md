## Two rules and the connectives {minutes=3}

¬(∀x. P(x)) ≡ ∃x. ¬P(x), and ¬(∃x. P(x)) ≡ ∀x. ¬P(x). "Every allowed transfer leaves the sender at zero or above" negates to "some allowed transfer leaves the sender below zero": one transfer, not every one. A violation query asserts that existential, and a model of it is a witness (D-01).

The connectives follow: ¬(A ∧ B) ≡ ¬A ∨ ¬B, ¬(A ∨ B) ≡ ¬A ∧ ¬B and ¬(A → B) ≡ A ∧ ¬B. "Both balances stay at zero or above" negates to `a′ < 0 ∨ b′ < 0`. Writing `a′ < 0 ∧ b′ < 0` asks for both at once, and on the unguarded transfer Z3 answers `unsat` although the property is violated {{run:RUN-z3-demorgan}}. Negating an implication keeps its premise: `allowed ∧ a′ < 0`, not `allowed → a′ < 0`.

## English into logic {minutes=2}

| English | Formula | Common slip |
|---|---|---|
| P only if Q | P → Q | Q → P, or P ↔ Q |
| P if Q | Q → P | P → Q, following word order |
| P provided Q | Q → P | P → Q |
| P unless Q | ¬Q → P, that is, P ∨ Q | P → ¬Q, or P ↔ ¬Q |
| P if and only if Q | P ↔ Q | one direction only |

The course reads "P unless Q" as "if not Q, then P". Where a requirement means "exactly when not Q", the item says so in words.

## Free variables and the order of quantifiers {minutes=2}

Asserting a formula asks whether some values of its free variables make it true, so free variables act as an outermost "there exists". Asserting `∀k. k·k ≠ y` therefore asks whether some y is not a perfect square, and Z3 answers `sat` with the model {{run:RUN-z3-unknown-pow#values.k_squared_witness}} {{run:RUN-z3-unknown-pow}}.

Order matters. ∀x ∃y lets each x choose its own y, while ∃y ∀x asks for one y that serves every x. A public benchmark of formal problems once carried a statement written with ∀x∃ where ∃∀x was meant.

"Money is protected" is not yet a property. Say which one you mean: the sender never goes below zero (one state), the total never changes (one step, D-04), a hold pays out once (two steps). Each has its own negation and its own witness.

For Rust readers: `xs.iter().all(p)` is ∀, `xs.iter().any(p)` is ∃, and `!xs.iter().all(p) == xs.iter().any(|x| !p(x))` is the first rule. Where it breaks: an iterator visits the finite collection you hold, while ∀ over the integers ranges over values no loop can visit, which is why the solver, not a loop, answers it.

## The shape of a query {minutes=2}

The roadmap's starter query, as SMT-LIB:

```smt2
(declare-const a Int)
(declare-const b Int)
(declare-const amount Int)
(assert (and (>= a 0) (>= b 0) (> amount 0)))
(assert (< (- a amount) 0))   ; the negated property
(check-sat)
(get-model)
```

Through Z3Py the same query found a model, {{run:RUN-z3-starter#values.model}}, and with `amount <= a` added it came back `unsat` {{run:RUN-z3-starter}}. The SMT-LIB text itself is recorded in {{run:RUN-z3-smtlib-tour}}. Declared constants are the query's free variables: `check-sat` asks whether some values satisfy every assertion (D-03). Your `claims/*.smt2` statement files are text like this, and the receipt hashes each one with its trailing whitespace trimmed and one newline added.

## Verdict lines {minutes=2}

| Line | Means | Stamp |
|---|---|---|
| `sat`, then the model | some values satisfy every assertion: a witness, once it replays | REFUTED [R] after replay |
| `unsat` | no values do, in this encoding, if the solver is sound | PROVED [P] of the encoding, uncertified, budget named, with the open defeater "encoding unverified" |
| `unknown`, reason "incomplete (theory arithmetic)" | no verdict: the query lies outside what Z3 decides, though a solution exists {{run:RUN-z3-unknown-pow}} | UNKNOWN [?], with the reason |
| `unknown`, reason "canceled" | no verdict: the budget ran out {{run:RUN-z3-budget-pyodide}} | UNKNOWN [?], with the reason; it fails closed where it guards enforcement |

Budgets are `rlimit`, because a `timeout` set under Pyodide never returned {{run:RUN-z3-budget-pyodide}}. In SMT-LIB the budget is a solver option and the reason is a query, `(set-option :rlimit …)` and `(get-info :reason-unknown)`, both recorded with the page's examples {{run:RUN-z3-smtlib-tour}}.

## A second solver {minutes=1}

The course re-runs authored `unsat` results on cvc5 when it builds. On the guarded query cvc5 also says `unsat`, with an Alethe proof that contains a `hole` step {{run:RUN-cvc5-alethe}}. Two solvers agreeing is diversity, not a checked proof, so "uncertified" stays. Solvers have bugs: on the inputs of one public issue an older Z3 release answered `unsat` on satisfiable inputs where the newer one answered `unknown` {{run:RUN-z3-11179}} (lesson S4.L9).

## Post-states and frames, from lesson S4.L5 {minutes=2}

Post-state constants carry the suffix `_p`, the obligation is one assertion, and each unchanged piece of state gets a named frame conjunct, `(! … :named frame_k)`. Drop a frame and an untouched account may change, which "proves" a false theorem {{run:RUN-z3-missing-frame}}.

For Rust readers: SMT-LIB is to Z3 roughly what LLVM IR is to rustc, the plain text every front end lowers to, worth reading when you need to see exactly what was asked. Where it breaks: SMT-LIB states constraints, not instructions, and nothing in it runs in order.

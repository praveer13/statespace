## Two questions, two kinds of evidence {minutes=3}

A test asks whether one input passes. A violation query asks whether any input, in this encoding, breaks the property. Each kind of evidence covers something different and earns a different stamp:

| Evidence | What it covers | Stamp |
|---|---|---|
| A few hundred tests pass | the inputs the tests chose | TESTED [T], with the number of tests and how the inputs were chosen |
| Every input from 0 to 7 is checked | every input inside the bound, none outside it | MODEL-CHECKED [M], with the bound, complete within it |
| `unsat` on the violation query | every input of this encoding, if the solver is sound | PROVED [P] of the encoding, with checker, version and budget named, uncertified, and the open defeater "encoding unverified" |
| `sat` with a model that replays | one input that breaks the property | REFUTED [R], with the witness length |

In the first lesson's transfer the tests passed and the sender was still overdrawn. A suite checks the inputs its author thought of, and fixtures that gave both accounts the same balance never reached the inputs where the recipient covers the amount and the sender does not. A violation search covers every input of the encoding, including values no fixture holds: the wrap of a 64-bit recipient balance needs two very large values {{run:RUN-z3-bv64}}, which lesson S1.L5 mounts.

A passing test is evidence about the inputs it ran. A violation search asks about all of them.

## Reading a counterexample {minutes=3}

A `sat` answer is only the start. Work through five moves, in this order.

1. **Replay it.** Put the model's values into the premises and the property. For the starter query's model, {{run:RUN-z3-starter#values.model}}, every premise holds and the property fails {{run:RUN-z3-starter}}. The course grades witnesses this way and never by matching values, because a solver may return any member of the class.
2. **Name the cause.** Which premise let it through? In the starter query nothing bounds the amount by the sender's balance. In the opening exercise the guard read the recipient's balance instead.
3. **Minimize, for an objective you choose.** Optimizing the amount finds a smallest overdraft of {{run:RUN-z3-optimize-min#values.minimal_amount}} {{run:RUN-z3-optimize-min}}. "Minimal" means minimal for that objective and nothing else.
4. **Generalize.** Write the class every witness belongs to, here "the amount exceeds the sender's balance", and check that it implies the violation.
5. **Fix the class, not the instance.** Excluding the one witness with a zero balance leaves the class intact: a balance of 1 with an amount of 2 still overdraws. A fix has to kill a witness that is not minimal, and the broken version stays beside the fixed one in your specimens.

## What unsat does not say {minutes=2}

It speaks about this encoding only: an `Int` is not a 64-bit integer (lesson S1.L5). It speaks about this solver run only: the solver is an assumption, and one of your claim's seams. And it speaks only when the premises can hold together (D-02). Each limit becomes a field of your claim card (D-06).

For Rust readers: `cargo test` and proptest give TESTED evidence, and proptest's shrinking resembles minimizing for an objective. Where the comparison breaks: no test runner can report that no failing input exists, while a solver can, for the encoding it was given.
